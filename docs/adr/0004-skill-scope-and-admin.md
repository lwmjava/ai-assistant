# ADR-0004 技能范围与系统管理员跨租户管理

> 状态：**Accepted**  
> 任务：`SKILL-001`  
> 批准日期：2026-10-01  
> 批准人：产品负责人（本仓库个人开发者）  
> 风险：L1  
> 实现任务：`SKILL-001`、`SKILL-002`

## 1. 背景

成员需要创建只对自己对话生效的技能。后续技能市场需要一种「对所有用户生效」的技能。系统管理员需要查看并处理任意用户、任意租户的技能，包括修改、启用、停用、删除，以及新增系统全局技能。

这改变了「查询只看当前会话租户」的隔离方式，属于治理文档第 17 节里的租户隔离，因此单独立项。

## 2. 事实

| 声明 | 证据 |
|---|---|
| 现有技能在进程内单例里，不区分租户 | `app/agents/skills/manager.py` |
| 系统管理员角色的定义是跨租户 | `app/core/security.py` 的 `Role.SYSTEM_ADMIN` |
| 知识库跨租户仍禁止 | ADR-0001 |
| 技能市场页面、定价和安装尚未实现 | `docs/plans/plan_d2.md` 非目标 |

## 3. 选项

- A. 私有技能只对创建者生效；另设系统全局技能，启用后所有用户可见、可被对话选用；只有 `system_admin` 能跨租户改写和新建全局技能。
- B. 成员技能一旦创建就对整个租户生效。
- C. 维持现状，系统管理员也不能跨租户看技能。

## 4. 决定

选择 **A**。

- `scope=private`：只有创建者的对话会选用。同一租户的其他成员看不到。
- `scope=global`：仅 `system_admin` 可创建。启用后，所有有读权限的用户都能在列表里看到，对话匹配也会纳入。停用后不再匹配，普通成员也看不到。
- `system_admin` 可列出全部用户和租户的技能，并修改、启用、停用、删除。
- `system_viewer` 可跨租户只读，含详情，不能写。
- `tenant_admin` 可启停本租户私有技能，不能跨租户，不能改他人正文，不能新建全局技能。
- 内置 YAML 只读，不能通过接口修改、启停或删除。
- 不改 ADR-0001。知识库仍然不因本决定变成跨租户可读。

未选 B：会让一名成员的提示词进入同事的对话。未选 C：做不到用户要求的超管管控，也留不下技能市场要用的全局范围。

## 5. 后果

- 系统全局技能的正文会进入所有用户的系统提示。创建和修改都做注入检测，注入前套不可信围栏。围栏不能证明模型一定服从。
- 列表接口不返回正文。详情接口对有权查看的人返回正文。
- 技能市场的上架、定价、安装和审批仍未做。`global` 只是范围标记。

## 6. 迁移

新表 `skills`，并用 `name_key` 保证私有技能按创建者唯一、全局技能按名称唯一。`messages.skill_names` 记录当次选用的技能名。已有消息不回填。

## 7. 验证

`pytest tests/ -k skill -v` 覆盖：私有技能对其他人不可见、系统全局技能可被选用、系统管理员按租户列出并改写、列表不含正文、详情含正文。

## 8. 回滚

回退实现提交，并执行该 Alembic 修订的 `downgrade`。会话正文保留。技能行和技能名列被去掉。默认编排和检索基线不变。
