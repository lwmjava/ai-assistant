# ADR-0006 保守清洗与到期删除补偿

状态：Accepted（本次用户明确批准按计划实施的范围）。日期：2026-10-05。用户决定：软删除保留 90 天，到期物理清理持久补偿和重试。技术细化如下；不批准真实数据迁移、重建或删除。

## 背景与事实

现有软删除保留源文件、分块和向量；读路径排除已删文档。retention 向量失败后仍删 DB，缺恢复目标。已有原始解析文本 hash 去重。清洗不得损坏代码/盒图缩进。

## 决定

- 原始上传字节不变。新增 ingestion snapshot 表，保存本次原始解析文本、blocks 与清洗报告（版本、原始/派生 hash、质量评分、是否回退），随文档级联删除；新导入与重解析才写，旧文档不自动补采。
- 保守规则仅去掉开头 BOM、规范化换行。每行内容与缩进必须逐字等同基准；异常/校验失败回退原文和 blocks。质量评分为确定性可复算诊断，不作为检索质量或拒绝阈值。
- 原始解析 hash 仍用于已有版本去重，派生 hash 单独记入报告，避免规则升级自动制造新版本。同步上传仅在同租户、同上传者、同来源、同原始 hash 的未删当前文档中去重；显式策略/版本/生效配置不合并。原有源文件保留；重复上传生成的未引用暂存副本，仅在确认未被任何文档/导入任务引用且与原文件位于同租户目录后丢弃，避免配额漏计。原文档无源路径时接收新源文件并记录字节数。
- 新增清理任务表：id、tenant_id、document_id、vector_backend、vector_target（目标配置 SHA256，不存连接串/Token）、status、attempt_count、max_attempts、next_attempt_at、last_error_code、时间戳。document_id 唯一，无文档外键，完成后保留证据；只处理到期文档。
- 清理意图先提交，随后删除向量和源文件，最后文档删除与任务 done 同事务提交。失败 rollback 后保存重试状态和脱敏错误类别，最多 3 次，60/120 秒退避；第三次 failed，不再自动重试。重启扫描 pending 即恢复；向量删除及源文件缺失必须幂等。
- 目标库与运行配置不一致时保留 pending，暂停消费；同租户文档核对失败则 failed，不访问向量/文件。不存在的文档不触发外部删除，任务 failed 保留人工核查证据。
- 复用现有进程内导入调度器，单 worker；多实例争抢不宣称解决，留给 OPS-001/002、RAG-039。
- 删除尝试先写审计，审计异常走同一持久失败路径，不先执行物理删除；成功后保留原有 purge 审计。完成审计的跨事务可靠投递仍属于现有审计边界，未新增 outbox。

## 选项与后果

不采纳立即删除向量（改变保留语义）或仅日志补偿（无法重启恢复）。增加两张表和原始解析文本存储，带来容量成本与敏感内容保留义务；snapshot 仅内部服务消费，不新增公开接口。

## 迁移、验证与回滚

新增迁移创建两表及索引，并幂等补齐原型清理表缺失的 vector_target；不自动执行真实库。已被标记为 head 的原型库需显式运行 docs/plans/repair_rag014_schema.py，备份后只新增字段，旧任务默认空指纹并暂停，不猜测目标。用户于 2026-10-05 批准并执行当前 SQLite 的这项修复。临时 SQLite 验证升级/重复升级，降级仅在两表均空时允许；非空拒绝 drop，避免丢补偿记录和原始快照。回滚代码前停止调度器并保留表，旧代码兼容附加表；不得重新启用旧版不安全的到期清理。已物理删掉的数据不由代码回退恢复。

验证结构保真/异常回退/幂等，导入去重、metadata 与原始快照，失败后重开数据库成功、次数上限、目标库漂移、跨租户拒绝、90 天前不清理与重复清理。使用 Mock 仅证明流程。真实 Milvus 验证另属 RAG-015。
