# ADR-0009 单实例导入抢占、恢复与发布凭据

日期：2026-10-10。状态：Accepted（已批准单实例任务范围内的技术细化，实施与验收以当前证据为准）。

授权依据：用户 2026-10-09 批准任务集按单实例规划，见 [范围调整记录](../plans/plan_tasks_single_instance_rescope_20261009.md)；2026-10-10 用户明确调用 task-card-delivery 技能，启动多 Agent 实现 RAG-039。本记录不授予生产操作、真实数据迁移、模型费用或 Git 发布权限。

## 背景与事实

现有导入器把并发配置当批次 limit，逐个执行；pending 检查与 running 写入分离，进程退出后的 running 无恢复。文档摄取自行提交，存在文档已经发布而任务尚未记成功的窗口。重解析更新同一文档，不能只凭目标存在推断本次重建成功。URL 配额事务可能跨网络等待持有 SQLite 写锁。

## 选项与决定

采用既有调度器、进程内短锁登记与数据库条件更新，不引入队列、分布式锁或跨实例租约。纯 asyncio 锁不足以覆盖同进程多个线程事件循环；跨实例基础设施超出已批准范围。

- 按实际 Engine 绑定活动任务、来源互斥和全局并发；每个执行任务独立 Session，异步等待不持登记锁。批次大小与最大并发分别配置，原 `limit` 参数继续表示每轮批次上限。
- pending 条件更新为 running 并递增尝试数后才执行。相同租户与来源任务串行，避免两个任务同时判断同一当前版本；不同租户不共享来源身份。
- 执行入口与调度启动恢复非活动 running。普通导入核对 `Document.import_job_id` 及租户、用户、来源等绑定后补成功；无发布凭据的中断任务在尝试额度内回到 pending，额度耗尽失败并留痕。已有 failed 不自动无限重试。
- 重解析只在最终文档事务提交前写入对应导入任务成功凭据，任务和重建结果一起提交；既有无任务参数的直接重解析调用保持兼容。异常与取消必须先核对持久凭据，不将已提交结果翻成失败或重复发布。
- URL 源文件配额预留与快照登记使用短事务，登记后源字节由现有配额统计覆盖，再进行解析及嵌入等待。已登记的本次快照可供中断恢复；初始重解析旧源文件不得当作本次新快照或失败清理对象。
- 检查任务、批次、重解析目标与存储目录的租户绑定；沿用系统管理员既有跨租户管理和历史内部任务兼容，不引入资源 ACL。
- 未全部完成的批次保持 pending/running；全部终态后才计算 success/partial_success/failed。恢复、重试、取消均更新持久统计与脱敏 trace。

## 后果与兼容

保证范围是一个应用进程，包括该进程内多个协程与线程入口，不证明多进程或跨实例安全。默认 local 不变；外部向量与 SQL 仍不共享事务，沿用现有补偿，不能宣称跨系统 exactly-once。配额预留与最终发布之间可能留有待恢复快照，原文保留而非清理真实数据。具体算法、失败边界、文件归属与证据见 [实施计划](../plans/plan_rag_039_single_instance_20261010.md)。

## 迁移、验证与回滚

复用已有表和字段，不自动迁移或重建真实知识库。验证使用隔离 SQLite、临时源文件与合成 Embedding，证明生命周期而非检索质量。覆盖多入口竞争、线程并发上限、已发布中断、未发布重启、取消、次数上限、配额并发、同源版本、跨租户、批次统计和旧版本失败后可检索。最终通过与未验证项写入单卡实现说明和独立审查，不由本 ADR 推导。

回滚前停止导入调度器，恢复本卡代码和配置；保留任务、文档、源文件与 trace。无 schema 降级、重要数据删除或外部索引重建。回滚到旧代码后，中断任务恢复与并发保证会失去，须人工核查未完成导入，不能把代码回退当作数据恢复。

## 2026-10-10 批次终态恢复补记（F03）

用户授权修复最终审核F03，独立计划通过，方案见 [批次恢复修复计划](../plans/plan_rag_039_batch_recovery_fix_20261010.md)。子任务已提交success而最后汇总事务失败时，恢复不能只查running子任务。

- 既有恢复入口先更新非活动running任务及trace并flush，随后以单次SQL outer join/group by按持久子任务对账批次状态和计数；正常完成与恢复共用状态规则，不再逐running任务先缩批次total。
- 对空批次、现存子任务少于声明total、tenant/user绑定不一致批次保持汇总并记录仅batch id/原因的诊断，不把残缺集合缩成success。计数漂移但子任务绑定完整时校正；极大声明total不擅自缩小。
- 已success/failed子任务不回放，不增加attempt，不再次Embedding/发布；活动running保持运行，pending批次不提前终态。恢复返回值仍仅为恢复running子任务数量，批次修复不计执行数。
- 更新与恢复同事务提交；再次提交失败向上传播并回滚，后续可重试。一次聚合避免历史批次逐项多次查询，只实际漂移批次写入；修复后重复恢复不发UPDATE。仍为单实例边界，不增加队列/schema或跨系统事务保证。

验证采用真实导入入口故障注入、新Session与新Python进程读取隔离SQLite；状态/唯一性证据见正式test_rag_039_batch_recovery及独立复审，不由本记录推导通过。回滚仅移除本轮汇总对账，保留前次任务恢复代码及数据库/源文件；回滚后F03缺口恢复存在。


## 深度审查修复技术补记（2026-10-10）

沿已批准权限及单实例范围，来源串行不授予版本链写权限。异步去重/版本候选只有现有can_write_document允许的主体才可复用或升级；普通成员同名上传命中他人有效来源明确失败，拒绝前不Embedding或降级。tenant/uploader读语义不变，不新增ACL/共享写授权，历史无actor内部任务兼容保留。同主体与合法tenant/system管理员仍按现有权限处理。软删候选排除，新导入建立合法新版本组，不恢复被删旧知识。

普通批次构建、完成和retry聚合使用声明total作为下界，只聚合同tenant/user子任务；0空批次不成功，缺任务pending/running，不提前终态。创建子任务在add/flush/commit前校验batch绑定，commitFalse仍由原整批/配额事务拥有提交。恢复既有严格缺child guard及一次GROUPBY保持。

去重任务可以持久success/document_id而文档marker属于原job；确认故障后仅在rollback/refresh、现有完整binding校验通过且数据库持久job success/hash与合法doc tenant/source/未删/hash/适用主体相符时保留成功。不可盲信内存或手工success，不放宽无效当前marker拒绝；取消仍传播，已提交结果不反写失败、不重耗attempt。外部SQL与向量仍不共享事务。

正式故障回归、独立审查与未验证范围见深度修复计划/实现说明。SQLite50ms争用限制保持；不以本补记宣称生产、高负载或多进程保障。回滚停调度后仅退本轮边界修复，保留原039/F01-F03/QA005及重要数据；无schema迁移/真实数据删除。人工业务验收仍待用户，任务保持in_review。
