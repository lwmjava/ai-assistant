# ADR-0011 结构化顺序 Agent Plan

日期：2026-10-13。状态：Accepted，用户2026-10-13明确批准本方案及Mock范围扩展；批准不等于已实现。任务：PAGT-004。此记录不代表功能实现，不授权生产、付费模型、数据迁移或 Git 发布。

## 背景与事实

原卡要求可解析的结构化步骤，含依赖与预期产出，并逐步执行和失败定位；明确不做通用 DAG，也不改五阶段整体结构。当前 SYSTEM_PLAN 输出编号文本，行动循环自由选择工具，没有步骤状态。ADR-0010 的 StateManager/ToolExecutor 和同消息恢复已在当前工作区存在，必须复用，不另造 Runtime。

当前 ToolExecutor 的正常返回不总等于业务成功：内置部分工具把错误转换为文本。本卡若只记录 Executor ok 会掩盖失败，必须保留结构化业务错误分类，兼容旧观测格式。

## 选项

1. JSON 展示 + 自由行动：不能证明逐步执行与失败对应，否决。
2. 固定顺序 tool/reason 步骤：推荐，最小覆盖原始契约。
3. DAG/并行/动态数据引用：超出本卡范围，Deferred。

## 已批准决定

Plan v1 为版本化严格 JSON，1–16 步，每步含 id/description/kind/depends_on/expected_output；工具步声明 tool 与具体 JSON arguments。依赖仅指向数组中更早存在步骤，不运行拓扑调度。参数不从前步动态注入；reason 和最终草稿可消费当前可见的脱敏步骤观测。

开跑前校验完整计划，禁止重复/未知/后向/自依赖、非有限数值、未知字段与超限内容。行动阶段顺序执行，复用 Executor、RBAC、审计、注入围栏、预算与指纹。工具正常与业务错误用结构化状态传递，旧显示文本不变。失败定位到 step_id 和安全错误码，停止后继。

StateManager 新增结构化计划、步骤状态及成功前缀游标并原子验证。合法计划生成、每步完成和失败均 checkpoint；取消保留已完成前缀。当前恢复入口与权限保持，单实例、非 exactly-once 边界不升级。QualityGate 仅修最终草稿，不重跑成功工具。

非流式与流式复用同一个步骤执行迭代器，保持现有事件契约，步骤 Trace 仅记录安全标识和错误码。所有新增模型调用有界超时，工具重试遵既有幂等契约，总预算不重置。

## 兼容、迁移与回滚

保留 state.plan 文本视图给 RAG/Prompt 使用；新增结构字段带版本，旧 checkpoint 缺字段继续原文本链。新运行默认严格 v1，非法规划不自动降级为可执行旧链；原文本可作展示。显式构造参数关闭新规划以走旧路径；已保存 v1 快照仍按 v1 恢复，不改走旧链重做工具。

无数据库 schema 迁移，无服务/API/前端变更。MockLLMProvider 仅增加规划阶段有效 JSON 响应，其他行为保留；该文件范围已明确批准。回滚通过构造参数或回退本卡代码，保留业务数据。不能把回滚代码当重要数据恢复。

构造参数回滚保留 v1 解析与续跑；完整回退到不识别 v1 的旧代码无法保证新活动快照恢复，须停止并人工核查活动执行。每计划的 checkpoint 次数包含计划生成、各步边界与终态，按本卡有界步骤数核对，不沿用旧工具轮写入上限。

## 验证与后果

采用真实 Pipeline/Executor/Service/HTTP 和隔离 SQLite，脚本 provider 为 E2，不证明真实生成质量。覆盖完整依赖校验、业务错误、权限、预算、取消新 Session 恢复、同步/流式一致、QualityGate 不重工具、旧 checkpoint 与回滚。独立工程审查、入口级反例、关闭对账和最终人工审核按 task-card-delivery 执行。

具体实现与失败边界见 docs/plans/plan_pagt_004_20261013.md。用户未委托业务验收，最终不自动done。动态参数引用、通用 DAG、前端步骤 UI、多实例和生产验证均未交付。
