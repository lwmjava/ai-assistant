# ADR-0012 SSE ActiveRun 生命周期与断线回放

日期：2026-10-15。状态：Accepted。用户明确批准 docs/plans/plan_sse_001_20261015.md 方案及必要路径。仅批准单进程执行所有权与事件回放边界，不授予生产操作或发布权限。

## 目标、现状与非目标

当前 HTTP 流直接消费 ChatService 管线，断开与执行取消耦合，缺少运行所有权、事件序号和回放。目标是所有事件携带 run_id，事件名与需求逐项一致，断线后生产任务继续，重连只订阅增量而不重跑模型或工具，结束后可查询完整结果。保留已有受控 ChatService、身份/租户权限与 checkpoint，不另造 Agent Runtime，不做引用侧栏、多实例状态外部化或进程重启自动续跑。

## 决定

在 services 增加单进程 ActiveRun 管理器，由其拥有生产 asyncio.Task；HTTP 流只是订阅者，关闭订阅不取消生产任务。每个 run 绑定 user_id、tenant_id、conversation_id 与 message_id，查询、订阅和取消均重新验证当前有效身份及绑定，未授权不泄露 run 是否存在。任务使用独立数据库会话，不持有已结束请求的 Session。明确取消通过受鉴权接口执行；停机时取消并回收任务，不能声称跨进程持久运行。

事件 ID 为 run_id 加递增序号；统一 run.started、node.started/finished、intent.classified、plan.generated、tool.call/result、token、citations、error、run.finished、heartbeat。15 秒无输出发心跳。重连使用同一 run 的 Last-Event-ID，浏览器在 30 秒内重连一次；不再次提交原用户消息。新增 GET /api/v1/runs/{id}、GET /api/v1/runs/{id}/events、POST /api/v1/runs/{id}/cancel。终态查询返回经过既有输出安全处理的最终回复及状态。

缓存采用有界内存：单 run 最多 1000 条事件或 8 MiB、进程最多 100 个保留 run；仅淘汰终态 run，已满且全部活动时拒绝新 run，不取消已有任务。终态保留 15 分钟；超出回放窗口明确返回可识别的冲突并引导加载最终结果，不能静默丢 token 或启动第二次执行。缓存仅用于短暂断线，长期结果沿用消息持久化；不将原始工具参数、凭据或未脱敏返回写入事件。上述界限作为服务内常量，不额外新增配置路径。


## 选项、后果、迁移与回滚

否决继续以 HTTP 连接拥有执行任务：不满足断线继续与增量回放；否决本卡引入分布式任务队列/共享事件存储：超出当前单实例边界。采用受控 ChatService 外层的单进程任务管理，消息持久化与已有 checkpoint 保持原责任，不新建数据库表。

进程重启会失去活动任务与短期缓存，不声称高可用或跨实例续流；终态消息仍可按对话权限读取。缓存/并发限制产生显式拒绝，不静默覆盖仍活动的任务。客户端与服务端协议需同步迁移，不保留第二套旧流式协议作为业务别名。

停止生成通过显式取消接口；订阅取消只释放连接。应用停机必须回收生产任务和独立会话。恢复旧版本前停止接收新 run 并等待活动 run 完成，回退前后端与文档，不删消息或 checkpoint。

## 验证

逐项覆盖产品 §5.1.4 全事件及字段、Last-Event-ID 顺序回放、权限撤销/跨用户租户、窗口过期、缓存限制、断线继续、主动取消只保存已生成部分、Session 生命周期、慢订阅不阻塞、错误脱敏与终态最终查询。新增确定性 Agent Evaluation、前端交互与四门、后端全量回归、最终输入指纹及 Linux/CI 门禁。未完成项明确保留，不以 ADR Accepted 关闭任务。
