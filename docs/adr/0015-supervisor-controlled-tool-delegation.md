# ADR-0015：Supervisor 研究节点受控委派工具行动

状态：**Accepted**，2026-10-19。User explicitly approved this plan, allowed_paths and ADR-0015 on 2026-10-19.

## 背景和事实

Supervisor 已具备有界 research/draft 控制及节点事件，但 research 只调用模型；传入 tools 并不使工具可执行。默认和工具短路径已复用 ToolExecutor。AgentPipeline 的行动循环包含解析、参数检查、权限执行、重复检测与不可信资料防护，但没有 state_store 时每次进入会重置轮次。当前子任务摘要取自模型文字，不能证明真实执行。

## 选项

- **A（推荐）**：research 在需要工具能力时委派给请求内既有 AgentPipeline 行动循环，调用既有 ToolExecutor；控制和最终草稿仍由 Supervisor 负责。同一请求共享累计轮次、指纹和工具结果。
- B：新增图工具节点，另行连接工具提议与执行。图结构更显式，但容易复制解析、预算、重复检测与拒绝规则，增加兼容面。
- C：直接委派完整 Pipeline.run。会重复理解、规划、检索和最终回答，扩大知识库组合及预算语义；不采纳。

## Accepted decisions

1. 采用 A。Service 装配请求内行动委派器、注册表、身份上下文与技能租约。Supervisor 仅研究节点可触发行动；不调用完整 Pipeline.run，不重复检索，不改变现有 route_message 的优先级或默认 self 编排。
2. 复用同一 AgentState 和请求内委派器；显式启用累计预算，不伪造 state_store。总工具尝试额度沿用 AGENT_MAX_TOOL_ROUNDS；拒绝、无效和重复提议不得免费刷新额度；调研轮次仍受上限约束。额度耗尽直接进入草稿，不能每轮重复调用收尾模型。
3. 工具只可来自已注册、具有效契约的 L0/L1 能力，并继续满足既有身份、租户、角色、参数、风险及审计规则；L2/L3、无契约与未注册工具不得在新路径自动执行。L1 不获得新授权，生产写操作仍须单独授权；现有工具的有限重试策略不变。新增节点不改变全局 RBAC，也不替 MCP 补造契约。
4. 在该研究委派路径消费 Skill 工具绑定，与上述允许集取交集；只在该受控能力可用时将 Supervisor 工具模式从 unsupported 升级为支持。控制和草稿节点没有工具执行权，私有技能围栏与每次新启动前的版本/撤权复核保持。明确补充 ADR-0014 第4点的暂不支持限制，其余决定不变。
5. 每次研究以真实 ToolOutput/执行结果生成有界、脱敏的确定性结果摘要，区分 not_called、denied、invalid、error、timeout、ok，以及重复跳过、预算耗尽和取消。模型生成的研究/最终文字不作为执行证据；未调用或失败的状态必须在最终可见文本中确定性披露。可保留模型解释，但不能覆盖真实状态。
6. 复用既有 tool/node/subtask 事件，不新增 API/schema。结果状态可写入现有事件可选元数据和摘要文本；对外 subtask 的兼容状态含义不得改变成前端不认识的枚举。拒绝和取消等路径核查审计；提前策略拒绝若缺记录，补最小的既有审计接线，不记录原始参数、正文或异常堆栈。
7. 控制、研究和草稿调用均有有限次数及超时；预算总上界在实现计划中列出。取消传到正在运行的委派/执行器，不启动后续节点；已发生副作用不承诺撤销。流式消费者在 tool.call 让出控制后，紧贴实际执行前再次复核技能，不把排队事件当作授权关口。
8. Supervisor 显式 checkpoint 恢复仍不支持，继续安全拒绝；不保存为自研管线可恢复的运行，不自动重放。直接构造且未注入委派能力的旧调用方保留无工具模式，必须明确说明没有工具执行。
9. 新委派器注入 Service 负责的主体复核回调：每次启动工具前用独立 Session 检查当前 User/Tenant、角色与 token_version；无技能时也检查，不能用空 SkillRuntime.check 代替。开发无认证哨兵只沿用已有明确配置，不能据此授予需认证的 L1 工具。数据库不可用或身份无法证明时拒绝。Agent 不访问数据库，不承诺撤回已开始动作。
10. 研究文字和工具观测始终是有界、不可信资料，不进入控制节点的系统指令；保留原始用户目标作调用授权依据。控制模型看到的是安全状态摘要，不能把工具返回或研究里的调度指令当成新的权限。
11. 新路径的“有效契约”必须由代码校验，不能只判断 contract 非空：risk 为 L0/L1、audit=true、版本/权限声明完整，timeout_seconds 为非bool有限正数且不超过300秒，max_retries 为非bool整数且在0至3之间；不满足则新路径拒绝。只收窄新委派，不放宽或全局重写旧工具契约。具体工具原有更严格限制仍生效。
12. 保留 Supervisor 现有图前一次检索及原上下文防护；不新增知识库/工具组合规划、资料参数提取或路由规则，不将本卡证据当作 V1C-005 完成。工具提议不能把检索正文转为新的授权来源。
13. 新委派路径调研上限R为非bool整数0..10（默认2），工具总尝试T为非bool整数0..100（默认沿用配置10，直接构造0表示不执行）。非有限值、负数、超界或类型错误拒绝，不通过截断掩盖非法配置；旧未注入委派能力的构造不全局改变。

## 后果和兼容

有工具的研究轮可能多次调用模型，必须按请求累计额度；无工具能力的旧直接调用保持原单次研究。现有 Skill 支持矩阵和无工具 Prompt 测试需要按新增能力更新，不能删除隔离/版本/拒绝断言。真实执行结果是额外不可信资料，仍须围栏、预算与脱敏。

## 验证

真实 ChatService 普通/流式与真实 LangGraph、隔离 SQLite、合成模型及本地工具；覆盖成功、从未调用、伪称成功、未注册/无契约/高风险、失败/超时、参数非法、权限/租户、取消、重复、跨研究轮次累计预算、版本撤权、缓存命中后仍真实执行新请求。专项、全量 pytest、Ruff/mypy、独立入口审查和最终审核均绑定最终输入；不以隔离结果证明生产模型质量。

## 迁移和回滚

无 schema、数据库迁移、新框架或供应商。回退新委派接线与累计预算可选参数，Supervisor 恢复只生成研究文字并明确不支持工具；保留消息、审计与旧 checkpoint，不重放动作。不更改默认 self。生产启用、费用、Git 发布及业务接受各按用户对应授权处理。
