# ADR-0019 开发环境 Milvus Lite 启动选择

> 状态：**Accepted**（2026-10-21）
> 批准：用户要求开始实施开发环境 Lite 启动兜底。
> 本决定不表示 Lite 已在当前 Windows 环境跑通，也不表示前置的默认 Milvus 闭环已经关闭。

## 背景

默认向量库已是 Milvus。开发机上的 Standalone 经常没启动。若每个请求自行改连另一个库，同一批文档会在两个互不相通的实例之间丢向量，检索却表现为没有命中。

## 事实

- 项目固定 `pymilvus==2.5.11`，连接使用 ORM `connections` / `Collection`。
- 2026-10-21 在 Windows、`ai-assistant` 环境中检查：`milvus_lite` 模块不存在。因此本机不能把原生 Lite 摄取当成已通过。
- Standalone 与 Lite 的文件不共享。历史索引用 Standalone 写入，没有单独的存储标记。

## 选项

1. 启动时选择一次，并把选择写进数据库；进程内不再改。Lite 一旦记下，即使后来 Docker 恢复也不自动切回。
2. 每次检索失败再换库。两个实例的数据会混用，否决。
3. Lite 不可用时退回本地 NumPy 向量库。会重新引入已经放弃的默认路径，否决。

## 决定

- 只在 `RAG_VECTOR_STORE=milvus` 时选择。`local` 仍是显式离线模式，不是故障替身。
- 生产环境、关闭兜底开关，或服务地址不是本机回环地址时，只使用配置的 Standalone。选择失败时固定为向量能力不可用，非检索API仍启动；检索/摄取明确失败，不逐请求重试或换库。
- 鉴权失败、Schema 不匹配、其他配置错误不进入 Lite。
- 开发环境且地址是本机时，只有连接拒绝或超时可以在启动时改用 Lite 文件。
- Lite 运行库缺失时明确失败，并说明需要在 Linux 或 WSL 使用同一客户端版本。不升级 SDK，不宣称 Windows 原生已支持。
- 选择写入 `rag_vector_runtime`。已登记Lite重启后，仍需满足开发环境、启用兜底、本机服务地址、运行库可用且文件路径一致，才继续Lite；限制变化时拒绝向量能力，不自动切库。已登记Standalone端点改变或服务不可用时不自动换实例。
- 新建Milvus索引用 `rag_index_storage.storage_instance` 记录模式与规范化位置的SHA256摘要；Standalone按协议/主机/端口，Lite按规范化绝对文件路径。禁止URI内嵌凭据和查询串，Token仍使用独立配置。该摘要同时隔离缓存。读、已有索引复用、显式目标写入/删除及连接都核对，差异时先于远端副作用拒绝。
- 缺少实例摘要或仅有旧模式名的历史索引无法证明实际归属，启动后保持隔离，不能自动认领到当前实例；核验/迁移须另行受控执行。本轮不扫描或改写重要历史数据。不承诺检测同一地址后端数据卷被替换，恢复与卷管理仍需受控操作。
- 健康检查和管理状态写出实际模式与兜底原因，不写出口令或令牌。

## 后果

2026-10-21验收修复授权补记：Windows 开发机在 Standalone 未启动且没有 Lite 运行库时，向量能力不可用，健康检查报告error与脱敏原因；普通非检索API仍可服务。恢复向量能力需核对配置后重启。这替代此前“整个应用启动失败”的表述，与VDB-001非检索隔离契约一致。

## 迁移与回滚

新表由建表和Alembic补齐，实例摘要使用已有字符串字段，不新增列。关闭兜底后已有Lite登记会令向量能力不可用，不能静默恢复Standalone。回滚保留Lite文件与登记，不自动删除或合并实例；旧代码不理解完整实例标识时须先核验再恢复向量读写。

## 验证

选择规则用注入的探测结果验证。真实 Lite 摄取必须在具备 Lite 运行库的 Linux 或 WSL 上单独取证。当前 Windows 探针未通过，不能当作该验收已完成。
