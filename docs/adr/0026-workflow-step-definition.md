# ADR-0026 工作流只编辑已批准的 Prompt 步骤

日期：2026-11-07。状态：Accepted。范围限于现有单步工作流的定义校验、修订冲突和运行图；不新增表，不表示业务验收已经完成。

## 背景与事实

现有 Workflow 是一条定时 Prompt。WorkflowEngine 把 `prompt_template` 原样交给现有桥接，一次执行产生一条 WorkflowExecution 和对应日志。没有步骤表、变量求值器或第二套执行引擎。

## 决定

已批准步骤只有 `prompt`，节点标识固定为 `prompt`。定义保存必须恰好是这一个节点，且没有出边。其它类型、额外节点、指向未知节点的边，以及任何循环（含自环）都在写入前拒绝。

花括号中的名字只作为声明过的变量。名字必须是有限长度的标识符，声明顺序必须与模板中的出现顺序一致。保存时不替换这些名字，也不把模板交给表达式求值。执行输入仍是模板原文。

修订标记是 `updated_at` 的 UTC 文本。保存请求必须带上刚读到的标记；不一致则不写模板。读定义和读运行图都不改执行历史。

运行图只有引擎实际执行的那个 Prompt 节点。节点状态等于 WorkflowExecution.status；失败时原因来自该次执行的失败告警。轨迹按日志发生顺序挂在同一节点上。

## 选项与后果

把多步图存进新表会改变执行模型，并超出当前不新增表的边界，否决。在模板上做 `format` 或求值会把声明变成执行能力，否决。沿用现有更新接口保存名称和调度，模板改由带修订标记的定义接口保存。

旧数据不迁移。已经保存的模板仍按原文执行；其中若含非法占位，下一次定义保存会被拒绝，直到改成合法声明。

## 迁移与回滚

没有新列和新表。回滚时移除定义与运行图入口，已保存的 `prompt_template` 和执行历史保留。不重放历史执行。

## 验证

覆盖保存后重载、模板原文进入执行输入、未知步骤、非法变量、循环、过期修订、跨租户相同 404、只读角色拒绝写入、停用主体拒绝，以及失败节点与执行状态一致。读取运行图不改变执行记录。
