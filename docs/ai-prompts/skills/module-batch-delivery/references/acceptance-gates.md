# 交付验收门禁 v1.0

每卡开工及关闭时执行；模块最终验收再次检查受跨卡修改影响的项。

## 1. 契约与可观察断言

从原始任务的 deliverables、acceptance、non_goals、依赖和批准决定建立表：

| 原始要求及出处 | 输入/前置 | 实际操作链 | 可观察期望 | 测试或报告 | 代码指纹/环境 | 结果/缺口 |
|---|---|---|---|---|---|---|

不得只对照自行撰写的实施计划。任何删除、弱化、移到非目标的必交付项均列为冲突，不能自行接受。版本化路由理由不等于版本化完整切分计划，保存策略名不等于保存有效参数。

## 2. 测试证据层级

- 确定性算法可用有效单测；持久化、多个入口、生命周期、权限或跨系统要求必须覆盖真实适用链路。无需为无关任务添加全系统 E2E。
- 持久化要求提交后从新会话读取验证，不以同一对象仍有值代替保存成功。
- “上传/重解析一致”必须实际执行两阶段，比较有效策略/参数、内容、结构及适用来源范围；覆盖请求覆盖、相关配置变化和旧数据缺计划。纯随机 ID 不要求相等。
- 验证失败后的数据/副作用状态、回滚与适用幂等性；仅断言抛异常不够。故障注入只在隔离环境。
- 页面要求经实际操作后检查状态和必要持久化；构建/截图打开页面不代替用户路径。
- 新失败测试须失败于缺失业务行为；模块缺失、导入错误或环境崩溃不单独证明业务问题。可先修测试设施，再记录有效红绿结果。

## 3. 独立与证据有效性

审查者读取原始卡、最终代码及证据，自行设计相关反例，不只复述实现说明。不编造发现、不靠最低问题数量验收。无真实独立执行上下文时如实报告，强制要求未满足不能关闭。

命令记录实际解释器、测试数据、相关配置覆盖、退出码、结果、报告和代码状态。提交 hash 在有工作区改动时不足：另记录受影响代码/测试/配置的指纹或可追溯 diff。后续修改影响行为时重新验证/审查受影响范围。

skipped、未执行、Mock、替代验证逐项映射未证明的要求。配置覆盖可以用于可复现测试，但不能把 structured 路径通过作为 auto 路径验收。基线失败按证据隔离，不偷偷改变验收目标。

## 4. 指标与关闭

任务要求质量或性能对照时提供适用数据集、评测器、版本、参数与可复算指标；测试通过数量不能代替覆盖/结构破坏/检索/延迟指标。旧报告仅在证明适用于最终实现时复用。

关闭前交叉核对：原始交付、测试/评估、审查发现、实现说明未做项、任务状态。任一必交付项同时被记为“未做”或“后续再做”，阻止 done。

每项状态只能为通过、失败、未验证、不适用；不适用给出原始契约或批准依据，不能自动豁免难测项。所有必验项通过且门禁/文档完成后才关闭，具体状态枚举沿用仓库规则。全绿单测、多个 Agent 赞成、无阻断代码问题均不能单独证明整卡完成。

模块完成还要求最终整合结果通过，前卡证据仍有效，无未关闭的必交付卡。阻塞子树可保留，不可假 done 供下游运行。
