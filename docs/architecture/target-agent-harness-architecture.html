最终目标架构图

以 Agent Harness 为控制平面，将模型决策、受控执行、数据访问和横切治理分离。箭头表示主要依赖或调用方向。

OS 核心 / 社区接口 EE 增值扩展 TARGET 渐进治理组件 安全、审计与交付治理

架构约束：模型只能提出结构化动作。代码动作必须进入 Code Sandbox，不得在宿主进程执行。业务动作必须经 Adapter / Repository。测评是离线横切能力，不嵌入第 3 层 Harness 循环。

当前事实：本图是目标职责图。当前项目已具备部分 Pipeline、RAG、Tool/Skill、Memory、Security、Audit、Trace 与代码沙箱能力，但独立 Harness、Context Builder、Tool Executor、State Manager、持久化 Trace、结构化 Citation、版本化 Evaluation 和正式 Milvus 闭环仍需按治理路线渐进收敛。
架构图文本说明：
  1. Web、API、社区 Channel 与 EE 企业 Channel 通过统一消息契约进入 Gateway。
  2. Gateway 完成认证、RBAC、租户/资源 ACL、配额与请求追踪后，才将请求交给 Harness。
  3. Harness（第 3 层）只负责编排：Context、Runtime、State、预算、Guard 与 HITL。它不包含沙箱运行时，也不执行测评。
  4. Runtime 从模型、Skill/Workflow、Tool Registry 与 MCP 获取能力；RAG/Memory 在权限过滤后提供不可信上下文。
  5. 代码动作经 Tool Guard 后进入第 4 层 Code Sandbox（AST 白名单、进程隔离、资源限额、超时 Kill）。
  6. 业务动作经 Adapter/Service 与 Repository 访问 ERP/CRM/企业 API，禁止 Agent 直连数据库或遗留系统。
  7. Evaluation 测评位于第 6 层横切治理：离线消费 Trace 与 Gold/Silver/Adversarial 数据集，覆盖 RAG、Agent、Skill 与 Safety；不阻塞单次用户请求。

关键请求时序图：从用户请求到受控完成

展示目标运行时的主路径，以及风险动作进入人工审批的分支。RAG、网页、Tool/MCP 返回均以不可信内容处理。

目标执行语义：短路路径可跳过不需要的计划或工具步骤，但不得跳过身份、权限、Guard、沙箱隔离（代码动作）、审计和输出安全检查。测评在请求完成后异步进行。

时序图文本说明：
  1. 用户通过 Channel 发送消息或 API 请求；Gateway 验证 JWT、角色、租户、资源权限和限流。
  2. Harness 构建包含身份、任务、预算、会话、Memory 和权限过滤后 RAG 内容的 Context。
  3. Runtime 基于 Context 生成结构化 Action，并提交给 Guard；模型本身不直接执行副作用。
  4. Guard 验证动作的权限、风险与参数。需要审批的 L2/L3 动作创建绑定主体、参数哈希和有效期的审批请求；拒绝则终止并审计。
  5. 代码动作进入 Code Sandbox（AST / 进程隔离 / 资源限额 / 超时 Kill）；业务动作经 Adapter/Repository 访问外部系统。
  6. Runtime 完成后，Harness 执行输出安全检查、持久化与审计，并经 Channel 返回用户。
  7. Trace 异步进入 Evaluation。测评覆盖 RAG、Agent、Skill 与 Safety，不阻塞本次响应，也不属于第 3 层 Harness 控制循环。
