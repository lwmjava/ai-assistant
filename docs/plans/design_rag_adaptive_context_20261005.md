# RAG 结构识别、自适应切分与模型预算设计

日期：2026-10-05。状态：Draft / Planned，待评审；用户授权先落设计与 ADR，不表示批准实施、迁移或启用。决策草案：[ADR-0005](../adr/0005-rag-adaptive-chunking-context-budget.md)。事实核对：[RAG 任务卡评审](../reviews/2026-10-05-RAG任务卡能力覆盖核对.md)。

## 1. 目标、现状与范围

目标：用户上传后无需反复试切分策略；原文结构与含义完整；大章节可用摘要帮助理解；回答按所选模型的真实输入限制组装上下文，并能回查原文。

当前事实：parent_child 默认按 paragraph 切父子块，长段落硬切，父子分别切后按数量映射；structured 识别标题但正文仍按句子/字符处理；auto 只按文本启发式选四种。service.py 上传可消费 format/layout 的 ParsedBlock，重解析未复用同等路径。context_merge.py 固定记忆 2000、RAG 6000 字符截断；LLMProvider 没有窗口能力契约。当前来源是检索命中列表，并非逐答案点引用。Memory 摘要不是知识库章节摘要。

设计覆盖上传/重解析、切分、派生摘要、RAG 上下文与 LLM 调用预算；不改资源 ACL、默认向量库、Embedding 模型、RRF、独立重排、Query Rewrite。不得顺带重写 Harness 或新增框架/供应商。不直接迁移已有知识库。

## 2. 目标链路与职责

```text
上传/重解析 → Parser/ParsedBlock → 结构单元识别 → 自适应切分
             → 原文块/父子关系 → Embedding 与现有持久化
             → 可选章节摘要任务（独立状态，绑定原文版本）

提问 → 身份/版本过滤 → 原文检索 → 按需取同版本摘要与父块
     → Context Builder → LLM 调用前 Budget Guard → 生成 → 来源输出
```

Parser 提供原文、版式和来源位置；切分层决定边界，不授权、不生成事实；应用 Service 管理持久化与版本。Context Builder 为无数据库访问的组件，接收服务已授权的证据。预算 Guard 在每次实际 LLM 调用前校验，覆盖规划、行动、工具结果、质量检查、最终回答与摘要调用；共享能力契约，按请求所选模型执行。先在现有 ChatService/Pipeline 集成，不新增顶层 Runtime。

## 3. 结构保护与自适应切分

先识别章节标题、普通段落、列表、表格、fenced code、ASCII 盒图和解析器 blocks/bbox。对 fenced code/盒图保持换行、缩进和字符内容；普通正文在段落/句子边界组合。结构识别必须处理围栏内标题、不同围栏长度、未闭合围栏和嵌套列表，不用简单标题正则跨越代码块。

chunk_size 是软目标，模型输入上限是硬约束。完整结构单元在 Embedding 与生成预算均允许时可超过软目标；超过硬限时不能任意字符截断：长表按完整行分组并重复表头，正文按自然边界；代码按可识别边界拆分并保留关联元数据，无法安全拆分的图/超长行标记 oversized，保留原文且明确失败/待处理原因。完整原文保存在源文件中，不意味着整份都必须向量化。

识别失败使用保守结构路径并标记 degraded，不静默改为破坏结构的硬切。保留策略覆盖入口，但共享结构约束。不是为了覆盖十种策略强行路由；决策记录文档特征、策略与降级原因。

父块先按章节和结构单元形成，子块只在该父块内部切，使用来源范围建立父子关系；不按块数比例猜归属。无丢失/乱序通过来源范围覆盖校验；标题前缀、表头重复、overlap 标记为派生上下文，不与原文重复率混算。上传与重解析使用同一计划，保存计划版本、策略参数和来源位置。

截图案例：标题“战略定位：双轨制”与完整 fenced 盒图保持关联；图内从“实验”到“场”的行不得拆断，也不得折叠空格。若图超过软目标但未超过硬限，整体保留。

## 4. LLM 辅助边界与章节摘要

规则保护结构是前置硬约束。LLM 仅建议普通正文的边界，输出结构单元 ID/边界，不输出改写后的原文。验证边界合法、顺序、覆盖与结构原子性；超时、坏 JSON、越界、注入干扰均回退规则结果。显式开关，默认关闭，允许调用前核对当前用户/租户的数据处理授权；沿用已配置供应商，不自动外发至新服务。

大章节达到配置的 token 阈值才生成摘要；阈值不写死为当前 500 字符。摘要作为派生数据，不替代原文、不自动成为 Gold。版本信息包括文档/章节 ID、原文 hash、切分版本、Prompt 版本、摘要模型与生成状态。状态区分 pending/running/ready/failed/stale；失败不回滚已成功原文索引，不阻止使用原文检索，有限重试且有成本/时间上限。

超长章节先按结构分批摘要，再做层级合并；每次调用受预算 Guard 限制。输出摘要及支撑其内容的原文块 ID，校验 ID 同租户同版本并确实存在；仅 ID 有效不能证明摘要事实正确，真实质量评测仍必需。表格数字、条款例外、代码不得仅依赖摘要回答。

首次实现不建立新的摘要向量检索通道：通过原文命中的章节关联按需取摘要，或在用户明确请求指定文档概览时由 Service 授权读取相关章节。摘要显示为背景概览，不能作为逐答案点原文证明。过期/失败摘要跳过；重解析/发布/删除使摘要失效，不能串入旧版本。

## 5. 模型能力与预算

由版本化能力配置声明 provider/model/deployment 的 context_window、max_output、独立 max_input（若存在）、tokenizer/counting_method；Embedding 模型单独声明每输入与每批限制。记录来源与核对日期，不向 LLM 询问自身窗口，不把 max_tokens 当窗口。模型别名/部署更新后必须重新核对能力配置。

未知窗口/无法计数时不猜数：可使用管理员显式确认的保守配置并标记估算；没有此配置则拒绝该调用并说明配置缺失。优先使用支持的 tokenizer 或提供商计数能力，无额外依赖未经批准不安装。无法精确计数时需经过代表样本校准的估算与安全余量，仍记录限制，不声称数学保证。

```text
可用输入 = min(独立 max_input（若有）, context_window - 输出预留) - 安全余量
RAG 可用 = 可用输入 - 系统/工具 schema - 用户消息 - 记忆/历史 - 其他阶段内容
```

实际组装消息的角色包装、工具 schema、引用标签均计入；不得重复计算已计入的记忆。输出预留受模型 max_output 限制。预算不足按优先级减可选摘要、重复父块与低相关证据，再减少可压缩历史；不得删除安全约束或用户核心问题。仍超限返回明确原因，不无界重试。

RAG 按块选取、结构完整，保留不可信开始/结束围栏。每次 LLM 调用前再核对最终 payload，后续工具与 critique 的增长不能绕过预算。来源区分 retrieved/selected/cited：用户来源输出至少对应 selected 原文；真正 cited 需生成后的定位与准确性验证，不因送给模型即宣称被采用。

## 6. 权限、失败与一致性

摘要、原文、父块均沿用现有租户、文档版本、生效与删除规则；关联取父块/摘要时再次校验。不得放宽控制面写权限来开放只读引用。uploader 回滚语义与同租户引用只读权限的既有缺口需单独确认，本设计不擅自改变。

新版本准备完成前旧版仍保持可检索；成功切换需原子提交；外部索引切换/补偿按独立任务验证。摘要失败、模型不可用、超限与无命中分开记录。Trace 记录版本、边界决策、token 计数、选块/弃块原因、耗时与成本，不记录凭据、用户全文或文档摘录。

## 7. 交付顺序与任务关系

本次不新增/修改 tasks.yaml，不把下列阶段当作已批准任务卡。正式拆卡需另落拆分计划并校正 allowed_paths/依赖；一次只实现一条。

1. RAG-021：结构保护、源范围、超长结构策略及失败测试；先建立切分评价。
2. RAG-022：结构驱动路由、上传/重解析一致性与父子归属；引用原始完整块验收。
3. 单独拆模型能力契约与 token 预算任务：配置、全调用入口、Context Builder、超限失败；不混入切分实验。
4. 单独拆 LLM 边界辅助：开关、输出校验、降级、成本与真实质量评价。
5. 单独拆章节摘要及关联组装：生命周期、授权、事实保真、引用、失败与增量恢复。

模型预算先于 LLM 辅助/摘要；阶段可分别关闭。现有 PRAG-003/004、RAG-015/017 与权限/版本卡是接口与验证关联，不把未完成依赖默认视为通过。

## 8. 验收与 Evaluation

确定性用例：截图同类盒图；代码内标题；超长表格/行；中文混合文档；父子范围；空文档；上传/重解析一致性；模型切换；所有阶段 payload 超限；围栏完整；selected 来源与实际上下文相符；跨租户/旧版/软删摘要拒绝；模型失败规则降级；新版本失败旧版继续可用。

切分指标：原文覆盖、丢失/乱序、结构破坏率、父子包含关系、长度分布与 oversized/degraded 比例。受保护且未超硬限的样本结构破坏率为 0；无丢失/乱序；超限样本必须有显式结果，不伪装完整。

真实评测：分别运行规则基线、路由候选、LLM 边界候选、摘要候选，其他变量固定。沿用冻结 rag-v0.1，不覆盖原报告、不用 holdout 调参；追加版本化结构与生成回归集，AI 生成默认 Silver。记录 Recall@1/5/10、MRR、nDCG、答案点正确性、引用准确率、拒答与安全切片，以及延迟/成本。新增生成门禁阈值须在实施计划中批准后固定，未定阈值前不允许启用生产；Mock 只证明链路。

实施时用项目指定 conda 环境运行适用 pytest/ruff/mypy；新增配置同步 .env.example/README，Schema 同步 OpenAPI 与契约，前端变更执行 typecheck/build。当前指定环境路径未找到是已知验证限制，本轮没有执行测试。

## 9. 迁移、回滚与待批准事项

新切分版本仅作用于新上传和明确请求的重解析；旧索引可读不被启动时重建。重建需授权、保存旧索引版本、验证成功再切换。摘要不就地覆盖原文。模型与 Embedding 索引版本绑定遵守 PRD，不能原地混用模型。

回滚分别关闭 LLM 边界与摘要，恢复规则路径；预算配置恢复到已验证版本，不能关闭硬预算护栏来绕过失败。切分回滚恢复旧计划与旧索引映射，重要数据重建需人工批准。默认 local、现有 Embedding 与 RRF 不变。

需要技术/产品负责人批准：ADR-0005、软目标与 oversized 行为、未知模型调用策略、摘要数据处理授权与保留生命周期、阶段发布门禁及实现拆分。用户目前仅批准文档落盘。所有上述新能力为 Planned，未实现、未迁移、未上线。
