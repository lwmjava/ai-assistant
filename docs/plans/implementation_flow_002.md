# 实现说明：工作流页失败态与空态

> 日期：2026-10-01
> 计划：`docs/plans/plan_d1.md` 的 FLOW-002 节
> 结果：空列表、引擎未启用、失败原因可以在页面上区分。

## 完成的行为

只改了工作流页。

1. 没有任务时仍显示「还没有定时任务」。
2. 手动运行返回 201 且 `status` 为 `failed` 时，提示标题是「执行失败」，正文用 `execution.error`。没有 `error` 时正文是「执行失败，未返回原因」。成功状态仍用成功提示。HTTP 4xx/5xx 仍用接口 `detail`。
3. 执行历史里状态为失败且 `error` 为空时，危险色段落显示「执行失败，未返回原因」。已有 `error` 时显示原文。没有记录时仍是「还没有执行记录」。
4. 开关关闭时仍是「工作流引擎未启用」。

## 代码位置

- `frontend/src/pages/Workflows.tsx` 的 `handleRun` 与 `ExecutionRow`

- `WORKFLOW_ENABLED=false`：页面标题是「工作流引擎未启用」，不是空列表。
- 开关打开且没有任务：看到「还没有定时任务」，没有失败原因段落。
- 一条没有执行记录的任务：历史是「还没有执行记录」。
- 创建者已停用后手动运行：提示是「执行失败」，正文是「任务创建者已失效（禁用或移出租户），工作流已自动停用」。历史里同一句按危险色段落显示。
- 另插入一条 `status=failed` 且 `error` 为空的记录：历史显示「执行失败，未返回原因」，不是空状态。
