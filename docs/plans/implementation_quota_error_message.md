# 实现说明：对话页回显配额上限

> 日期：2026-10-01
> 计划：`docs/plans/plan_quota_error_message.md`
> 结果：消息条数或源文件达到上限时，对话页在输入框上方保留说明，并弹出「已达配额上限」。这次失败不再显示成连接中断。

## 完成的行为

流式发送和一次性发送收到 `quota_exceeded` 时，输入框上方显示已用数量、上限，以及请管理员提高上限或删除会话后再发。原文会回到输入框。说明一直留着，直到下一次发送。轻提示标题是「已达配额上限」，正文与输入框上方相同。

网络断开仍显示「连接中断」。知识库上传和工作流执行如果收到同一响应，失败说明使用同一段文字。

## 代码位置

- 文案：`frontend/src/lib/quota-message.ts`
- 普通请求：`frontend/src/lib/http.ts`
- 流式请求：`frontend/src/lib/sse.ts`，`frontend/src/hooks/useChatStream.ts`
- 对话页：`frontend/src/pages/Chat.tsx`

## 验证

```text
cd frontend
npm run typecheck
exit 0
```

用临时库在对话页发送一条消息，消息上限为 0。输入框上方出现：

```text
消息条数已达上限：本租户已有 0 条用户消息，上限是 0 条。请联系管理员提高上限，或删除部分会话后再发送。
```

输入框里仍是刚才发送的内容。页面没有出现「连接中断」。临时接口和前端已停止，没有改 `data/ai_assistant.db`，也没有动 8000 端口上的服务。

## 没做的事

- 没有改 429 的响应体
- 没有在对话页提供修改配额的入口
- 没有在浏览器里再走一遍源文件超限和一次性发送
