# 租户与用户列表页

> 日期：2026-10-01
> 来源：系统管理员要在页面上设置配额，并把租户、用户列表改成与技能列表相同的表格方式。
> 状态：已实现。说明见 `docs/plans/implementation_admin_list_pages.md`

## 问题

配额只能通过接口修改。租户页和用户页是纵向卡片，创建表单铺在列表上方，行内直接改名称或角色。用户列表已有分页，租户列表一次返回全部。停用之后没有启用接口，审计枚举里已有 `tenant_activate` 和 `user_enable`，服务没有对应动作。

## 交付

- 租户列表、用户列表：筛选在上，筛选下方左侧是「新增」，新增进入独立创建页。表格最后一列是操作：详情、修改、停用或启用。租户行另有「配额」。列表下方分页。
- 租户筛选：名称、状态。数据仍用现有 `GET /api/admin/tenants?include_inactive=true`，页面内筛选并按每页 20 条分页。不改变这个接口的返回形状，避免技能页和创建用户时的租户下拉被分页截断。
- 用户筛选：用户名、角色、状态、租户。沿用服务端分页，并让列表接受 `tenant_id`，避免先分页再在当前页里筛租户。
- 新增页：`/tenants/new`、`/users/new`。创建成功后回到列表并提示。
- 详情、修改用弹窗。租户修改只改名称，已停用时说明须先启用。用户修改只改角色，不能改自己。详情展示当前行已有字段；租户详情同时读出两个上限。
- 配额弹窗调用现有 `GET` / `PATCH /api/admin/tenants/{tenant_id}/quota`。两个上限留空表示不限制，`0` 表示不能再新增，原因必填。
- 新增 `POST /api/admin/tenants/{tenant_id}/activate` 与 `POST /api/admin/users/{user_id}/enable`。停用确认后仍走原接口。启用已启用的记录返回 409。重新启用租户时，若已有同名未停用租户，返回 409，不改状态。启用用户不恢复旧令牌，需要重新登录。

## 非目标

- 不显示消息条数或源文件的已用量。
- 不改对话页和知识库页的 429 提示。
- 不增加侧边栏入口，不让租户管理员设置配额。
- 不改用户名、邮箱或密码，不删除租户或用户。
- 不把租户列表接口改成分页对象。

## 验收

- 系统管理员能筛选、翻页、打开新增页、查看详情、修改、停用后再启用。
- 租户配额保存后再次打开仍是刚保存的上限；原因为空时不提交。
- 非管理员调用启用接口得到 403。
- 启用用户后旧刷新令牌仍然无效，用原密码重新登录成功。
- 前端 `npm run typecheck` 通过。相关后端测试通过。
