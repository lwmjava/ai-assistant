## 目标、选项与推荐

目标：模型给出受支持的单一工具请求时，经同一个共享解析器形成 ToolCall，再走既有参数、权限、技能、租户、预算、审计和执行链；运行时与官方评测保持相同语义。

1. 继续强化提示词：改动小，但已发生同类复发，不能保证协议服从。不推荐作为单独修复。
2. 推荐：在共享工具意图解析层增加严格、有界的单调用 DSML 兼容解析。只将一种明确的 calls/invoke/parameter 结构转换为既有 ToolCall；不在通用 LLM content 层改写回答，不执行任何代码或动态表达式，不增加模型请求。
3. 原生 structured tool calling：需要供应商能力确认、LLM 接口和运行时/评测入口改造，当前范围较大，暂不采用。

## 推荐方案的约束

- 标准 tool_call 保持兼容；SYSTEM_ACT 继续优先要求标准格式。
- DSML 必须是整个回复的唯一调用结构，单 calls、单 invoke、唯一非空工具名；参数名不重复。仅允许明确的属性和已声明的标量/JSON 表示，严格校验；具体语法以实际失败形态和合成反例定义，不扩成通用 XML 执行器。
- 拒绝混合协议、多个调用、嵌套调用、未知结构/属性、重复参数、畸形闭合、超限内容以及任何有歧义的类型转换；不从解释文本、代码围栏或工具观测中猜测请求。
- 工具名不做别名推断，未知工具仍由现有受控路径拒绝。参数仍必须通过原有工具 schema；兼容解析不授予权限。
- 运行时和 evaluator 已共同调用 inspect_tool_call；不修改 scripts/、冻结数据、阈值、打分逻辑或 CI。测试中合法 DSML 由“未调用”改为“有效意图”，不代表未经执行器即可运行；畸形和未支持 DSML 必须拒绝。
- 不新增调用重试、预算、依赖、配置、持久化或框架，不改工作流重试行为。若检查发现必须改变 Harness/状态边界或 ADR，先另行裁决。

## 实施与失败边界

1. 独立审查本计划与存量调用方，确认兼容不会将工具结果变成指令。
2. 先写失败测试：实际观测协议的合成重放，通过官方入口记录一次调用；默认行动链的同形请求只执行一次；标准格式继续通过。
3. 反例覆盖：多调用/混合格式/重复字段/坏 JSON/错误类型/未知工具/超长回复；普通文本不触发；权限与技能限制仍拒绝；预算耗尽不执行；取消不继续执行。不涉及数值计算，但参数内非有限 JSON 数值必须拒绝。
4. 最小共享解析实现，参数完整传递，不对代码文本做求值或执行。同步受影响的非冻结协议契约测试。
5. 运行相关工具、Pipeline、Supervisor、权限、预算、取消、官方入口隔离测试；Ruff、mypy app/ 和不带筛选的全量 pytest，使用指定 conda Python 和隔离测试库。纯后端且无 API 契约变化，前端本地检查不适用。
6. 未参与实现的 Agent 独立审查最终 diff、入口反例和证据；实现说明另落 docs/plans/，评审落 docs/reviews/。记录最终文件 SHA256、平台、依赖、命令、退出码。
7. 不预先宣称修复真实模型。最终提交的 Backend、Frontend、Agent official baseline 必须通过后才能解除 CI 阻断；Git 发布和真实模型复验按对应授权执行。
