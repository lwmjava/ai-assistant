# 对外业务 API 版本前缀实施计划

日期：2026-10-15。API-001；原始契约 tasks.yaml，已批准 /api/v1 方向不重复裁决。已批准补充 Dockerfile 与 scripts/milvus_switch_check.py，其他范围沿原卡：app/main.py、app/api/、frontend/src/、tests/、README、docs/、tasks.yaml。Vite 现有 /api 前缀代理天然覆盖 /api/v1，无需修改范围外配置。

## 目标与现状

唯一业务 API 挂载改为 /api/v1，不保留 /api 别名；所有现有调用方、OpenAPI 与 README 一致。当前 app.main 仍挂 /api；前端 HTTP、SSE 和独立导出 fetch 都有前缀；首次改密身份白名单为旧绝对路径；Docker 探针与 Milvus 切换脚本也使用旧路径。生产编排已统一继承镜像探针，无需再修改生产文件。

## 方案与非目标

1. 先写 OpenAPI 全部业务路径 /api/v1、旧路径 404、正常版本健康路由、首次改密白名单仍有效及 SPA 不吞 API 404 的契约失败测试，再最小迁移挂载。
2. 保留 `/` 为既有 UI/服务信息入口、/docs、/redoc 和静态资源入口；这些不是第二套业务 API。服务信息不列入 OpenAPI，health 链接更新；OpenAPI paths 全为 /api/v1。前端托管时 `/api`、旧 /api/* 及未知 /api/v1/* 仍返回 JSON 404，不回 index.html。
3. 同步 app/api 首次改密白名单和当前路由说明。前端 HTTP、SSE、独立导出全部使用新前缀，以实际 fetch 断言验证，保留刷新/重试与错误语义。只修改后端业务路径，不改 @/api 模块导入或外部供应商 API URL。
4. 存量测试与内嵌子进程脚本中的本平台调用更新；新增测试中的旧路径拒绝断言保持旧路径，禁止机械变成新路由成功断言。实际 Milvus 脚本、Docker HEALTHCHECK 同步；README/当前运行手册与 Swagger 更新，历史计划/审查中的当时证据不追溯改写。

不改业务规则、角色、身份、模型、检索、SSE 事件协议或工作流，不保留旧 API 作为兼容副本。不顺手调整 Vite、外部服务 URL、历史版本报告或其他任务功能。

## 验收与风险

全部注册业务 API 及 OpenAPI paths 为 /api/v1；旧路径不提供别名/重定向；README 端点表的方法与路径存在于当前 OpenAPI；三个前端 fetch 入口路径正确；首次登录可 /me/改密但业务仍拒绝；SSR/真实 SPA 路由不会掩盖 API 404。新增确定性测试先红后绿，审查全部存量调用方。

风险 L2：客户端必须同步迁移。回退时前后端/脚本/镜像探针及文档一起回退，不改数据库数据。执行相关 pytest、全库 Ruff/mypy、前端四门，最终批次再执行不带筛选的全量 pytest，并绑定最终输入；Docker/进程相关证据按 Linux 与最终提交 Ubuntu CI 门禁保留。独立审查、实际说明和未验证项落盘。任何必要门禁未通过，保持 in_review，不能宣称发布或整批完成。
