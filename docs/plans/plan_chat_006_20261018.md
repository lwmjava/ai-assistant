## 现状与方案

现有ChatService、非流式和流式接口均可受控生成，Message有独立ID与时间。checkpoint与工具收据以真实用户消息ID绑定，不能复用已完成请求冒充新生成。当前没有重新生成入口或按钮。

1. 新POST /api/v1/chat/conversations/{conversation_id}/messages/{message_id}/regenerate，无客户端文本覆盖，复用ChatResponse。API仅做身份依赖、调用Service、错误映射。Service校验可访问会话、实际末条消息为指定助手，取其前最近用户消息；无原问题/目标过期拒绝。权限遵循现有会话写入边界，同租户系统管理员仍按已有可访问范围处理，不复用原owner执行身份。
2. 作为独立新轮次复制原始用户文本和已保存附件，重做附件安全、视觉能力及预算校验，调用现有chat链路。新增用户/助手消息，保留完整原问答；消息配额正常扣计。新用户消息ID隔离checkpoint与工具收据，无模型或迁移改动。
3. 重新生成显式绕过LLM回复缓存，检索缓存保持。默认chat和stream共享现有进程内会话写入互斥；重新生成锁从最新目标复查持有至生成结束，同目标并发/陈旧请求拒绝。多进程幂等不在本卡范围。
4. 开始及异步生成后持久化前复核真实主体、租户、角色/token_version，撤权或停用后不保存成功新助手。异常、预算/远端失败不删除或覆盖旧消息；沿用现有失败请求持久化语义，可保留本次新用户消息/失败记录，不伪称全链事务回滚。错误不暴露内部堆栈。
5. 页面只对末条助手展示重新生成；生成期间禁用发送/重复点击，保留旧气泡。明确说明保留原问答、新轮次及配额语义。成功刷新服务器消息，新ID/时间区分；失败提示并刷新实际记录。会话切换后不把旧请求结果写入新会话。

## 契约对账与失败边界

| 要求/边界 | 断言及证据计划 |
|---|---|
| 最后助手重新生成 | 真实API+隔离测试库+合成provider，经新Session回查新回复ID和原回复原文；E2 |
| 失败保留原回复 | provider失败、输出拒绝/撤权、附件损坏时，原消息内容/ID与原checkpoint不变；E2 |
| 数值边界 | 非法/超长ID不造成500或新消息；零/耗尽配额拒绝且不调用模型；本卡无向量计算，NaN/Inf算法不适用 |
| 权限/租户 | viewer403、他人会话/跨租户404、inactive/token变更拒绝；无消息写入/模型调用 |
| 身份/绑定 | 消息属于其他会话、非尾助手、孤儿助手、已新增用户请求冲突；不相信客户端prompt/attachments |
| 附件与预算 | 历史文档/图片按当前安全能力复检，损坏附件拒绝，不进知识库；完整附件进入真实合成provider请求 |
| 幂等/并发 | 同目标并发和旧目标再次提交409；与普通chat/stream互斥，异常后锁释放；不声明跨进程幂等 |
| 模型/缓存 | 明确绕过LLM回复缓存；真实管线+合成provider按调用用途记录，不以总次数掩盖回归 |
| 页面失败/切换 | 旧气泡始终可见；刷新保留新回复；失败有提示；会话切换不串会话；窄屏与只读隐藏/禁用 |
