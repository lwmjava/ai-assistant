## 目标、现状与方案

当前请求只有文本；Message 无附件关联字段；ChatMessage.content 为字符串，模型预算和阶段消息也只处理字符串。目标是输入框粘贴/选择 PNG、JPG/JPEG，选择指定文档和源码，每文件最多 1048576 字节，随当前用户消息到模型，不调用知识库摄取或建索引。

使用 ChatRequest 中显式附件输入（文件名、base64 内容）兼容现有 JSON/SSE 入口；服务先逐文件校验扩展名、严格 base64、解码后字节数与图片签名，再进入任何用户消息写入或模型调用。任一非法文件使本次请求失败且无新增消息/附件/知识库副作用，前端展示对应文件错误供移除。文件名只作为显示数据，不参与文件路径。文档复用已有解析服务，源码按 UTF-8 解析；旧 Office 只使用已有转换能力，无新依赖或 shell 字符串拼接。临时解析资源及时回收，解析失败返回固定脱敏错误。

白名单精确为：png/jpg/jpeg；md/doc/docx/xls/xlsx/ppt/pptx/pdf；go/py/css/html/htm/java/js/json/xml/yaml/yml/c/h/cpp/cc/cxx/hpp/vue/ts。不支持 tsx/jsx 或其他扩展，不另设文件个数上限。总模型上下文仍受已有预算约束，预算失败不能静默丢附件或只交文件名。

用户 Message 增加可空 JSON 文本 attachments 字段，保存经过校验的附件信息及当前消息模型所需内容，历史用户数据默认为空。图片以 data URL 多模态内容到当前消息所用模型；文档/源码正文以不可信内容围栏注入，不能提升为系统指令。图片不转成文字占位来冒充已交模型。相关阶段构造、缓存键、计数与预算需支持多模态；未核对视觉/计数能力必须明确拒绝并保留未验收项，不放宽预算护栏。附件关联与对话同样校验主体/租户；不提供可越权下载的新全局 ID。后续历史展示附件摘要，避免把二进制内容当正文渲染或写进审计/Trace。
