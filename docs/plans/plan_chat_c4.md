## 目标

1. 流式生成时可以停下。已吐出的文字留下，并标成已停止。刷新后仍在，且不再追加。
2. 连接中断后，能把服务端已经写完的助手回复拉回来。还没写完的，不能显示成已完成。
3. 能给自己的会话改名和删除。删除前确认。不能删别人的会话。
4. 只读成员可以看会话，不能发送。输入框禁用，并写明原因。
5. 用测试写明：成员看不到别的租户、看不到同租户的其他人；系统管理员只看得到当前租户里的会话。

## 现状

- 对话页已有「停止生成」。它只中止浏览器的 fetch。服务端仍会把整段回复在结束时写入，没有已停止标记。刷新后看到的是完整回复，验收不成立。
- 消息表没有状态列。`create_all` 不会给已有表加列。把「已停止」写进正文会污染下一轮上下文，也分不清这是回复还是标记。
- 流式事件不回传会话编号。新建会话时，断线后页面不知道向哪一条去拉。
- 用户消息和助手消息都在生成结束时才写入。中途失败会把问题也丢掉。
- 删除接口、确认框和审计已经有了。任务里「控制台没有删除」已过时。缺的是重命名。
- 删除和打开用的是同一条归属规则：本人，或当前租户里的系统管理员。成员删别人的会话已经是 404。
- `viewer` 调用发送接口时，`require_permission` 已经返回 403。缺的是页面禁用。`system_viewer` 同样没有 `conversations.write`。
- 列表已经按当前租户过滤；非系统管理员再按本人过滤。缺的是本批要求的回归说明。

## 已定的取舍

停止和断线在服务端看起来都是「响应被关掉」。本批不另建后台运行，也不做 Last-Event-ID 重连。连接一旦断开，这次生成就停在服务层已经收到的 token 上，写入一条助手消息，状态为 `stopped`。正文只用已经收集到的 token，不用管线里可能已经算完的整段 `state.answer`，否则停止后仍会把后文写进去。

用户点停止时，页面立刻标「已停止」，不弹生成失败。网络中断时，页面写「连接中断」，并给出「加载完整回复」。加载结果按库里的状态显示：

- 助手消息状态是 `complete`：这是完整回复。
- 状态是 `stopped`：展示已保存的文字，并说明这不是完整回复。
- 最后一条仍是用户消息：回复尚未完成，不能当作完整回复。

一次性模式没有逐字输出。停止只是放弃等待。若服务端已经正常写完，加载到的是完整回复，不标已停止。若还没写完，按上面的「尚未完成」处理，不编造半截回复。

第一条流式事件是会话编号，并在此之前先写入用户消息。这样断线后知道向哪拉，问题也不会丢。安全拦截发生在创建会话和写消息之前，拦截失败仍不落库。

完整回复在发出 `done` 之前写入，避免页面刷新时库里还没有这句。停止时在生成器结束处写入，只写一次。已经写成 `complete` 的，不再改成 `stopped`。

重命名和删除沿用现有归属：本人可以改、可以删；同一租户的系统管理员也可以（删除本来就能，且有审计）。其他角色删或改别人的会话返回 404，不暴露会话是否存在。不把租户管理员提升为能管理他人会话。空标题和超过 80 字的标题拒绝。

只读判断不再在服务里写第二套。后端继续用现有权限。页面在角色没有 `conversations.write` 时禁用输入。角色是 `viewer` 时文案为「只读成员不可发送消息」。`system_viewer` 用「当前角色不能发送消息」。

消息状态列必须落在模型和启动补齐里。这两处不在任务允许路径中，原因和当初补 `sources` 列相同：不改的话，已有数据库下一句插入就会失败。新库由模型建出该列；已有库由迁移和启动补齐，默认 `complete`，旧回复不显示已停止。

## 方案

### CHAT-001 停止生成

- `messages.status`：`complete` 或 `stopped`，默认 `complete`。
- `chat_stream`：安全检查通过后解析会话、先做记忆，再写入用户消息，再产出 `conversation` 事件。之后逐事件收集 token。正常结束时，在产出 `done` 之前把助手消息写成 `complete`。生成器因取消或关闭而停下时，把已收集的 token 写成 `stopped`。没有 token 时也写一条空的已停止消息，避免刷新后仍像还在生成。
- 不改管线内部。取消只发生在服务层两次产出之间。模型当前这一小段可能还会返回，但不会再往已停止的消息上追加，也不会再写第二条完整回复。
- 页面停止后保留已看到的文字并标「已停止」。主动停止不走「生成失败」。

### CHAT-002 断线后查看完整回复

- 不自动重连，不做多端同步，不做运行日志。
- 非用户主动的流错误：保留已看到的文字，提示「连接中断」，按钮为「加载完整回复」。按上一节的三种库状态显示，不把未完成标成成功。
- 服务端在 CHAT-001 已把能留下的内容写好。本任务只消费已有的会话详情，不改服务层的生成过程。

### CHAT-003 会话重命名与删除

- `PATCH /api/chat/conversations/{id}`，请求体只有 `title`。去掉首尾空白后为空，返回 422「标题不能为空」。超过 80 字，返回 422「标题不能超过 80 个字」。无权或不存在，返回 404「会话不存在或无权访问」。
- 删除保持现有接口和确认框。不重做删除。
- 当前会话标题旁可以改名。列表里的删除按钮保持原样。

### CHAT-004 只读成员不能发送

- `viewer` 的 `POST /api/chat` 与 `POST /api/chat/stream` 保持 403。
- 没有发送权限时禁用输入框和发送。`viewer` 看到「只读成员不可发送消息」。

### CHAT-005 会话隔离回归

- 不改列表过滤，不改知识库跨租户行为。
- 用例写明每个身份能看到的范围：成员只能看见自己在当前租户的会话；系统管理员能看见当前租户里的全部会话，看不见其他租户。

## 非目标

不做重新生成，不做对话分支，不做会话搜索。不保证断线后自动重连，不做多端同步，不把生成挪到请求之外的后台任务。不改检索、不改 `.env`、不改知识库权限。不收紧系统管理员在当前租户里已有的删除能力。不新增第二套发送权限判断。

## 验收

- 流式停止后，库里的助手消息只有停止前的文字，状态为 `stopped`，没有后文。刷新后能看到这些文字和已停止标记。
- 已完成的回复可以按会话详情拉回。只有用户消息、或状态为 `stopped` 时，不显示成已完成。
- 改名后列表标题更新。删除后本人再打开得到 404。成员删除或重命名他人会话得到 404。
- `viewer` 发送返回 403，页面不能发出。`member` 仍可发送。
- 隔离用例通过，并在用例说明里写明范围。

- 状态列不在允许路径里。已在上面单独写出，并说明为什么不能把标记塞进正文。

本轮没有待改的设计问题。

### 第二轮：企业里的会话产品会不会这样用

- 生成中可以停下，停住的文字还在，并标明没有生成完。这是会话产品的基本行为。
- 断线后不假装已经自动重连，也不把半截回复说成完整答案。能拉到的完整回复就展示，拉不到就说明还没完成。后台继续跑完再重连是下一批的事，本批交付计划已明确不做。
- 一次性等待没有中间文字。停止只表示不再等。若服务端其实写完了，加载到的就是完整回复，不误标已停止。
- 人管理自己的会话；当前租户的系统管理员仍可处理该租户里的会话，并留下审计。成员不能动别人的。这和现有管理台一致，不额外放开租户管理员。
- 只读角色看得到输入框是禁用的，并说明原因，而不是发出去再失败。

本轮没有待改的设计问题。

### 第三轮：失败时会不会说错，以及能不能被测试抓住

- 停止落库只用已收集 token，避免把未展示的全文写进去。
- 已写成完成的消息不会在连接随后断开时被改成已停止。
- 安全拦截仍发生在写消息之前。
- 空的已停止消息会标成没有生成内容，不会显示成一条成功回复。
- 下一轮上下文跳过空正文，避免把空的停止消息送给模型。有文字的停止消息仍保留，用户可以接着问。
- 停止用服务层关闭生成器来验证，不依赖浏览器点击时机。隔离、改名、删除和 viewer 用接口验证。页面再用浏览器核对停止标记、改名、删除确认和只读禁用。

本轮没有待改的设计问题。

三轮均未发现问题，按本文件实现。

## 实现说明

流式生成可以停下。停下时，已经出现在页面上的文字写入助手消息，状态为 `stopped`，刷新后仍带「已停止」。没有再追加未展示的后文。连接中断时页面提示「连接中断」，并可以加载完整回复：库里已写完的按完整回复显示；状态是已停止的会说明这不是完整回复；还没有助手消息时说明回复尚未完成。
