> 地位：`docs/product/项目产品需求方案.md` §5.12 的详细补充。功能列为后续待开发，不进入当前交付。
> 状态：详细方案待评审。尚未写入 `tasks.yaml`，评审通过前不拆任务。
> 日期：2026-10-01
> 评审：阶段 1 的失败实例、超时和授权仍受 `docs/reviews/2026-10-01-plan_chat_feedback评审.md` 约束。该评审否决的是上一版失败反馈方案，不表示本版已通过。
> 需求：§5.12 只登记范围和进入条件。§4.5.2 的「反馈」仍是页面六态。§5.7 的进化和 §5.10 的训练导出保持原优先级；本文件说明用户反馈如何成为它们的语料来源之一。

按阶段交付。前一阶段的数据契约稳定后才做下一阶段。复审通过前不拆卡。

## 要解决的问题

用户今天不能把一次失败或一次成功回复的判断交回来。系统因此缺少一类由用户给出的信号。这类信号以后要和对话原文分开存放，成为自我修复和自我进化的语料来源之一。

自我修复看的是失败和「无用」：哪一次尝试失败、哪条回复被判定没用、当时用了哪个技能和模型。自我进化看的是成对信号：同一类问题上什么回复有用、什么回复无用。两条都只产生可追溯、可删除、已脱敏的样本。它们不直接改 Prompt、技能或模型。

## 已核对的现状

核对日期：2026-10-01。

- 没有反馈表、点赞、点踩或评分。
- 流式失败会发送「生成失败，请稍后重试」，不附带异常原文。非流式在会话和用户消息已经落库后失败时，错误响应不返回 `conversation_id`。见 `app/api/routes/chat.py`、`app/services/chat_service.py`。
- 生成器取消一律按 `stopped` 保存已收集文本；没有 token 时仍可能写入空的助手消息。服务端分不清用户停止和网络断开。页面没有无输出等待上限。`LLM_TIMEOUT` 默认 60 秒。
- 系统管理员用 `ChatService._can_access` 可以读取同一租户里其他用户的会话。
- `InputFilter` 与 `LogSanitizer` 已能处理证件号、手机、银行卡、邮箱、IP、密钥字段和 JWT。它们不会自动作用到新的业务表。
- 反思在 `EVOLUTION_ENABLED` 且 `EVOLUTION_REFLECT_ENABLED` 时，于成功回复后异步运行。`Reflector.reflect` 只把结果写入日志，不改技能、不改 Prompt、不落库。见 `app/evolution/reflector.py`、`ChatService._maybe_reflect`。
- 夜间蒸馏 `Distiller._fetch_recent_conversations` 按更新时间取最近会话，没有租户条件，分析文本包含消息原文。见 `app/evolution/distiller.py`。
- 产品要求训练在外部进行。租户管理员导出本租户、脱敏后的 Alpaca 或 ShareGPT 是 §5.10 的目标，当前实现仍要按代码事实核对，本规划不把它写成已完成。

## 范围

四个阶段：

| 阶段 | 交付 | 语料角色 |
|---|---|---|
| 1 | 失败尝试与失败反馈 | 失败样本的原始记录 |
| 2 | 成功回复的有用 / 无用 | 偏好样本的原始记录 |
| 3 | 按租户生成语料快照 | 修复与进化的读取入口 |
| 4 | 管理端查看、导出审计、删除传播 | 企业上线的运营与合规闭环 |

星级不作为信号。五分没有稳定的修复动作，也不能和「有用 / 无用」对齐。用户用两个动作表达判断，再用固定原因补充。自由评论只作补充，不单独当标签。

## 非目标

- 不把反馈做成工单，不回复用户，不把评论派给某个人。
- 不在本规划内自动修改技能、Prompt、工具或模型参数。
- 不把评论或语料原文送进现有 `distill_recent`。那条路径没有租户边界。
- 不在产品内训练模型。对外导出只准备已脱敏样本。
- 不新增用户停止专用接口。服务端继续不区分停止和断线。
- 不改用户页和租户页的排版。
- 不做跨租户汇总榜，不做公开的质量排行。

## 企业级约束

这些规则四个阶段都要遵守。

身份与租户：

- 提交只允许记录所有者。判断是 `user_id == current_user.id`，不调用 `_can_access`。系统管理员不能替同租户其他人提交。
- 查看分成两条路径。用户只看自己的提交状态。系统管理员查看全量反馈和语料时必须带租户过滤能力，且不靠会话读取权限。租户管理员只看本租户。
- 对不上的提交返回 404，正文为「记录不存在」，不透露记录属于谁。

数据：

- 评论和进入语料的摘录，保存前依次经过 `InputFilter` 和 `LogSanitizer`。库里和响应里只有处理后的文本。
- 日志和异常只记反馈 ID、`attempt_id`、信号类型。不记评论，也不记处理后的评论。
- 用户评论、用户问题和助手回复都是不可信数据。以后送给反思或蒸馏时必须包在不可信围栏里，不能当成系统指令。
- 反馈原表默认保留 180 天，或直到本人删除、管理员删除、租户合规删除，以先到者为准。90 天是审计日志的保留目标，不套用在这条业务数据上。
- 到期清理的定时任务不在阶段 1 实现。保留规则在本规划写死，阶段 4 把删除和导出做完后，清理任务是否另立由拆卡时决定。
- 删除是合规动作。原记录删除后，语料快照标记为撤销，之后的蒸馏、导出和修复样本都跳过它。已经下载到系统外的文件收不回来，导出审计要记下时间和范围。

完整性：

- 失败反馈的唯一约束是 `(user_id, attempt_id)`。冲突时返回第一行，不改评论。
- 成功评价的唯一约束是 `(user_id, assistant_message_id)`。允许用户改一次判断，语料使用最新一条，旧值留在变更时间里。
- 并发插入靠数据库唯一约束，不靠先查后写。

查询：

- 列表默认 `created_at` 降序，相同时间再按 `id` 降序。
- `page` 默认 1，最小 1。`page_size` 默认 20，最大 50。超过上限返回 422。
- 响应使用固定 Schema，不含会话标题、消息全文、堆栈、技能正文和内部异常。

## 阶段 1：失败反馈

目标是让用户对某一次失败尝试提交反馈，并让这次失败在刷新后仍能识别。

### 失败实例

客户端在发送前生成 32 位十六进制 `attempt_id`。`POST /api/chat` 和 `POST /api/chat/stream` 都必须带上。缺省或格式不对时返回 400，不创建会话。

空消息校验通过后写入 `chat_attempts`：

| 字段 | 含义 |
|---|---|
| `id` | `attempt_id`，主键 |
| `tenant_id`、`user_id` | 当前用户 |
| `conversation_id`、`user_message_id` | 落库后补上，此前为空 |
| `outcome` | `pending`、`success`、`api_error`、`no_response`、`stopped` |
| `created_at` | 创建时间 |

不保存用户消息正文、模型原文或异常文本。同一 `attempt_id` 再进入对话接口时，属于当前用户且仍为 `pending` 则沿用；属于别人或已是终态则返回 409。终态只能从 `pending` 进入一次。

### 结束方式

无响应由服务端计时，不由页面断开连接。断开在服务端仍是生成器取消，只能进入 `stopped`。

| 页面看到的情况 | 谁判定 | `outcome` | 助手消息 | 能否做失败反馈 |
|---|---|---|---|---|
| 用户点停止 | 页面中止流 | `stopped` | 已有 token 时写 `stopped`；没有 token 则不写 | 否 |
| 网络中断 | 连接断开 | `stopped` | 与用户停止相同 | 否 |
| 无输出超时 | 服务端，默认 90 秒 | `no_response` | 不写 | 能 |
| 接口或模型报错、安全拒绝 | 服务端 | `api_error` | 不写空助手消息 | 能 |
| 正常结束 | 服务端 | `success` | `complete` | 否，留给阶段 2 |

计时从用户消息落库开始，出现 token、`done` 或其它终态就取消。90 秒晚于默认 `LLM_TIMEOUT` 60 秒。到点只发错误事件，不走 `stopped` 分支。

流式错误事件和非流式失败 JSON 使用同一组字段：`code` 为 `api_error` 或 `no_response`，`data` 或 `detail` 为固定安全文案，外加 `attempt_id`、`conversation_id`、`user_message_id`。后两个还没有时为 `null`。不返回异常原文。安全拒绝保持原状态码和拒绝原因，并带上 `attempt_id`。

页面只在收到这两种 `code` 时显示「反馈问题」。不用本地定时器中止请求。用户停止和连接中断维持现有文案，不出现失败反馈入口。

### 失败反馈表

`chat_feedbacks`：`id`、`tenant_id`、`user_id`、`attempt_id`、`conversation_id`、`kind`、`comment`、`created_at`。`kind` 必须与尝试的 `outcome` 一致，只允许 `api_error` 或 `no_response`。`comment` 可空，有内容时为脱敏后的 1–500 字。

`POST /api/chat/feedback` 要求尝试属于当前用户；尝试上若已有会话，会话的 `user_id` 也必须是当前用户。`kind` 不匹配则 422。完整性冲突时返回已有行。

`DELETE /api/chat/feedback/{id}` 允许提交者本人和系统管理员。其它角色 404。

对话详情在用户消息上增加 `attempt_id`、`attempt_outcome`、`feedback_submitted`。只返回是否已提交，不返回评论文本。刷新后，未提交的失败轮次仍显示入口，已提交显示「已反馈」。评论提交失败时，输入框保留草稿。

### 本阶段不做

成功回复上的有用 / 无用、语料快照、管理端页面、到期清理任务。读取接口在本阶段就要有，页面放到阶段 4。

### 验收

- 同一会话两次 `api_error` 可以各有一条反馈。
- 同一 `attempt_id` 并发提交只保留第一行。
- 非流式在用户消息已落库后失败时，错误 JSON 含尝试、会话和用户消息标识，不含异常原文。
- 系统管理员对同租户他人的尝试提交，得到 404。
- 无输出 90 秒的 `outcome` 为 `no_response`，没有新的空 `stopped` 助手消息。
- 用户停止且已有 token 时不能提交失败反馈。没有 token 的取消不新增助手消息。
- 评论中的手机号、邮箱和 token 形态在库和响应里已替换。
- 浏览器里失败后可提交；刷新后「已反馈」仍在；提交失败时草稿还在。停止和断线没有入口。

## 阶段 2：成功回复评价

目标是让用户对一条已经完成的助手回复标记有用或无用。这是偏好语料的来源，和失败反馈分开存。

只对 `outcome=success` 且助手消息 `status=complete` 的回复开放。`stopped`、失败轮次和没有助手消息的轮次不显示评价。

页面在该条回复下提供「有用」和「无用」。选择「无用」时可选一个原因：`off_topic`、`factual`、`format`、`citation`、`incomplete`、`other`。两个动作都可以再写 1–500 字评论，可空。原因和评论都不是必填；「无用」没有原因时仍然保存，语料里原因记为 `unspecified`。

表 `message_ratings`：`id`、`tenant_id`、`user_id`、`conversation_id`、`assistant_message_id`、`attempt_id`、`rating`（`up` 或 `down`）、`reason_code`、`comment`、`created_at`、`updated_at`。唯一约束 `(user_id, assistant_message_id)`。再次提交更新 `rating`、`reason_code`、`comment` 和 `updated_at`。

授权与阶段 1 相同：助手消息所属会话的 `user_id` 必须是当前用户。系统管理员不能替别人评价。删除沿用本人或系统管理员。

对话详情只返回当前用户的 `rating` 和 `feedback_submitted` 等价状态，这里字段名为 `rating`，取 `up`、`down` 或空。不在详情里返回评论。

### 本阶段不做

不生成语料快照，不调用反思或蒸馏，不做星级，不在失败气泡上放有用 / 无用。

### 验收

- 完成回复可以标记、修改和删除。刷新后仍是最后一次选择。
- 失败、停止和中断轮次没有这两个按钮。
- 另一名用户、包括同租户系统管理员，不能改这条评价。
- 并发下同一用户和同一助手消息只有一行。

## 阶段 3：语料快照

目标是把阶段 1 和阶段 2 的记录变成进化模块可以读取的样本。快照是派生物，不是第二份对话库。

生成条件同时满足才进入快照：

- 失败反馈对应的尝试仍是 `api_error` 或 `no_response`，或评价仍是 `up` / `down`。
- 原记录没有被删除。
- 租户和用户仍有效。停用用户的记录不进入新快照。

表 `evolution_corpus_items`：

| 字段 | 含义 |
|---|---|
| `id` | 快照主键 |
| `corpus_version` | 固定为 `fb-corpus-0.1` |
| `tenant_id`、`user_id` | 来源用户，不跨租户合并 |
| `source` | `failure_feedback` 或 `message_rating` |
| `signal` | `api_error`、`no_response`、`up`、`down` |
| `reason_code` | 评价原因；失败样本为空 |
| `attempt_id`、`conversation_id`、`user_message_id`、`assistant_message_id` | 可空，按来源填写 |
| `model`、`skill_names` | 当时的模型名和技能名；没有则为空 |
| `comment` | 已脱敏评论 |
| `user_excerpt`、`assistant_excerpt` | 各最多 500 字的已脱敏摘录；失败且没有助手消息时助手摘录为空 |
| `revoked_at` | 原记录删除或到期后填写；未撤销为空 |
| `created_at` | 快照时间 |

唯一来源是 `(source, attempt_id)` 或 `(source, assistant_message_id)`，避免一次判断生成多行。原记录更新后，下一次生成覆盖未撤销快照的信号、原因、评论和摘录。

生成由显式任务执行，可以手动触发，也可以日后接到进化调度。本阶段不把它挂进现有 `_tick`。读取接口按租户过滤。系统管理员必须指定 `tenant_id` 才能读取，避免一次拉出全部租户。

送给反思或蒸馏的文本只来自未撤销快照，并且整段放进不可信围栏。不调用今天的 `distill_recent`，也不把快照写进 `Reflector` 的对话原文。本阶段只保证快照能按租户查出、字段完整、撤销后查不到。真正让蒸馏消费这批样本，留在阶段 3 的后续任务里单独立项，以免和现有无租户蒸馏绑在一起。

语料用途：

- 自我修复：`api_error`、`no_response` 和 `down` 是观察回归样本。按 `skill_names`、`model`、`reason_code` 聚合。它们不是 Gold 标注，不能单独当作评测通过条件。
- 自我进化：同一租户内的 `up` 与 `down` 作为偏好观察。蒸馏可以据此产生建议。建议仍然只是建议。

### 本阶段不做

不改技能清单，不改 Prompt，不启动内置训练，不把快照导出成文件。

### 验收

- 一条失败反馈和一条无用评价各生成一条未撤销快照，摘录和评论已脱敏。
- 删除原记录后，对应快照带 `revoked_at`，按租户查询默认不返回。
- 不指定租户时，系统管理员的语料查询被拒绝。
- 快照内容不出现在现有蒸馏分析文本里。用测试替身调用一次 `distill_recent` 的取数，确认它仍不读取 `evolution_corpus_items`。

## 阶段 4：运营与合规闭环

目标是让授权角色看见、导出和删除这些数据，并留下审计。

管理端增加只读列表，沿用技能页那种全宽表格，不沿用用户页和租户页的窄栏布局。筛选项与阶段 1 的读取契约相同，并增加 `signal`、`reason_code`。列表展示信号、原因、脱敏评论、模型和技能名，不展示摘录全文；详情里再展示摘录。

导出：

- 租户管理员导出本租户未撤销语料。系统管理员导出时必须指定一个租户。
- 格式为 JSONL，每行一个 `fb-corpus-0.1` 对象。不提供 Alpaca 或 ShareGPT，避免和 §5.10 的对话导出混成一种文件。
- 导出写入审计：谁、何时、租户、时间范围、条数。审计详情不包含评论和摘录。
- 导出前再次脱敏。撤销记录不出现。

删除：

- 本人删除自己的失败反馈或评价。系统管理员可按 ID 删除。租户管理员可删除本租户记录。
- 删除原记录的同时撤销快照。
- 会话被用户删除时，挂在该会话上的反馈、评价和快照一并撤销。这是阶段 4 才接通的级联，阶段 1 和 2 的删除接口只处理反馈或评价自身。

到期清理若在拆卡时单独立项，只撤销到期原记录及其快照，并写一条不含正文的审计。

### 验收

- 租户管理员看不到其它租户的行，也不能导出其它租户。
- 导出文件不含撤销记录，审计里没有评论正文。
- 删除一条评价后，列表、对话页状态和语料查询都不再把它当作有效样本。
- 浏览器能按信号和原因过滤到刚提交的记录。

## 与现有进化模块的边界

阶段 3 之后，反馈语料是修复和进化的输入之一，与对话原文、质量门分数并列，不替代它们。

现有反思继续只分析当次对话并写日志。现有蒸馏继续按它今天的取数运行，直到另有任务给它加上租户边界，并明确把未撤销语料当作附加输入。那一项不在本规划的四个阶段里提前做，避免把一份没有租户过滤的分析变成跨租户进化。

用户评论不能触发技能更新。即便以后蒸馏读到「无用」和原因，产出的仍是待人工确认的建议。

## 复审前不拆卡
