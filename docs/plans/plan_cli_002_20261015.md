# 初始化 JWT 配置实施计划

日期：2026-10-15。任务：CLI-002。原始契约：tasks.yaml；前置 CLI-001 当前为 done，已有迁移/创建管理员回归已在本批通过。批次授权和 init 执行边界见 `plan_platform_batch_20261015.md`。

## 目标、现状与方案

提供 `ai-assistant init` / `python -m app.cli init`，生成随机 JWT_SECRET_KEY 并写配置，默认不覆盖已有文件；非开发环境跳过 init 且使用默认/空白密钥时拒绝启动并提供一条解法。

事实：当前 CLI 仅 migrate/admin，且模块顶层 import Settings/认证服务；现有 validate_jwt_secret 已拒绝非 development 的精确默认值，不能把该已有行为写成本卡新实现。空白密钥尚未拒绝；lifespan 在数据库建表/账号引导之后才校验。Settings 默认固定读取源码根 .env，不随 cwd 改变。产品写 JWT_SECRET，真实键为 JWT_SECRET_KEY，输出沿真实配置键，不引入别名。

1. CLI 先用 argparse 分派；init 路径仅用标准库，不导入 Settings/数据库/认证服务，不读取工作区 .env。原 migrate/admin 延迟 import，原参数兼容。
2. init 用 secrets.token_urlsafe(48) 生成密钥，默认写当前目录 .env；README 明确从项目根运行。支持 --env-file 指定新输出文件；该参数仅决定输出，不承诺改变应用默认加载路径。测试只在新临时目录运行，或将临时文件值显式注入隔离启动进程。
3. 独占创建，拒绝已有文件、目录、符号链接，保持原字节不变；创建用 0600 意图，Linux 权限语义另验。失败固定脱敏提示，写入失败清理仅本次新建文件，不覆盖旧文件、不留下成功假象。stdout/stderr 不含密钥内容。
4. 保留既有非开发默认密钥拒绝，补空串/空白拒绝；开发语义保持兼容。安全校验前移至建表/账号引导之前，失败时不写业务数据。日志/异常包含 ai-assistant init 或环境变量设置解法。未启动的进程不能同时提供 /health，不另建诊断服务器。

## 非目标、范围与风险

不改已登录会话语义，不执行工作区 init，不读取/覆盖工作区 .env，不实际更换用户密钥，不更换密码、数据库、依赖或部署架构。只改 app/cli.py、必要 app/core/ 初始化辅助和 security.py、app/main.py、tests/、README、tasks.yaml、已批准 docs/plans 与 docs/reviews 证据。风险 L2：配置生成和启动拒绝；只在隔离目录/库实跑，不做生产操作。

## 验收

从原始卡验收映射：真实 CLI 生成配置→随机非默认值、无泄漏、数据库未创建；重复/已有文件/目录/链接拒绝且原内容不变；注入写失败无半成品；init/init --help 不导入 Settings；非开发默认/空白密钥在真实 lifespan 拒绝且数据库无表；临时生成值显式注入后启动正常；原 migrate/admin 测试保持。新增确定性用例先红再绿。

运行指定 Python 下相关 pytest、Ruff 与 mypy；公共启动路径触发最终不带筛选的全量 pytest，待批次最终输入稳定执行，未通过不关闭。文件系统/进程行为还需 Linux 与同最终提交 Ubuntu Backend CI；Windows 不能替代。前端无源/契约变更则不适用，理由写入实际说明。独立审查必须直接读取卡与最终 diff；候选指纹、命令/退出码和未验证项落盘。

回滚仅撤回本卡代码；不删除已由用户创建的配置，不重写既有会话或真实密钥。遇新越界、重要数据覆盖或无法隔离基线失败立即停止受影响操作。
