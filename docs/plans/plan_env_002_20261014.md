# ENV-002 实施计划

## 目标、现状和授权

原始契约为 tasks.yaml ENV-002：示例不再提供可直接登录的口令，源码默认密码仍为空，用户名与密码同时非空才引导管理员。当前 .env.example 有固定非空密码；README 的 CLI 示例也有可执行的固定密码文字。用户已明确授权实施，并批准 docs/plans、docs/reviews、docs/evaluations 扩展。基线 HEAD 为 80629c4cd5ce00d59b26116c7419edce00e6a113，分支 codex/cov-001；COV-001、ENV-001 的已有未提交文件保留。

## 方案与非目标

将 INITIAL_ADMIN_PASSWORD 赋值留空（不使用非空尖括号占位）；README 说明任一项为空均跳过引导，CLI 示例改为由部署者先通过秘密管理注入密码后执行命令，不提供密码字面量。保持181个配置键、源码默认值及引导实现不变。不读取真实 .env，不创建真实账号，不改业务、依赖、CI，不提交或推送。

## 验收与失败边界

用实际 Settings 在隔离环境加载模板；AST 提取原始模型、bcrypt 函数和 ensure_initial_admin，在隔离 SQLite 执行真实持久化链，避免导入全局 Settings 读取 .env。生成临时测试密码仅在内存中，报告不输出其值。

| 原始要求/边界 | 操作与期望 | 证据 |
|---|---|---|
| 示例无可用密码、默认仍空 | 实际 Settings 加载模板与源码默认，两者密码为空；当前模板应先失败再通过 | E2 配置加载 |
| 双项非空才创建 | 四种空/非空组合，新Session核对用户、租户、成员关系；成功密码经真实bcrypt验证 | E2 SQLite入口 |
| 身份与绑定 | 只用隔离Settings/SQLite，无真实.env、业务数据库读取 | E2 路径和源码指纹 |
| 回滚与幂等 | 同配置重入只保留一个管理员；已有用户时不创建新管理员 | E2 新Session读取 |
| 权限与租户 | 成功为system_admin/default，成员绑定同一用户与租户；缺任一输入时零新行 | E2 持久化 |
| 数值、远端、超时 | 本卡只改变文本配置，不改变数值处理、远端调用或超时；不适用，保留原实现 | 原始契约限定 |

前置 ENV-001 当前技术审查通过但业务验收未委托，保持 in_review。本卡复验181键加载；密码值改变会使前置旧模板指纹成为历史证据，不改写旧报告冒充新证据。开展独立计划审查、入口反例审查及不同身份的最终审核。模板行为变化需 ruff、mypy 和相关隔离回归；未改公共代码，不触发全量pytest或前端门禁。最终人工业务验收未委托时保持 in_review。
