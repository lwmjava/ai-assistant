# 统一错误码端到端实施计划

## 目标、现状与边界

依据 tasks.yaml ERR-001、产品需求 §6.6 和本日计数纠正：八种命名错误码与静默刷新成功，共九种场景。统一错误主体为 `{error:{code,message,retry_after,request_id}}`；保留必要的旧 detail/code/配额数值字段以兼容现有调用方，新增规范字段是权威契约。成功刷新无提示，不制造第九码。没有新增供应商、依赖、权限体系、Runtime、生产操作或真实模型调用。

现有认证多数返回 detail，disabled 与不存在混同 401；登录服务提前隐藏 disabled，尚不能在正确密码验证后区分 403。刷新撤销与过期无稳定 code。对话限流/配额已有局部 code，上传超限已有 413；前端只认识部分旧载荷，刷新失败丢失原因。需要对齐 HTTP 与 SSE 的展示，同时保留既有安全日志脱敏、预算、取消和租户控制。

## 原始契约与验收对账

| 要求 | 真实入口与预期 | 验证 |
|---|---|---|
| session_expired | 过期 refresh / 无效会话返回401，前端清会话提示重新登录 | 隔离JWT+HTTP+前端请求链 |
| token_revoked | 管理员撤销后旧 refresh 返回401并区别过期，前端显示管理员重置提示 | 实际撤销路由、新Session、前端不无限刷新 |
| user_disabled | 正确密码登录或现存凭据访问禁用用户返回403，错误密码不泄露账号状态 | 隔离用户启停与HTTP |
| tenant_suspended | 非系统管理员停用租户访问返回403，页面先提示后登出；系统管理员既有管理例外保留 | 实际身份/租户与页面 |
| rate_limited | 429及有效retry_after，发送倒计时；非法数值无无穷禁用 | 实际限流链、HTTP/SSE及计时器 |
| quota_exceeded | 429，原配额数值保留，消息横幅及租户用量展示，失败不新增消息/文件 | 隔离配额与持久化 |
| model_unavailable | 生成调用实际故障映射502/流内错误，内联固定脱敏提示 | 合成远端故障，不外发费用 |
| file_too_large | 超限上传413、显示限制值、无文件/DB副作用 | 真实multipart隔离目录与附件路径 |
| 静默刷新成功 | access过期后共享一次刷新、原请求成功且不弹错 | 真实请求协议测试及页面fixture |
| Swagger | 命名错误码、响应格式及端点状态可查 | OpenAPI契约和导出同步 |

## 最小方案与非目标

使用现有FastAPI异常处理和API边界的固定错误目录，按明确抛错点映射，不通过任意异常字符串猜测身份/模型状态。request_id使用服务端请求上下文，不展示给用户；不将凭据、异常类、堆栈放进规范message。通用其他业务错误兼容现有detail，命名码保持仅原八码。

前端统一解析规范/旧载荷；刷新结果保留稳定原因、并发共享和只重放一次；终态身份错误不无意义刷新，登录重定向提示可保留至新页面，租户停用全屏说明后登出。SSE沿既有规范事件消费，HTTP错误与事件文案一致。已有上传大小和配额规则不变。

不改变首次改密、现有系统管理员租户管理例外、令牌撤销作用域、会话副作用语义，不全量重写服务或把API业务规则搬进handler。不修集合外已知时区问题。方案只细化已批准契约，工程审查在 docs/reviews/。

## 失败边界清单

- 数值：retry_after的0、负数、NaN、Infinity、过大值以及文件上限恰好/超1字节；只对有效有限值倒计时。
- 失败：刷新超时/拒绝/并发401、二次401、模型首包前与流内故障、上传拒绝，不泄漏内部异常。
- 权限与租户：禁用用户、停用租户、错误密码不枚举用户、系统管理员既有例外、跨租户撤销拒绝，不因错误处理放行。
- 身份与绑定：过期与撤销不混同；request_id与响应头一致但不在页面显示；同请求旧detail与规范字段一致。
- 回滚与幂等：刷新单飞及至多一次重放；拒绝后新Session读取无消息/源文件新增；失败不删除已有资源。
