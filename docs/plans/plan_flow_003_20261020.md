## 2. 现状与根因

`app/workflow/scheduler.py:_tick`先取得now，再调用`next_run_time(cron, timezone)`。后者默认以函数内部当前时间求严格未来时刻，因此正常情况下`nxt <= now`永不成立。调度器可以启停，但定时链路进不了`_trigger`。

现有能力复用：`engine.py:next_run_time`本身的“下一次”语义正确，保留其API语义；`_trigger → WorkflowEngine.execute → WorkflowBridge → ChatService`已承担执行、用户/租户上下文、消息和执行记录。现有SQLModel表、手动触发API及历史查询不另造。现有owner失效的拒绝和停用逻辑继续适用。

文档漂移：scheduler注释及FLOW-001历史说明没有实现补跑；产品需求§5.6.2已明确misfire=`run_latest`。锁定拆分计划把完整重试/misfire打磨留给PWFL-001。本卡只采用“每次扫描最多选择当前最近到期时刻”的判定以免错误地逐tick补历史，不宣称完整完成PWFL-001。

| 方案 | 结果与代价 | 决定建议 |

## 4. 推荐行为与数据流

```text
应用既有lifespan启动调度器
  → _loop / _tick（当前UTC时间）
  → 加载enabled且非suspended工作流
  → 按任务IANA时区求最近到期时刻（含整点）
  → 与工作流创建时间、内存水位及同租户cron记录max(created_at)比对
  → 未到点或已经消费：零执行
  → 到点：先消费本轮时刻，再走原_trigger
  → 新Session复核当前工作流/owner
  → 原WorkflowEngine → Bridge → ChatService
  → 新Session / 既有历史API查询cron执行记录
```

1. 时刻全部以aware UTC比较，SQLite返回naive时间按既有UTC约定补齐；cron仍按任务时区解析。整点等于now可触发，时钟回退不能重放已消费时刻。未来创建时间不能触发早于创建的slot。到期helper以now加1微秒为严格前驱查询边界，再转UTC并断言候选不晚于now；不能无条件加1秒（会把靠近整点的未来候选误当到点），极限溢出/非法时区只使该任务失败关闭。
2. 每次扫描对每个任务最多执行最近一次；错过多轮不逐条扫历史，不循环重试失败任务。原下一次时间helper不改成“上一次”，必要时在同一engine模块新增专用到期helper，共享已有croniter依赖和错误类型。
3. 内存水位在尝试前推进，失败也消费该轮；普通同槽后续tick不重复。恢复水位明确为该工作流、同租户、cron来源所有已有尝试记录的max(created_at)，包含pending/running/failed/success；不能拿manual成功、started_at或finished_at替代，不用coalesce(started_at, created_at)把延迟启动误当新的调度槽。失败/pending/running均不得因“只找success”被当作没有尝试而重试。
4. 使用上述执行记录created_at作为已有表能提供的保守恢复水位。长任务的finished_at不作为消费水位。**不承诺跨重启精确slot或恰好一次**：没有scheduled_for时，判定到落库间跨槽延迟无法精确恢复原计划槽。该限制不得被测试全绿掩盖，后续精确恢复需另行状态/模型决策。本卡不新增锁、并发池、重试器或迁移。
5. 进入原执行入口前按ID重新读取任务及owner，删除/禁用/暂停的旧快照不能触发；缺失/禁用/迁租owner按原规则拒绝及停用。保持原身份和租户边界，不新增权限能力或告警。若需要扩大权限语义，先停止申请。
6. 一个任务非法cron/时区、执行异常不影响同tick其他有效任务；不输出原始prompt/模型正文到新日志。不增加Webhook调用、通知或重试，仅沿原成功回调行为。保留原串行tick及其扫描时刻快照，不承诺实时SLA或并行执行，不新增并发池。
7. DST继承现有安装版本croniter的候选语义，再以UTC做边界和水位比较，不另建时区调度器。记录春季不存在时刻和秋季重复时刻的实测回归；同ZoneInfo的fold=0/1本地比较会相等，必须先转UTC。当前croniter6.2.4的纽约春季02:30可能映射到03:00，秋季重复01:30可能返回首轮；本卡不声称“跳过不存在时刻/重复时刻执行两次”等未批准产品策略。若要求改变该策略须先另行裁决，不能默默引入新的DST规则。
8. 保留开关、缺croniter时不启动和调度启停。运行中开关UX属于FLOW-004，本卡不变更默认开关、前端或API。取消仅保持原有传播，不新增PWFL-002超时/取消能力。
