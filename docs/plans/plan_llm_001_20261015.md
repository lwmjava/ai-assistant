# 四用途模型配置与熔断实施计划

日期：2026-10-15。LLM-001。原卡 tasks.yaml，产品需求 P0-8 与 §5.1.7；工程审查 docs/reviews/2026-10-15-llm-001-engineering.md。

## 目标与现状

配置并识别 chat、intent、embedding、rerank 四种用途，保留 fallback；未知用途拒绝。规划、执行、质量门继续使用 chat。现有 generation factory 只登记 chat/intent，embedding 已有独立有效配置及实际 RAG 工厂，rerank 尚无配置档。现有兜底逐请求尝试，无跨请求熔断，单跳直接返回客户端。每次获取 provider 会重新建链，因此熔断不能只存在于临时链对象。

## 方案

新增四用途的类型化配置描述接口，严格校验用途，配置对象 repr 不含密钥。chat/intent/fallback 读取现有字段，embedding 直接映射现有 EMBEDDING_*，不另造一组不生效的嵌入变量；rerank 新增独立 provider/base_url/model/api_key 档，密钥仍只环境注入。generation provider 只服务文本生成用途，embedding 不能走 chat/completions；rerank 只登记可用配置，不调用未经核对的供应商重排协议、不启用检索重排。RAG 实际调用继续使用已有嵌入工厂，配置来源一致，禁止因兜底自动更改 endpoint/model/dim/index deployment。配置对象只描述用途，不将 rerank 配置存在写成重排已实现。

chat/intent 的现有有序兜底加跨请求熔断状态，键包含供应商配置身份（密钥仅哈希）、用途及模型，不输出配置明文；状态有界，过期回收。默认连续三次瞬时失败打开，冷却 30 秒后仅一个半开探测；成功关闭，瞬时失败重新打开。400、权限/参数安全错误、预算与取消不计瞬时故障，不吞 CancelledError；开路快速跳至后续链。保留已有配置错误的兜底行为，但不把凭据错误当可探测瞬时熔断；已经输出 token 后禁止换家重放内容。单跳也经过熔断边界，开发 Mock 行为及现有 override 入口保持。

半开状态使用探测租约/代次，旧在途请求不能覆盖较新状态；流正常耗尽才算成功，取消或 aclose 必须在 finally 释放探测名额。单跳包装保留调用方需要的模型身份/能力信息，每一实际 hop 继续使用自身预算和缓存边界，不共用首跳窗口。

先建立有效红测：四用途读取、未知拒绝、跨多个 get_llm_provider 实例开路/兜底/半开、取消与配置切换隔离、已输出不换家。再最小实现。审查调用缓存、预算和流式取消的现有断言，禁止简单修改总调用次数掩盖回归。测试中用本地 stub 只能称路由契约证据，不能称两家真实提供商已验收。

## 范围与非目标

仅 app/llm、app/core/config.py、.env.example、README、tests、tasks.yaml 和已批准 plans/reviews。无需修改 app/rag；不改索引、数据库或五阶段调用，不实施后续租户 model_profiles 表/管理 API，不引入未批准供应商或外发。此卡聚焦原卡四任务配置与兜底验收，完整租户自选 profile/API 属其他边界，不能因 P0-8 引用擅自扩范围。

## 验收、证据与回滚

配置/熔断/兜底/取消/预算/缓存定向回归，全库 Ruff/mypy，最终不带筛选全量 pytest，更新确定性 Evaluation。至少两个真实提供商切换后对话进入选中供应商仍为原始必验项：实现与离线路由通过后，提供可审查的有界请求方案，再请求具体端点、凭据注入及费用授权；本次不得读取工作区 .env 或擅自发送真实请求。未获授权/缺证据保持 in_review，不能以两个模拟端点关闭该验收。

默认不启用 rerank，不为五阶段独立配模型，不自动切换 Embedding。回退配置与路由改动即可，无数据回退；必要检查缺失时不关闭任务。
