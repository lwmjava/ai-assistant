# NFR-002 实现计划（结构化日志：JSON 格式与 trace_id、user_id、tenant_id）

> 任务卡：NFR-002（P0，L1，risk: logging-format-changed）
> 位置：RAG 域 PRAG-004 的前置依赖（PRAG-004 验收需要"低分命中可复现日志记录"）
> 分支：nightly/rag-20261005

## 1. 目标

让应用日志输出为单行 JSON，并贯穿 trace_id、user_id、tenant_id 三字段，跨模块可按请求串联、可归因。

## 2. 现状（代码事实）

- 日志使用标准库 `logging.getLogger`，无 trace_id/user_id/tenant_id 字段（grep 无输出）。
- 日志脱敏由 `install_log_redaction()`（app/security/log_redaction.py）以 **Filter** 实现，挂在 logger/handler 上、在 emit 前改写 record.msg —— 与 **Formatter** 正交，不冲突。
- `settings.LOG_LEVEL`（config.py:67）已存在但 main.py 未据此配置 handler 格式。
- 认证：`get_current_user`（app/api/deps.py:38）返回 User（含 `id`、`tenant_id`），JWT payload 含 sub/tenant_id。

## 3. 方案（最小、Brownfield、幂等、可测）

### 3.1 新增 `app/core/log_context.py`
- `contextvars`：`_trace_id_var` / `_user_id_var` / `tenant_id_var`
- 提供 getter/setter + `clear()`；供 formatter 读取、middleware/deps 写入。

### 3.2 新增 `app/core/json_logging.py`
- `JsonLogFormatter(logging.Formatter)`：`format()` 输出单行 JSON：`ts`、`level`、`logger`、`message`、`trace_id`、`user_id`、`tenant_id`。message 用 `record.getMessage()`（此时已过脱敏 Filter）。
- `setup_logging()`：按 `settings.LOG_LEVEL` 设根 logger 级别；给根 logger 及全部现有/未来 handler 替换为 `JsonLogFormatter`（幂等，复用 log_redaction 的挂载模式）。

### 3.3 新增 `app/core/trace_middleware.py`
- `TraceIdMiddleware(BaseHTTPMiddleware)`：每请求生成/复用 `X-Request-ID` → `log_context.set_trace_id()`；响应回写 `X-Request-ID` 头；请求结束 `clear()`（保留到响应后，保证日志串内一致）。

### 3.4 接线
- `app/main.py`：`install_log_redaction()` 后调用 `setup_logging()`；`app.add_middleware(TraceIdMiddleware)`。
- `app/api/deps.py`：`get_current_user` 成功返回前 `log_context.set_user(user.id, user.tenant_id)`。

## 4. 非目标（卡 non_goals 遵守）

- 不引入外部日志平台 / 无新依赖。
- 不改日志脱敏逻辑（SEC-002 负责）。
- 不做日志检索界面。
- 不改审计日志（audit/logger.py 独立）。
