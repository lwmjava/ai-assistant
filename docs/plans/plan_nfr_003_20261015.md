# 单实例生产编排实施计划

日期：2026-10-15。任务 NFR-003，用户明确追加为本批前置卡；原始契约以 tasks.yaml 为准。此计划不授权生产启动、重要数据迁移或默认向量库切换。

## 目标与现状

新增生产编排：一个应用实例、PostgreSQL 及配置实际需要的向量服务；健康检查、依赖就绪、重启策略与资源限制。默认 RAG_VECTOR_STORE=local 保持；local 路径不等待用不到的 Milvus，启用 Milvus 时使用已有批准的 2.4+ 服务形态，非 Lite。

当前只有 docker-compose.yml。它默认启动并等待开发 Milvus 三件套，缺独立生产文件。现有 Dockerfile 使用非 root 用户并有 /api/health 探针；requirements.txt 已含 psycopg2-binary，但 pymilvus 仅在已批准的可选 extra，不在默认镜像安装清单。根目录没有 .dockerignore，而 Dockerfile COPY . .；不能在缺构建上下文排除规则时执行生产构建，因为可能把工作区 .env、数据和本地状态打进镜像。

宿主 Docker Compose v2.40.0 可执行配置检查；本机 Docker Desktop 已尝试隐藏启动，但 Linux Engine pipe 不存在，未发现可用运行进程。WSL 只有 docker-desktop，无独立 Ubuntu。实际一键启动、Linux 测试及最终 Ubuntu CI 目前没有证据。

## 最小方案

1. docker-compose.prod.yml 提供 app+db，命名持久卷、单 Uvicorn 进程、数据库依赖健康、已有应用镜像健康探针、unless-stopped、CPU/内存限制。只映射应用端口，默认宿主 loopback，数据库不对宿主开放。资源值是初始限制，不宣称达到性能容量。
2. deploy/compose.milvus.prod.yml 作为显式覆盖，包含沿用已有 pinned Milvus/etcd/MinIO 服务及健康依赖；覆盖 app 的 RAG_VECTOR_STORE=milvus，并让 app 等 Milvus 健康。默认不包含该覆盖。Milvus 仍 Partial，本卡不代替摄取/删除/重解析闭环。
3. 新生产文件从一开始不写可预测凭据或全放行跨域；JWT/数据库口令/允许来源等需部署者显式注入。保留原开发文件当前行为，NFR-012 的原卡检查与修改仍需其前置门禁，不能把本卡安全新建等同于 NFR-012 已完成。
4. 复用根 Dockerfile，仅增加可选 Milvus extra 的 build 参数，默认镜像不安装额外依赖；启用覆盖时安装已有 pyproject 声明的 extra，不引入新供应商或版本。新增 .dockerignore 排除 .env、数据、本地状态、Git、缓存和前端依赖/产物；不排除运行所需迁移与源码。
5. docs/workflows 下写操作说明，包含 local 与可选 Milvus 启动、临时凭据、健康观察、故障、卷保护和代码回退；不执行 down -v、不重写真实数据。scripts 下增加只检查生产配置契约的无外发脚本或等价验证，输出不能包含凭据。

## 验收、非目标与风险

原始验收全部保留：干净隔离项目实际一键启动后声明需要的健康探针通过；依赖未就绪时 app 不进入就绪；local 不把可选 Milvus 计入启动计时。Compose config/YAML/静态契约检查只证明配置，不能替代容器运行。没有 daemon 时记录阻塞，NFR-003 不关闭，NFR-012 不以其为已完成前置。

从隔离临时 env 文件和运行时随机合成凭据执行 docker compose --env-file <临时文件> -f docker-compose.prod.yml config --quiet；默认展开只含 app/db，Milvus 覆盖展开依赖完整；缺必需项拒绝、不回显秘密。隔离运行使用独立 project 名/卷，不接已有容器或生产数据；如果涉及镜像下载或 runtime 缺失，保留真实结果。必要 Linux/CI 及最终输入指纹遵 AGENTS 第10节。

不做 Kubernetes、自动扩缩、多实例共享存储、PostgreSQL 生产演练、RAG 默认切换、反向代理专项或未授权部署。风险 L2；只回退本卡配置/镜像代码，不删除持久卷或数据。任何真实重要数据覆盖、未授权依赖变化或不可隔离失败均停止受影响操作。
