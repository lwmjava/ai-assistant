## 方案比较与推荐

1. 只输出 JSON，行动仍自由调用工具：改动少，但不能证明逐步执行、依赖满足或失败定位，不能满足交付。
2. 固定顺序 Plan v1：推荐。数组顺序即执行顺序，depends_on 只能引用已声明的更早步骤；有步骤状态、有限调用、受控工具执行和 checkpoint，复用现有运行时。
3. 通用 DAG/并行/动态重规划：超出原卡非目标，不采用。

## 推荐运行契约（待设计确认）

Plan v1 用严格 JSON 对象，schema_version=1，steps 为 1–16 项。每步包括 id（受限标识）、description、kind（tool/reason）、depends_on（更早步骤 ID 列表）、expected_output。tool 步须声明注册工具名及具体 JSON arguments；reason 步不调用工具，只综合当前可见上下文和已完成步骤的脱敏观测。未知字段、重复 ID、未知或向后依赖、自依赖、缺字段、非有限数值和超大输入都在任何步骤执行前拒绝。

本版依赖是顺序前置关系，不引入表达式求值、动态输出引用或参数模板；后续推理可以消费前步观测，工具的具体参数由规划阶段给出。动态数据绑定不作为已支持能力。依赖链示例：读取时间 → 固定参数计算 → 综合前两步结果。

五阶段保持：理解 → 规划/校验 → 行动中按步骤执行 → 反思/质量门 → 响应。检索仍复用现有组装与当前权限路径，不另造 Service。规划提示词附当前注册工具及参数 schema，不能凭模型声明提升权限。工具步骤复用 ToolExecutor、RBAC/审计、检索指令守卫、指纹与累计工具预算；无注入 Executor 时就地组合既有 ToolExecutor。单步失败记 failed、step_id、安全 error_code，停止后继，不把失败写成 succeeded 或交模型掩盖为成功。

每步 pending/running/succeeded/failed，取消保留可恢复状态；保存步骤状态与观测后提交快照，完成步骤不重跑。全计划验证与快照恢复原子化，结构损坏不能触发显式恢复的新执行。QualityGate 仅改最终草稿，不重跑已完成工具。规划与 reason 步使用有界超时，步骤数、工具预算和重试均有上限，不新增无限循环。

保持 state.plan 的文本视图供旧 Prompt/RAG 接口使用，另存 structured_plan 与 step 状态。新增 schema 有版本；旧无结构字段 checkpoint 保持既有恢复路径，不静默把旧文本当 v1。新非法 JSON 失败定位规划阶段；降级保留原文本用于展示，执行回滚通过 Pipeline 显式构造参数关闭新模式，不新增配置或修改 API/前端。

现有 MockLLMProvider 不响应任何阶段契约，只回显用户文本；默认严格规划会令离线主链失败。拟仅在 app/llm/mock.py 增加规划阶段的有效单步 reason JSON 响应，保留其他阶段回显。该文件不在当前 allowed_paths，需要用户另行批准后修改；不会联系真实模型或引入供应商。

## 失败边界与对应反例

| 类别 | 反例与最终状态断言 |
|---|---|
| 数值/规模 | NaN/Infinity/极端超大参数、布尔版本号、空或17步、超长内容：整计划拒绝，工具零调用 |
| 失败路径 | 规划非 JSON/错误字段、模型超时、工具超时/上游错、reason失败：安全错误与准确 step_id，后继零执行 |
| 部分成功/重入 | 第二步故障、第一步已成功；取消后新 Session 恢复：前步不重复，剩余预算不刷新 |
| 权限/租户 | 跨租户身份、无身份、L2写闸未开、不可信资料提议工具：原Executor拒绝，准确步骤失败，审计仍受身份绑定 |
| 身份/绑定 | 未注册工具、重复ID、自依赖、未知/后向依赖、畸形步骤状态或游标：执行前拒绝，不部分污染状态 |
| 回滚/幂等 | 显式旧模式、旧checkpoint、QualityGate低分：旧主链可运行，完成工具不因草稿修订重跑 |
| 输出/观测 | 同步/流式相同计划与步骤状态、code_result不丢、Trace不含完整敏感参数；失败不能宣称完成所有步骤 |

每条边界至少一个正式反例，先红必须是业务断言失败而非 import 错误。版本化 Evaluation 标为 Smoke/Adversarial/Observed Regression，脚本 provider 与 SQLite E2 不证明真实生成质量。
