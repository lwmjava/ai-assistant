## 原始契约与事实

原卡 tasks.yaml PAGT-005：技能带版本号、变更留痕；内置技能有回归用例。验收：修改技能内容后版本号变化并可追溯，内置技能回归可执行。依赖PAGT-001，L1；非目标技能市场和在线编辑UI。批准范围app/agents/skills/、tests/、tasks.yaml、docs/。

当前两内置YAML及SkillManifest已有version=1.0；加载器把任意值str化，未验证版本/内容一致。SkillManager.register同名覆盖，没有内容指纹或历史；activate只记录名称/置信度，没有实际选用版本。DB私有/全局技能Service既有权限过滤且row.version=1.0；只读核对它们，不能越界修改服务/API/数据库。已有test_skill_smoke是模块级断言，pytest收集执行而非正式按技能逐案例回归；test_skill_selection验证管理/归属，与本卡版本回归不同。

## 选项及推荐

A 推荐：保留声明发布版本release（兼容既有version字段），新增确定性内容修订content_revision与有效执行版本effective_version。对全部运行Manifest，内容变化自动改变effective_version（例如1.0#sha256:<完整指纹>），即使DB声明版本暂未升号仍能追溯实际执行内容。内置YAML另配持久版本账本，包含发布版本/内容指纹/变更摘要；改内置内容时明确升发布版本并更新账本，未同步由回归门禁拒绝。激活上下文/安全日志携带被实际选择版本，注册变更留有限内存元数据，不保存Prompt正文。保留既有API的version字段含义，不称数据库声明版号自动升级。

B 仅人工升version+Git记录：改动最少，但同一version可能对应不同内容，无法在执行现场区分，且无自动识别内容变化。不推荐。

C 数据库版本链+历史正文+API/UI查询：覆盖持久版本浏览，但需要services/models/API/迁移/前端与更多授权，不是本卡当前边界。不推荐；不得静默用C实现。

## 推荐具体设计

- SkillManifest.version为既有声明发布版本（支持旧1.0及规范三段数字版本）；content_revision按schema版本固定的canonical JSON生成SHA256，覆盖名称/描述/模式/触发条件/Prompt/工具/模型/启用状态等行为字段，排除机器绝对路径和版本标签，纯格式/键顺序不误报内容改变。effective_version为声明版本+完整内容修订，内容改变必然变，绝不把内容指纹伪称单调数字版本。
- 编码失败、非有限置信度/错误版本类型或过长输入给安全ValueError；不打印原始Prompt、秘密或主机路径。运行内容修订和发布版本语义分离写入规格。存量private/global仍先通过Service可见性过滤，再由Manager选择；不扩大权限，不改DB写入规则。
- 内置发布账本位于app/agents/skills/builtin/的JSON文件，不被YAML发现器当技能。两内置初始版本及指纹/摘要可追溯，规范新发布号。门禁真实读取YAML与账本，修改未升版本/漏记录/错误hash须失败；合法修改必须升发布号并追加条目而不是替换历史。正式回归演示临时目录复制技能→修改内容→拒绝未升版本→升版追加记录→新Manager重新载入与执行匹配/注入。
- SkillManager注册/激活记录安全版本元数据，历史有界且返回副本，重复注册完全相同内容不新增变更；覆盖/回退留版本记录，非法更新不能部分覆盖当前可用对象。reload保留实际目录，不因失败丢失已加载技能。细节由工程审查收紧，不顺手改变匹配优先级。
- 内置规格（Purpose、Preconditions、Workflow、Tools/RAG、Constraints、Escalation、Examples、Tests/Evaluation、Owner/Compatibility）落docs，沿用既有实际Prompt，不借本卡改模型行为或加入新工具授权。
- 真实Manager/loader/文件读取→match→activate→inject，以及隔离ChatService/HTTP实际选用技能与模型消息为必交付E2。合成provider只检查执行/约束可追溯，不证明翻译/审查生成质量。

## 独立工程审查后的设计收紧（已获用户批准）

审查来源：../reviews/2026-10-13-PAGT-005-plan-review.md，Agent /root/pagt005_plan_review。采纳全部推荐 A。原 P1 方向问题已由用户批准推荐方案解决：内置发布 version 人工升号并追加持久账本；所有实际执行内容的 effective_version 自动随内容变化；现有 DB/API 声明 version 不自动升号。有界 runtime history 不等于数据库持久版本历史，内容身份不作为权限凭据。若用户后续要求 API version 自动递增，则先确认 Service/API 范围。

1. Manifest 在 register 校验并深复制；get/list_all/match 返回隔离副本。activate 校验实际注入的副本内容并计算对应版本，不接受伪造指纹；stale match 保持兼容，执行其旧内容快照并标记旧版本。只为真正达到阈值的激活技能记录身份和置信度；origin 另作为来源元数据绑定。
2. 纯发布校验入口显式绑定技能目录与该目录账本。正式内置回归校验版本控制目录，临时演练显式绑定副本；外部同名技能不自动获得正式内置身份。拒绝同版不同内容、倒退/重复发布号、末条与当前 YAML 不一致、漏/未知技能；候选追加还须与旧账本比较保留历史前缀。数字段比较兼容 1.0；Git 与独立审查共同核对历史，不宣称账本防篡改。
3. 普通 discover_skills 保留安全跳过坏文件的 Service 兼容路径；Manager load/reload 使用严格、有失败信号的发现路径。完成全部候选解析校验后，一次提交技能集、全局 history 与实际目录配置；任何失败都保留三者旧状态。合法删除空集与坏 YAML/目录失败明确区分。
4. history 使用全局固定容量 100 条元数据队列，返回副本；文本与集合输入总规模设限，不保存 Prompt 正文。直接 Manifest 与 YAML 两入口都拒绝无效类型、重复 YAML 键、非有限或越界置信度、非法正则、无效版本与编码。日志和错误只含固定错误类别及受限身份，不输出原文、正则或绝对路径。

独立验收增加真实 HTTP 技能更新、提交后新 Session 读取、下一次 Chat 实际选择及 Provider 收到的 Prompt，对比执行版本与既有写入审计；内置回归只证明约束传递，不把合成 Provider 输出写成真实模型质量。审查列出的可变对象、旧 match、部分激活、全局历史溢出、目录/部分文件失败、账本历史重写、同名归属与日志泄漏反例全部纳入正式测试。
