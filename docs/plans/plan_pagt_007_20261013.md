## 3. 方案比较与推荐

A（推荐）：独立 Agent CI job + 复用运行器 + 严格报告 gate + 退化探针。真实模型运行与校验可单独观察，避免既有后端或 RAG 失败掩盖 Agent 结果。增加少量脚本和报告契约。

B：在 backend job 末尾追加 Agent 步骤。改动更少，但前置 lint、pytest 或 RAG 失败会阻止 Agent 评测，持续门禁证据不完整。

C：只在 CI 使用 smoke 或回放旧报告。成本低，只能验证脚本链路，违反本卡“不把 Mock 模型或假数据当门禁证据”，不采用。

## 4. 推荐设计

```text
push / pull_request
  -> independent Agent job
  -> official real single provider (12 bounded calls)
  -> bounded complete report
  -> gate: expected identity -> current inputs -> raw parser -> metrics
  -> three probes: each must exit 1 with target metric reason
  -> upload only safe report / probe artifacts

missing credentials / timeout / invalid report / regression / bad probe
  -> job failure (no Mock fallback, no skip-as-pass)
```

### 4.1 运行器与身份

保留 smoke 和 --report-dir；新增 --out 显式报告路径，预先拒绝覆盖，失败不留下貌似完整的成功报告。报告写入使用排他创建并在失败时清理本次未完成文件，保护已有文件。

official 必须验证实际 intent provider 是真实单一 OpenAICompatibleProvider；拒绝 Mock、未知 provider 和无法确认逐次模型身份的 fallback 包装。CI 显式固定 chat/intent 为同一 chat profile，不新增供应商或 app/llm 配置字段。不把 chat availability 作为充分条件。禁用响应缓存；模型与运行器参数记录入报告，返回模型身份如现有接口无法提供则明确限制为配置的请求模型，不声称服务端返回身份已校验。

每次调用温度 0；12 次逻辑请求串行执行，每次超时上限 60 秒，总评测上限 780 秒，CI job timeout 20 分钟；当前 provider 使用 httpx 直接请求，无 SDK 自动重试，本卡不添加模型重试。用户确认方案后才通过既有配置加载机制使用凭证运行 official，不直接读取、输出或复制 .env。无真实模型则拒绝 official，不自动降级 smoke。报告只记录安全的模型名称与端点身份哈希，禁止包含 API Key、Authorization、原始错误响应或带凭证的 URL。

### 4.2 报告与严格门禁

保持数据集和评分语义不变，评分器版本 agent-chain-eval-0.2.0；新增独立 report_schema_version / gate_version 标识新报告和校验协议，避免伪称评分算法升级。保留旧手工报告读取习惯，但旧报告不能冒充新 CI 报告。

记录数据集版本及 cases/index 指纹、Prompt 名义版本、两阶段实际构建消息的整体指纹、关键 Pipeline/Prompt/工具契约/评测脚本指纹、git_commit、provider 类型、请求模型、temperature、mode、10 条完整案例及三项指标。Hash 覆盖真实送模输入，标准答案字段不进入模型消息。

独立 scripts/agent_gate_check.py 从冻结数据集复算指标，不信报告汇总。拒绝 smoke/Mock、缺失或重复案例、额外案例、标准答案字段漂移、无效类型、NaN/Infinity、超范围指标、指标与明细不一致、当前输入/源码身份不匹配及不完整报告。阈值保持 0.9/1.0/1.0，不由报告提供或任意覆盖。

身份校验输入必须独立于报告：gate CLI 必填 --expected-model 与 --expected-endpoint-hash；CI 从与 official 相同的非秘密 Variables 配置独立计算传入，禁止从报告读出期待值。端点先校验无用户凭证、query/fragment，规范化后哈希；本地调用同样明确提供期待配置。gate 必须对 raw_reply / tool_reply 使用当前真实分流/工具解析器重算预测，再与报告明细和汇总对照，防止自洽错误绕过。报告最大 1 MiB，单条模型回复最大 16 KiB；读取前和写入前校验，超限拒绝，JSON 禁止重复键与非有限常量。

明确工具指标仅是两个正例的选择 recall，不表示负例覆盖或工具执行安全。副作用字段区分“运行器不执行工具”的设计约束与已观测的模型请求；不得将固定零字典写成动态监测证据。用独立入口测试实际阻止 Tool/MCP/RAG/DB 执行，官方只发送已有合成评测文本。

### 4.3 CI 集成与退化验证

独立 job 沿用现有 push / pull_request 触发，不增加路径过滤，不依赖 backend/RAG 成功。permissions 保持 contents: read。安装步骤不注入模型凭证；official 步骤仅从 GitHub Secrets 接收 LLM_API_KEY，非秘密 base URL / model 从 Variables 接收并有现有 DeepSeek 默认值；固定 provider/profile/caching 参数。

凭证缺失或 fork PR 无凭证时明确失败，不跳过后算通过；禁止引入 pull_request_target 或带秘密执行不可信 fork 代码的替代流程。只上传指定安全报告/探针日志，不上传 .env 或整个工作区。上传失败不能掩盖原门禁失败。

2026-10-13 核对 GitHub 官方 [Secrets 文档](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets)：fork PR 与 Dependabot 事件没有模型 secret；未配置 secret 表达式为空字符串。两类事件均按缺凭证失败处理。工作流事件语义参考 [官方事件文档](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows)，不提升事件权限以绕过限制。

CI 先生成并校验新鲜真实 official 报告，再从该报告独立构造三份受控故障副本：route 翻转两个非 followup 路由（单错0.9仍符合阈值）；followup 翻转一个关键续问路由（route0.9，但followup0.5）；tool 去掉一个必选工具（tool0.5）。副本同步复算汇总，并通过真实 gate CLI，必须由对应指标判失败；不能仅凭格式错误判拦截。正常报告保留，故障报告明确标记为合成探针，不作为模型质量通过证据。探针不修改十例数据集或生产代码，也不新增模型调用。

探针同步改变 raw_reply / tool_reply 与预测及指标，确保通过完整性检查后在目标指标失败。合成性质标注在探针输出目录名及独立 manifest，不给正式 gate 增加允许合成通过的模式，不因报告内 synthetic 标记在指标检查之前拒绝。只对新鲜已通过真实 gate 的 official 报告派生，禁止从 smoke/历史报告生成可声称验收通过的探针证据。

gate 区分退出码：0 通过、1 指标退化、2 输入/身份/完整性错误；指标错误输出稳定的安全 reason code。probe 必须断言 exit=1 且 reason code 对应目标指标，CLI 使用错误、异常和任意非零均不算探针成功。safe parser 同时拒绝非UTF8和超出预定固定结构深度的对象。

受控报告退化证明门禁拒绝相应观测结果，不能证明任意 Pipeline 缺陷均可检出；另由入口验证 Agent 构造运行器/评分接线退化测试。这十例仍只能拦截覆盖范围内的硬退化。

## 5. 失败边界及正式反例

| 类别 | 边界 | 期望与正式验证 |
|---|---|---|
| 数值 | NaN/Infinity、负数、大于1、bool、空样本/零分母 | CLI 非零；有限0..1且重新计数，不修改阈值 |
| 失败路径 | API unavailable/超时/中途失败/截断JSON/报告缺失 | 安全错误、非零、无完整成功报告；CLI及隔离 provider 入口反例 |
| 权限与租户 | 缺 secret、fork无secret、模型提示泄露答案、误执行工具/DB | fail closed；固定合成输入；测试禁止外部执行；CI无额外写权限 |
| 身份与绑定 | chat real/intent Mock、fallback身份不明、旧Prompt/改数据集/错误模型/重复案例 | 拒绝 official 或报告；关键输入版本绑定；真实入口反例 |
| 回滚与幂等 | 已有报告路径、失败重跑、取消/部分报告 | 不覆盖旧报告、不重复业务写；显式退出；失败后可改新路径重跑 |

回滚只撤销独立 job/gate 集成、恢复手工评测，无数据库或运行时业务状态迁移。Report 输出目录限已批准 evals/ 或隔离测试目录，CLI 不接受覆盖既有证据。

## 7. 非目标、风险及关闭条件

不扩容数据集、不改变评分阈值、不做 RAG 实验、不新增运行时 Harness/Tool Executor/状态架构、不改 API 或生产模型配置、不实现分支保护配置、不自动 commit/push/merge/deploy。CI job 可提供 required-check，是否配置为仓库强制合并检查须报告实际仓库设置，不能仅写 workflow 就声称强制发布保护已启用。

主要风险：十例判别力有限；模型输出随服务端版本变化；外部API成本和可用性；fork 无凭证导致 check 失败；真实CI需要可发布最终代码与可用Secrets。服务端模型身份不可从当前仅字符串接口确认时只记录请求模型。所有未验证必交付项原样登记 tasks.yaml，保持项目未完成状态。

设计已批准：采用方案A、单模型身份限制、凭证缺失 fail closed、保持十例及阈值、真实报告衍生退化探针、不用合成数据证明质量；确认后按上述有限模型调用与角色开展实施。
