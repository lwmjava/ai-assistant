# PRAG-003 实现计划（Citation 产品化：结构化溯源输出，2026-10-05）

> 任务卡：PRAG-003（P1，L2，risk: api-response-shape-changed）
> 分支：nightly/rag-20261005
> 状态：计划（落盘后方可改业务代码）

## 1. 目标

让答案返回**结构化、可定位的引用**：每条来源含文档、页码或分块、以及摘录原文；前端展示摘录并可跳转到知识库定位来源；OpenAPI 响应结构同步更新。

## 2. 现状（探查结论）

- 后端已交付来源字段 `{filename, page, section}`（QA-002，`sources_from_hits` + `SourceOut`），但**缺摘录（excerpt）与分块 id（chunk_id/document_id）**，用户看不到引用原文、无法定位到具体分块。
- `ChunkResult` 已含 `id`（分块 id）、`content`（原文）、`document_id`、`source`——后端补字段零成本可拿。
- 前端 `SourceRef = {filename, page, section}`，`SourceNotes` 渲染为纯文本列表，**无摘录、无跳转**。
- 前端有 `/knowledge` 知识库页（`Knowledge.tsx`），是检索页，无独立文档详情路由；可用 URL query `doc=<document_id>` 做最小定位。
- OpenAPI：FastAPI 基于 `SourceOut` schema 自动生成，`SourceOut` 加字段即自动反映。

## 3. 方案

### 后端（app/rag/service.py + app/api/routes/chat.py）
- `sources_from_hits`：每条来源追加
  - `excerpt`：`hit.content` 折叠空白后截断（上限 240 字符，可读原文片段）
  - `chunk_id`：`hit.id`
  - `document_id`：`hit.document_id`
- `SourceOut` 追加 `excerpt: str | None = None`、`chunk_id: str | None = None`、`document_id: str | None = None`（可空，向后兼容，保持旧字段）。

### 前端（frontend/src）
- `types/api.ts` `SourceRef` 追加 `excerpt`/`chunk_id`/`document_id`（可选）。
- `MessageList.tsx` `SourceNotes`：每个来源展示"标题 · 页码 · 段落"，并显示摘录（截断可读）；来源项作为可点击链接，跳 `/knowledge?doc=<document_id>`（新标签）。
- `Knowledge.tsx`：支持 URL query `doc=<document_id>`，加载后在该文档对应的检索/管理区定位（读取 query 并在文档条目高亮/提示），提供最小"定位来源"路径。

### OpenAPI
- `SourceOut` 字段变化由 FastAPI 自动生成；在 README 端点说明标注引用结构；契约测试断言响应含 `excerpt`/`chunk_id`/`document_id` 字段（本卡自行验收，不依赖 REL-001 Swagger 定稿）。

## 4. 非目标

- 不做引用可信度评分（卡 non_goals）。
- 不改检索链路参数（卡 non_goals）。
- 不依赖重排结论（Citation 只改响应形状）。
- 不做独立"文档分块详情页"（用 `doc=<id>` 在知识库页最小定位，深链分块详情留后续）。
- 不把知识库数据/索引迁移，不改数据库表结构。
