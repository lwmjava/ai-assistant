# PRAG-004 实现计划（检索低分阈值与拒答，2026-10-05）

> 任务卡：PRAG-004（P0，L1，risk: retrieval-threshold-added）
> 分支：nightly/rag-20261005
> 前置：NFR-002（结构化日志）已实现——低分命中日志用 JSON 日志承载

## 1. 目标

相似度低于阈值的检索命中可少返回或全不返回；选择拒答时给出明确提示语，不得硬凑回答；低分命中写入可复现日志。

## 2. 现状（代码事实）

- `HybridRetriever.retrieve`（app/rag/retriever.py）→ `backend.retrieve(query+plan, top_k=5)`，无任何阈值过滤。
- **关键事实**：`ChunkResult.score`（app/rag/vectorstore/base.py）当前承载的是 **RRF 融合分**（`local.py:_rrf` 的 `1/(60+rank)` 累加），恒远小于 0.4（两路都第 1 也仅约 0.033）。卡的"相似度 0.4"阈值**不能直接套在 score 上**，否则全部命中被误滤。
- 真实相似度是稠密余弦（`local.py` 中 `dense = matrix @ q`，-1~1），当前未暴露给上层，仅在 RRF 排序内部使用。

## 3. 方案（需用户确认的裁决点）

**方案 A（推荐，正确且最小）**：让阈值作用于真实相似度，而非 RRF 分。
- `ChunkResult` 增加 `similarity: float` 字段（稠密余弦，-1~1）；`local.py` 在 RRF 命中里填入对应稠密相似度。
- 新增配置 `RAG_MIN_SIMILARITY`（默认 0.4）与拒答提示文案 `RAG_REFUSE_MESSAGE`。
- `retriever.py`：`retrieve` 后过滤 `similarity < 阈值`；全部被滤且原本有结果时，`last_hits` 置空、写日志（含查询与阈值，走 NFR-002 JSON 日志）、返回明确拒答提示；否则照常拼接上下文。
- 这是对 RAG 检索响应契约的扩展（新增字段），非破坏性（`score` 语义不变）。

**方案 B（否决）**：直接对现有 `score`（RRF 分）设阈值——RRF 分无绝对相似度语义，0.4 无意义，会破坏召回。不用。

## 4. 非目标（卡 non_goals 遵守）

- 不做拒答后的兜底生成。
- 不改 `top_k` 默认值。
- 不强制每一次低于 0.4 都必须拒答（低于阈值只影响返回数量；拒答提示在"有命中但全被滤"时给出）。
- 阈值不得用 holdout 集调参（用 0.4，不做超参搜索）。

## 5. 验收（来自卡 acceptance）

- [ ] 相似度低于 0.4 时返回更少或不返回命中。
- [ ] 若拒答，有明确提示语。

- [ ] 阈值与拒答文案有评测案例覆盖。
- [ ] 阈值不得用 holdout 集调参。
