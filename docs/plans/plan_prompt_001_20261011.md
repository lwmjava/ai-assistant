## 方案与取舍

采用文件化、不可变版本登记 + 只读校验/导出工具：登记源文件 LF 规范化 SHA-256、精确 Git 来源、生效 UTC 时间与恢复说明；新增只读 CLI 检查源内容漂移。源码覆盖必须包括 memory/compressor、evolution/reflector 与 distiller、RAG 边界/摘要，以及新增文件，不能只登记五阶段常量。允许保守地对应用源文件整体登记（除校验器本身），读其他模块不构成修改范围扩大。模型配置以显式字段白名单生成可复算版本，禁止密钥、连接串、请求内容进入输出。端点身份若需区分，使用安全摘要，不输出原始地址。保存模型配置的非敏感字段快照，明确端点/凭据仍由环境秘密管理，回滚需恢复对应环境版本并重启。默认登记来自源码默认值，不读取 .env，不把默认登记冒充当前部署。CLI 直接执行 stdlib-only 脚本，避开 app.agents 包初始化加载配置的既有副作用；用 AST 读取配置默认值而不导入 Settings。

比较过仅 Markdown 登记（易漂移）、运行期可切换 Prompt 平台（超出本卡）和带校验的文件登记；选择第三种。使用 brainstorming 的设计探索维度；已明确调用的 task-card-delivery 规定常规范围内修改连续执行、不做阶段性确认，按其授权完成，不提交或推送。

## 失败边界清单

1. 数值：模型温度/超时等 NaN、Infinity 拒绝版本化，防止 JSON 非标准数字；有限边界可重复计算。
2. 失败：登记缺失、坏 JSON、源不存在、内容漂移均明确失败，校验不修改源或登记。
3. 权限/租户：只读开发工具不接收业务身份、不读取租户输入；配置中的密钥/秘密端点与其他字段不得序列化，使用注入秘密的反例。
4. 身份/绑定：源码新增、删除、修改，以及模型名/路由/端点变化被发现；与工作目录无关；换行不导致跨平台误判。
5. 回滚/幂等：在临时树演练修改→失败→恢复→通过，多次读结果一致；不覆盖实际配置或生产数据。
