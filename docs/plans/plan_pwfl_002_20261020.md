## 方案与备选

推荐：在现有 engine 外包一层受控、可取消的 asyncio 子任务，注册执行 ID 与 workflow/tenant 绑定。HTTP 和 cron 继续等待最终结果，沿用原返回契约；不另造 Agent Runtime。每个任务持久化 `timeout_seconds`，默认300秒，整数范围1–3600。总时限包含 bridge 各次尝试与退避；超时和主动取消均停止重试。webhook 是成功后的独立有界通知，不把已成功记录追溯改成超时。发布前等待当前活动执行排空。

备选一：只给手动 `/run` 增加临时参数，不迁移。缺点是 cron 无法使用保存的任务超时，不能完整满足任务级配置，因此不选。

备选二：请求立即返回、后台长期持有任务。需要独立 Session、停机收敛和请求协议迁移，扩大本卡范围，因此不选。

执行语义：

```text
创建 pending 记录 → 绑定并注册子任务 → running
  ├─ bridge 成功 → success → 释放注册 → 可选 webhook
  ├─ 普通失败 → 原有限退避/重试 → success 或 failed
  ├─ 总超时 → 取消并等待子任务退出 → failed / WORKFLOW_TIMEOUT
  └─ 手动取消 → 取消并等待子任务退出 → failed / WORKFLOW_CANCELLED
```

不新增历史字段或状态枚举，超时与取消保留 `status=failed`，通过稳定 error 标记区别；记录结束时间与耗时。不能将仍在清理的任务宣称已释放。取消只支持当前进程合作式 asyncio 代码，不保证中断同步阻塞或已完成的外部副作用。不得用超时后直接遗弃子任务来制造释放证据。

API：`POST /api/v1/workflows/{workflow_id}/executions/{execution_id}/cancel`。沿用 workflows/write 权限和系统管理员跨租户规则，必须核验 workflow、execution 和当前活动绑定；跨租户或错绑返回404，终态取消幂等返回已有终态；数据库显示运行但本进程无任务时返回409，不能伪造已取消。通过既有 WORKFLOW_EXECUTE 审计动作记录 cancel 操作与执行ID，不写 prompt/输出。正常完成与取消竞态以最终实际终态为准。

所有外部取消（如调度器关闭、请求自身取消）必须清理子任务和注册并落终态，再向父调用传播取消；主动业务取消应只结束该次子任务，不结束调度循环。

独立计划审查补充的实施约束：注册项只共享ID、租户绑定和控制句柄，不共享执行Session或ORM对象；取消请求等待清理后必须使用新Session读取终态，避免identity map返回旧running。活动执行期间删除该工作流返回409，防止级联删除执行历史与终态提交竞态；执行结束后沿用既有删除权限。执行失败/取消若遇数据库事务异常，先rollback，再由原执行所有者可靠写终态，不允许取消API并发操纵同一个Session。收尾须抵御重复取消，清理完成才移除活动绑定；不得把仍运行的任务标为已释放。

300秒是发起合作式取消的截止点，不承诺清理必定在该秒数内结束。吞掉CancelledError的下游、同步阻塞及不可取消外部副作用不受硬时限保证，本卡不引入强杀兜底。遇到无法收敛的下游，必须报告未验证/失败，不声称满足释放资源验收；测试覆盖真实bridge合作取消及finally释放。

## 失败边界与 Evaluation

使用版本化 pytest 场景集合 workflow-timeout-cancel-v1（合成 Smoke/Adversarial，非Gold），测试真实 engine/API 与隔离 SQLite，bridge 可用合作式合成长任务做故障注入；另覆盖真实 WorkflowBridge/ChatService 的取消传播。每项验证最终持久化状态及资源清理，提交后用新 Session 回读。

| 类别 | 反例与期望 |
|---|---|
| 数值 | 0、负数、超上限、NaN/Infinity、bool、非整数拒绝；默认300且合法边界1/3600持久化后可读。 |
| 失败 | 长任务超时、退避中超时/取消、bridge异常、取消中清理、父任务取消均有正确终态，调用不再继续，finally释放可观察资源。 |
| 权限租户 | 匿名、只读角色、跨租户、错workflow/执行ID、owner删除/停用均不误取消他人任务或改用触发者身份。 |
| 身份绑定 | 不同 WorkflowEngine 实例共享本进程活动绑定，cron与手动均可取消；找不到本进程任务返回409，不伪报成功。 |
| 幂等竞态 | 重复取消、成功后取消、并发取消/完成不改写成功；每次执行仍只有一条历史记录，不追加重试；结束移除注册。 |
| 删除与事务 | 活动执行删除返回409且任务继续可查；执行结束后可按既有权限删除。取消遇事务异常先rollback，清理完成后新Session读到唯一终态；取消API不用另一请求的Session。 |
| 兼容回滚 | 老工作流迁移后默认300，既有同步/run成功及失败契约保持；退回旧代码前排空活动执行，保留执行历史。 |
