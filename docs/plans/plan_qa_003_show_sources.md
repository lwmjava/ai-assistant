# QA-003：对话页展示来源

> 状态：已实现（`tasks.yaml` QA-003 `done`）
> 来源：交付排期 B3；`docs/plans/plan_remaining_delivery.md` 的 QA-003
> 日期：2026-09-26
> 截止：2026-11-13
> 依赖：QA-002 已完成

用户在对话页能看到这条助手回复用了哪份文件。已有页码或段落时一起看到。没有来源时不出现空白来源区。

## 目标

1. 已保存的助手消息在气泡正文下展示来源。
2. 流式生成时，来源事件到达后，临时气泡也展示同一列表。刷新换成已保存消息后仍然看得到。
3. 来源为空时不渲染来源区。文件名不可点击，不打开原文。

## 现状

- 非流式响应、流式 `sources` 事件、会话详情里的助手消息已经带来源。每条有 `filename`，`page` 和 `section` 可以是空。
- 前端 `MessageOut` 和 `ChatResponse` 还没有 `sources`。`MessageList` 只渲染正文。
- 流式钩子把事件的 `data` 当成字符串。`sources` 事件的 `data` 是数组，目前没有对应分支，会被忽略。
- 一次性发送结束后会按 `conversation_id` 拉取会话详情。流式结束后也会刷新详情。展示以详情里的助手消息为准即可覆盖刷新后的页面。
- 本机 `.env` 若仍把检索关掉，对话不会产生来源，页面上看不到文件名。这不是页面缺陷。

## 方案

1. 在 `frontend/src/types/api.ts` 增加来源类型：`filename`、`page`、`section`。`MessageOut.sources` 和 `ChatResponse.sources` 都是这个列表，缺省为空数组。流式事件类型加上 `sources`。
2. `useChatStream` 识别 `sources` 事件。`data` 为数组时写入当前快照；不是数组时视为空列表。不把这个数组拼进回复正文。
3. `MessageList` 在助手正文下渲染来源。只有文件名时显示文件名。有页码时加上“第 n 页”。有段落时加上段落文字。列表为空或字段缺失时不渲染这块。用户消息不渲染。
4. 流式临时气泡使用快照里的来源，规则与已保存消息相同。`Chat.tsx` 把这份列表传给消息列表。
5. 不改后端，不改检索，不加跳转和侧栏。

## 非目标

不做引用角标、原文摘录和侧栏。不改来源的生成规则。不改知识库页面。

## 验收

- 有来源的助手回复下面能看到文件名；有页码或段落时一并看到。
- 来源为空的回复下面没有来源区。
- 流式和一次性两种发送，刷新会话后仍能看到来源。
- 前端类型检查与构建通过。
- 在浏览器里实际发送一条能命中文档的消息，确认文件名出现；再看一条没有来源的回复，确认没有空白来源区。

## 实现说明

登录后的成员在对话页看助手回复。来源列表有文件名时，正文下方逐条显示。页码是大于等于 1 的整数时，同一行加上「第 n 页」。段落非空时加上段落文字，用「 · 」连接。来源缺失或为空时不渲染这块。用户消息不显示来源。文件名是纯文本，不能点击，不打开原文。

流式过程中，`sources` 事件写入当前快照，不拼进回复正文。临时气泡用这份列表。流式结束后页面刷新会话详情，改由已保存消息展示。一次性发送结束后也会拉取会话详情，规则相同。

### 代码位置

- 类型：`frontend/src/types/api.ts` 的 `SourceRef`。`MessageOut.sources`、`ChatResponse.sources`，以及流式事件类型 `sources`。
- 流式：`frontend/src/hooks/useChatStream.ts`。`sources` 的 `data` 不是数组时当作空列表。
- 展示：`frontend/src/components/chat/MessageList.tsx` 的 `SourceNotes`。已保存的助手消息和流式临时气泡都使用它。
- 传参：`frontend/src/pages/Chat.tsx` 把快照里的来源传给消息列表。

### 验证结果

前端类型检查与构建在实现时已通过，退出码 0。命令是 `cd frontend` 后的 `npm run typecheck` 与 `npm run build`。

浏览器里以成员 ada0925 打开对话页。会话「今天天气怎么样」的助手回复下面没有来源区。随后两条询问 QA003SOURCE 月费的助手回复同样没有来源区，页面正文里没有 `qa003-billing.txt`。这两条回复的会话详情里 `sources` 都是空数组。

本机 `.env` 写着 `RAG_ENABLED=false`，运行中的对话不会构建检索器，所以页面产生不了文件名。知识库检索接口对同一句话仍能命中 `qa003-billing.txt`，说明文档在库里。没有修改 `.env`。这不是对话页没渲染来源。
