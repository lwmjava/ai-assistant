# 对话页回显配额上限

> 日期：2026-10-01
> 状态：已实现。说明见 `docs/plans/implementation_quota_error_message.md`

## 问题

`POST /api/chat/stream` 在消息条数达到上限时返回 429，正文是 `quota_exceeded`。页面把这次失败当成连接中断，轻提示标题是「生成失败」，几秒后消失。用户无法知道是配额用尽。

## 交付

- 识别 `code=quota_exceeded`。消息条数写成已用条数、上限，以及请管理员调高或删除会话后再发。源文件字节同样说明已用和上限。
- 流式和一次性发送都在输入框上方保留这段说明，直到下一次发送。轻提示标题为「已达配额上限」。
- 这条失败不再显示「连接中断」或「加载完整回复」。
- 知识库上传、工作流执行如果收到同一响应，失败说明也使用这段文字。

## 非目标

- 不改 429 的响应体。
- 不在对话页提供修改配额的入口。
- 不展示配额的设置页。

## 验收

- 消息上限用尽时，对话页能看到已用条数、上限和下一步。
- 前端 `npm run typecheck` 通过。
