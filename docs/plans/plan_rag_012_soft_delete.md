# RAG-012：软删除与保留期

> 状态：已实现（RAG-012 `done`）
> 分支：`feat/rag-012-soft-delete`
> 来源：交付排期 A2；评审修复方案阶段 3
> 日期：2026-09-25
> 截止：2026-10-15

删除改为记下删除时间，不立刻抹掉行、分块和源文件。保留期 **90 天**。成员与对话检索看不到已软删文档；租户管理员和系统管理员可以在列表里打开查看。期满后再物理清理并留下审计。

## 目标

1. 文档删除时间；列表默认隐藏；管理员可查看。
2. 保留期届满的物理清理路径与审计。
3. 前端默认隐藏；管理员可切换查看。

## 非目标

不改已落地的角色矩阵；不做完整状态机；不提供恢复接口；不立刻物理删除。

## 验收

软删对成员与检索不可见；未满 90 天不物理删；届满清理可追溯；相关 pytest 通过。

## 风险与回滚

L2。回滚删除时间字段与清理调用。已软删的行留在库里，不在回滚时补做物理删除。

## 实现方案

先改会失败的删除断言，再改删除、列表和检索过滤。角色矩阵保持现状：成员只能删自己的当前版，租户管理员可删本租户全部版本，系统管理员可跨租户删。本方案不新增恢复接口。

代码注释只描述当前行为，不写任务编号、文档编号、文档名称或修订日期。

### 1. 删除时间

`rag_documents` 增加可空时间列 `deleted_at`。空值表示未删除，有值表示已软删，同时就是删除时间。不加第二套布尔标记，避免两列不一致。

Alembic 新修订挂在 `d4e8b1c7a902` 之后，只加可空列。已有行保持空值。不回填、不删行。

软删时：

- 写入 `deleted_at`，保留 `is_current`、版本组、分块、向量和源文件。
- 不调用现有的物理删除，也不调用 `delete_source_file`。
- 已有 `deleted_at` 的文档再次删除，返回 404。
- 重解析、下载对已软删文档一律拒绝。管理员只能在列表和详情里看到它。

`test_kb03_member_cannot_delete_peer_admin_can` 现在断言删除后行不存在。改为：行还在，`deleted_at` 有值，检索不再命中。

### 2. 谁能看见

默认列表、详情、检索都不含已软删文档。

| 操作 | 成员 | 租户管理员 | 系统管理员 |
|---|---|---|---|
| 默认列表 / 详情 | 仍只看自己的未删当前版 | 本租户未删的全部版本 | 任意租户未删的全部版本 |
| 查看已软删 | 拒绝，即使带查询参数 | 本租户已软删 | 任意租户已软删 |
| 删除 | 仍只能软删自己的未删当前版 | 本租户未删的全部版本 | 任意租户未删的全部版本 |
| 检索 | 本租户未删当前版 | 同左 | 同左 |

`GET /documents` 增加 `include_deleted`。缺省为 false。只有租户管理员和系统管理员可以把该参数当成 true；成员传 true 也按 false 处理。

`can_read_document` 增加「`deleted_at` 为空」。对话检索因此不会把已软删文档当可读。

本地检索和 Milvus 检索都在现有 `is_current` 条件上再排除 `deleted_at` 非空。本地检索直接读分块表，只删向量、留下分块，检索仍会命中，所以过滤必须加在这两处查询上。不改融合方式，也不改生效日期开关。

### 3. 审计

软删仍走现有删除路由上的审计调用。`details` 含 `tenant_id`、`document_id`、`action=delete`。同租户删除也带这三项，便于和物理清理区分。不写标题、正文、路径。

不新增审计动作枚举。该枚举文件不在本任务允许修改的路径里。物理清理复用同一个删除动作，`details.action=purge`。

清理发生在后台，没有请求对象。直接写审计日志，不经过依赖请求的审计函数。操作者可为空。

### 4. 保留期与物理清理

90 天写在 `app/rag/` 内的具名常量，并写入权限 ADR。不改配置模块，避免超出允许路径。

新增 `purge_expired_documents(session, *, now)`：

- 只处理 `deleted_at` 早于 `now` 减 90 天的行。
- 先按文档所属租户清理向量，再删源文件，再删文档行（分块随级联删除）。
- 未满 90 天的行不动。
- 每成功删掉一行写一条 `action=purge` 的审计。

导入调度器每一轮扫描顺带调用一次清理，这样不用改应用启动入口。测试直接调用该函数，并把 `deleted_at` 设到 90 天以前，不依赖真实等待，也不依赖调度器是否开启。

清理不提供 HTTP 接口，避免成员或管理员绕过保留期。

### 5. 前端

`DocumentOut` 增加 `deleted_at: string | null`。知识库列表默认不请求已删除行。租户管理员和系统管理员有「显示已删除」开关；打开后请求 `include_deleted=true`，行上用徽章标「已删除」。成员看不到这个开关。

不增加恢复按钮。

### 6. ADR

在权限 ADR 补一句：删除是软删除，保留期 90 天；期满物理清理并再次审计。角色矩阵不改。资源级 ACL 仍不在本任务。

### 7. 实施顺序

1. 把「删除后行消失」改成「行保留且检索不可见」，并补管理员可见、未满 90 天不清理、期满清理留审计的失败测试。
2. 加 `deleted_at` 列与软删实现，列表和详情按上表过滤。
3. 检索排除已软删文档。
4. 实现期满清理，并挂到导入调度器。
5. 前端类型与「显示已删除」开关。
6. 更新权限 ADR 的保留期句子。
