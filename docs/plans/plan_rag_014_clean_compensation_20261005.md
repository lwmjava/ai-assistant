# 清洗链与删除补偿实施计划

任务：RAG-014。状态：已开始事实核对与方案设计；删除语义待负责人确认，业务代码未修改。

## 目标与事实

上传链具备去重、保守格式规范化、质量评分与元数据提取；向量删除失败持久记录、可恢复重试并保持租户隔离。

- `import_jobs.py` 已对解析文本计算 SHA256，并按来源与版本去重，不重新发明去重机制。
- `service.py::delete_document` 只设置 deleted_at，保留分块、向量和源文件。
- `retention.py` 在软删超过 90 天后执行物理清理；向量删除异常后仍删除文档记录，缺少持久补偿目标。
- `import_scheduler.py` 已有周期清理入口，可承接补偿，不引入独立队列基础设施。
- 产品需求 §5.2.4 描述删除 DB 与向量；现有软删/保留期行为和测试是具体运行事实。需明确该目标描述适用于保留期后的物理删除，还是要求软删即删除向量。

## 建议方案

1. 保留软删与 90 天保留期。软删后不可检索，但不提前物理删除；软删验收覆盖不可见、保留和重复删除。
2. 在保留期清理前持久化向量删除意图，以 tenant_id、document_id、目标向量库标识确定任务。成功后完成清理；失败保留可恢复任务及必要文档记录。重试有次数/退避/失败状态，重启可恢复，重复执行幂等。需新增独立 ADR（拟 ADR-0006，创建前复核编号），现有 ADR-0001～0005 不构成删除补偿决策。删除语义确认后，细化表结构、迁移与恢复状态并形成 Proposed 草稿；获批准后才实施对应持久化与删除边界。
3. 在现有导入解析后、哈希与切分前运行保守清洗。仅规范化换行/BOM 等明确格式问题，保留缩进、代码围栏和盒图。质量分与版本、字符数、结构信息进入元数据，先不按未知阈值拒绝内容。保留源文件。

备选：软删立即清理向量，但会改变保留期恢复语义；或者仅依赖日志重试，但无法满足重启后恢复要求。推荐上述保留期方案。

## 原始文件、解析文本与清洗文本

“保留源文件”指原始上传文件字节，沿用源文件存储路径；不是清洗后文本，也不将整个二进制文件直接作为分块输入。原始文件不被清洗覆盖，受现有保留期与删除策略管理。

解析器输出的原始解析文本与 blocks 是清洗基线。清洗得到独立的派生文本，记录清洗规则版本、是否回退与派生内容 hash；切分消费经过结构校验的派生文本，失败时消费原始解析文本。源文件可重新解析，但解析器版本变化可能改变结果，因此不能仅以保留文件代替原始解析文本/结构基线与版本记录。

结构保护包含代码围栏、缩进层级、盒图对齐、表格/标题边界，以及文本与 blocks 的一致性。不得全局折叠空白或去除行首缩进；没有可靠结构映射时不修改该区域。幂等性必须由重复清洗样本验证，不能预先假定。

## 失败、风险与回滚

任务风险为 L2，side_effect 为 rag-clean-compensate。风险包括结构损坏、清洗 hash 漂移造成错误去重、解析 blocks 与清洗文本错位、补偿误删租户/向量库目标，以及迁移后回退导致补偿任务丢失。

- 清洗异常或结构校验失败：丢弃派生文本，回退到未清洗的原始解析文本及对应 blocks，记录规则版本和失败类别，不输出正文。校验发现异常时不能继续以损坏文本索引；回退后仍走既有导入校验。结构校验覆盖不能证明所有文档绝对安全，需配合代码、盒图等回归样本。
- 清洗规则发布后发现缺陷：回退清洗调用/规则代码，新导入使用原始解析文本；不自动重建历史索引。已生成的受影响索引由版本记录定位，负责人另行批准重解析/重建。保留原始文件能支持恢复，但代码回退不会自动恢复已经写入的索引。
- 向量删除或补偿执行失败：保留持久意图与必要文档记录，不提前删除恢复所需记录；重复执行前校验 tenant_id、document_id 与目标库，错误仅记录脱敏类别。重试上限耗尽后保留 failed 状态供人工处理，不静默丢弃。
- 补偿代码回滚：停止新增/消费补偿任务，保留任务表和待处理记录，不自动 downgrade 丢表。迁移前备份、兼容旧代码与重新启用后的恢复方式在新增 ADR 中明确；不可恢复已被物理删除的数据，不将代码回滚描述为数据恢复。

上述运行时保护均为计划，尚未实现或验证。
