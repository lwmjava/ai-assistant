# RAG-022 失败保护与计划校验修复方案

## 目标与现状

用户授权按关闭复审报告定位、提出方案、修复并进行一轮验收。正常计划重放已实现；当前旧块在计划校验/Embedding前被删除，任务异常处理提交同一事务导致失败后丢块。LocalVectorStore.delete_by_document还会隐式commit，不能拿它参与应用层原子替换。加载计划仅检查strategy，缺参混入当前默认、损坏参数报错。auto入口尚缺质量指标证据。

## 方案

1. 保留单张RAG-022范围。先写隔离内存库的真实导入任务失败回归，覆盖有效计划Embedding故障、坏计划、新会话重读旧块/plan/计数，取得业务断言失败。
2. 计划无值才走旧数据兼容；非空损坏/未知版本显式ValueError拒绝，不静默改配置。校验受支持版本、注册策略和完整有效ChunkParams（拒未知字段和错误类型/约束），递归校验child_params。服务端input_policy每次注入，不存入计划。不新建供应商或预算规则。
3. 在校验、切分、Embedding成功后再准备替换。Local同库不调用带commit的删除接口，应用Session承担一次替换；数据库持久化失败rollback。导入任务失败也rollback后单独记录失败，保留旧文档/快照/分块。外部VectorStore保持范围内能力，不宣称跨系统原子性；必要清理失败不得继续声称成功，用测试双取证，真实Milvus重建不在授权内。
4. 新增auto解析入口的可复算结构评估：使用RAG-021数据/评测器，公开比较范围，覆盖text、blocks、bbox和上传/重解析链；记录基线/候选、原文覆盖、结构破坏、顺序和长度。合成/Mock只证明结构链路，不证明检索质量。
5. 更新实现计划里过时缩减条款、实现说明、验收映射、回滚与tasks.yaml进度；自动验收有可复现证据后按本会话授权判断关闭，不要求重复人工截图。

## 独立审查追加根因与修复

独立审查发现真实 TextDocumentParser 的 blocks 是逐行 strip 后的辅助行块，auto 原先优先选 format_aware，会把 Python 代码缩进去掉。新增真实解析器评估先复现覆盖下降/结构破坏，之后加入 is_text_parser 事实信号：其辅助行块不触发 auto 格式/版式路由，正文按既有标题/结构/语言规则选择策略。Service 即使遇到显式 format 或历史 format 计划，也使用保真的正文 split，保留显式策略与参数。原解析器、Office/PDF 块规则不改。新增实际 parser→上传→新会话重解析完整内容断言，评估从 24 扩到 32 组；最终修改后重跑全库验收。

## 非目标与风险

不改默认策略、Embedding模型、检索/RRF、资源ACL，不自动重建用户文档，不迁移开发/生产数据库，不push/merge/deploy。坏计划会拒绝重解析而保留原文，旧NULL计划仍兼容。外部向量库跨系统切换的既有边界不在本轮扩为新架构，必须明确未验证风险。

## 文件与验收

主Agent修改service/import_jobs和计划校验模块及业务失败测试；评估Agent只修改evals与独立评估测试；审查Agent只读。文件均在RAG-022 allowed_paths。

验收：先红后绿；新会话有效参数重放、配置变化、旧数据、损坏/未知计划；Embedding及数据库故障保留旧块/计数/快照，失败任务记录正确；auto结构评估可复算；迁移在临时数据库验证；相关RAG回归、全库pytest、ruff、mypy；独立最终审查。未验证项目如实记录，必交付缺口不伪关闭。
