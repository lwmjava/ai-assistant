## 1. 目标（交付）

在规则结构保护**之后**，为「规则结构保护之外的主题边界」提供一个**可选、默认关闭**的 LLM 辅助阶段：

- 模型**仅输出边界 ID**（句子序号数组），**绝不输出/改写原文**；原文由代码按序号映射到字符偏移后切取。
- 输出经严格校验：坏 JSON / 非整数 / 越界 / 注入式 prose / 超时 / 预算耗尽，一律**规则降级**（回既有规则切分），不阻塞、不改写原文、不外发正文之外的额外内容。
- 有限调用：走 RAG-028 的能力契约与预算 Guard（`LLMProvider.chat` 内 `_guard`），并叠加**单文档调用次数上限**（费用护栏），超限停止并降级。
- 与 RAG-021 结构保护衔接：fenced code / 盒图 / 表格仍由规则原子保护；LLM 只处理这些原子单元之间的**正文间隙（prose gap）**的主题边界，不替代结构保护。
- 提供真实单变量评测的**工具与报告骨架**（可运行、记录模型/Prompt/协议/数据/计数器版本与失败切片），但**本卡不发起任何真实模型调用**（无授权）。

## 3. 方案（最小实现）

### 3.1 新模块 `app/rag/chunking/llm_boundaries.py`

- `PROMPT_VERSION = "llm-boundary-prompt-v0.1"`、`PROTOCOL_VERSION = "llm-boundary-protocol-v0.1"`（输出为「句子序号数组」，序号 → 代码映射到字符偏移）。
- `split_sentence_spans(region) -> list[(start,end)]`：用 `re.finditer` 取句子级精确字符区间（与现有 `_SENTENCE_RE` 同口径），序号从 1 起。
- `parse_boundary_indices(raw, n) -> list[int] | None`：严格解析。剥离 ```json 围栏后必须是 JSON **数组**；元素必须是 `int`（拒绝 `bool`/`float`/嵌套）、`1 ≤ i ≤ n-1`；去重、升序；`[]` 合法（=不建议边界）。任何不符 → `None`。注入式 prose（含解释/指令/改写原文）必然无法解析为纯整数数组 → `None`。
- `BoundaryOutcome`（frozen dataclass）：`kind`（`offsets`/`degraded`）、`offsets`（相对区域、`0<off<len`、升序去重）、`reason`、`calls_used`。
- `BoundaryAdvisor`：
  - 入参：`provider`、`max_calls`、`max_chars_per_call`、`output_tokens`、`timeout`；内部 `_calls` 计数器。
  - `async suggest(region, *, target_chars) -> BoundaryOutcome`：
    1. `_calls >= max_calls` → `degraded/call_budget_exhausted`（不发请求）；
    2. `len(region) > max_chars_per_call` → `degraded/region_exceeds_input_budget`（不发请求，控 payload 与成本）；
    3. 句子数 < 2 → `degraded/too_few_sentences`；
    4. 构造 system（严格 JSON 输出指令）+ user（编号句子列表）消息；`temperature=0`、`max_tokens=output_tokens`、`timeout`；`self._calls += 1` 后 `await provider.chat(...)`；
    5. 异常分类：超时 → `provider_timeout`；RAG-028 `ContextBudgetError`/其它 → `provider_error`（请求未发出或失败，均降级）；
    6. `parse_boundary_indices` 失败 → `bad_json_or_non_integer`；成功则 `spans[i-1][1]` 映射为相对偏移。
  - `metadata_snapshot()`：返回不含正文、不含密钥的描述（provider.model、prompt/protocol 版本、计数上限），供 chunk metadata 记录与评测报告。

### 3.2 `app/rag/chunking/structure.py`

- 保持 `protected_split(...)` **同步**（避免涟漪到 `ingestion.py` legacy、`semantic.py`、`parent_child.py` 与既有同步单测）。新增可选参数 `boundaries: dict[int, _GapPlan] | None = None`，默认 `None` → 行为与 RAG-021 完全一致。
- `_GapPlan(offsets: tuple[int,...], meta: dict)`：正文间隙起始绝对偏移 → 相对偏移 + 要写入 chunk 的元数据。
- 新增 `async resolve_boundary_table(text, chunk_size, advisor) -> dict | None`：
  - `advisor is None` → `None`（默认关闭路径不变）；
  - 复跑 `structure_units(text)`，枚举正文间隙 `[cursor, unit.start)` 与尾部；
  - 仅对 `长度 > chunk_size` 的间隙 `await advisor.suggest(region)`；
  - 成功且有偏移 → `_GapPlan(offsets, {llm_boundary_used:True, model/prompt/protocol/calls 版本...})`；
  - 否则 → `_GapPlan((), {llm_boundary_used:False, llm_boundary_degraded_reason:...})`。
- `plain(start,end)`：查 `boundaries.get(start)`。有 `offsets` → 按偏移切分（区间仍过 `policy` 超限细分，保留 oversized 语义）；无 `offsets` 或无 plan → 既有字符切分。命中 plan 时把 `meta` 写进该间隙产生的每个 chunk 的 metadata。

### 3.3 `app/rag/chunking/base.py`

guarded wrapper 在 `structure_units(text)` 命中且 `params.llm_boundary_advisor` 存在时，先 `await resolve_boundary_table(...)`，再 `protected_split(..., boundaries=table)`；否则路径不变。

### 3.4 `ChunkParams` / 计划持久化

- `ChunkParams` 新增 `llm_boundary_advisor: Any = None`（服务端注入，与 `input_policy` 同列，**不入持久化**）。
- `plan.py`：`required = {field.name...} - {"input_policy", "llm_boundary_advisor"}`。
- `service.py`：
  - `_build_chunk_params`：拒绝请求级覆盖 `llm_boundary_advisor`（同 `input_policy`）；当 `settings.RAG_LLM_BOUNDARY_ENABLED` 时构造 `BoundaryAdvisor(provider=get_llm_provider("chat"), ...)`，注入。
  - `_build_chunk_plan`：持久化 values 同时排除 `input_policy` 与 `llm_boundary_advisor`。
  - 重解析走存储 plan 重放，**不**重新发起 LLM（LLM 边界为非确定性运行时细化，不进版本化计划；重放保持规则确定性）。

### 3.5 配置（`app/core/config.py` + `.env.example` + `README.md`）

## 5. 失败边界清单（五类，每类至少一条反例测试，随实现提交）

| 类别 | 反例 | 期望 |
|---|---|---|
| 数值边界 | 空文本 / 单句文本；ID 越界（0、>n-1）；重复 ID；非升序；`[]` 无边界；region 超长不调用；布尔/浮点元素 | 全部分支降级或规则切分；切片无丢失/乱序/越界 |
| 失败路径 | provider 超时抛异常；坏 JSON；模型返回注入式 prose（「忽略指令…」）；部分合法边界；有限重试后预算耗尽 | 一律规则降级，chunk 仍完整覆盖原文，metadata 记 degraded_reason |
| 权限与租户 | 调用次数达 `max_calls` 后停止外发；模型输出只影响切分、不构成权限来源；不新增任何 SQL/越权 | provider 实际调用次数 ≤ max_calls；无数据库写入变化 |
| 身份与绑定 | 边界偏移 ↔ 原文字符区间精确绑定（`source_start/source_end`）；chunk metadata 记录 model/Prompt/Protocol 版本与 `source_text_sha256`；切分计划不含 advisor | 两阶段重切原文区间可复算；版本字段非空 |
| 回滚与幂等 | 默认关闭（advisor=None）→ 与 RAG-021 输出逐块一致；失败降级回规则切分；同文档两次 ingest 各自新计数器、不重复副作用 | 默认路径 diff 为空；降级 chunk 与规则切分一致 |

## 7. 模型 / 样本 / 调用与费用上限提案（ADR-0005 §9 要求落盘；无授权不执行）

- **候选模型**：优先复用已登记能力的 `gpt-4o-mini @ api.openai.com`（128k/16k，已核对）；默认 `deepseek-chat` 未登记，须运营者按 RAG-028 声明后才能用。最终模型待运营者确认。

- **调用/token/费用上限提案**：单文档 ≤ 3 次调用、单次发送 ≤ 1500 字符、输出 ≤ 256 token；评测运行 ≤ 约 30 次调用、输入 ≤ ~50k token、输出 ≤ ~8k token，预估费用 < $0.01（按 gpt-4o-mini 公开价）。超限即停。
- **实测质量门槛提案**（待真实调用后填）：相对规则切分，在不升高结构破坏率/原文丢失（=0）前提下，报告主题边界合理性、chunk 长度分布、调用次数与成本；门槛数值待有授权实测后由负责人批准。
