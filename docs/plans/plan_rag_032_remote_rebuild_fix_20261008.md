# 新索引重建远端写入与旧索引保护整改计划

任务：RAG-032；2026-10-08。原始契约、ADR-0008和临时库/测试collection授权继续有效。本计划不授权重建既有真实知识库或生产切换。

## 目标与现状

独立审计[收尾复核](../reviews/2026-10-08-RAG-032收尾复核.md)有两条真实红测：reindex_document_in_place只写SQL而不调用向量库add；且preparing重建先按旧active清理外部向量，破坏旧索引持续可读。此前74通过/1跳过没有覆盖这些链路，不能据此关闭。

目标是全新合成测试索引从prepare、全量rebuild、数量/身份/检索校验、activate到rollback可观察闭环，准备期间旧索引仍能真实检索，失败不得损坏旧active。

## 最小方案与边界

1. 把目标索引解析及身份校验置于远端清理前。preparing只清理同目标索引的既有派生向量/SQL块，绝不默认操作active。首次准备无旧目标块时无需清理。
2. Milvus写入允许显式指定已经登记的active/preparing目标，检查完整身份、块归属与维度；连接目标collection。默认上传路径保持现有active写入约定。禁止依靠临时改active状态向preparing写入。
3. 重建收集新DocumentChunk，在SQL提交前调用向量库写入；外部失败或SQL提交失败回滚SQL并登记明确补偿状态，不声明跨库事务。补偿只能作用于本次目标/本次新块；旧active集合不碰。重复重建同目标同文档不累积重复块。
4. 单元/契约用例先复制独立红测，并补同维异模型、目标错配、部分写入失败、重跑与回退断言。真实服务验证只用全新UUID测试collection和隔离SQLite；使用显式合成provider固定向量验证生命周期，不能称真实模型质量提升。保留产物，不删除已有collection。
