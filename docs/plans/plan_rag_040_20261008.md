## 1. 目标

在 `allowed_paths` 内，最小实现「独立状态摘要任务 + 分批合并 + 支撑原文 ID + 版本 hash/Prompt/模型绑定 + 失效与成本限制」，且**默认关闭**、**不另建摘要向量检索**、**不替代原文块**。

交付物（对应卡片 deliverables）：

1. 独立状态摘要任务（`SectionSummaryJob`，状态机：pending/running/success/partial/failed），可重入、有限重试。
2. 分批合并：大章节（父块）正文超单批预算时切批，逐批摘要，再合并成一条章节摘要；部分失败不影响原文检索。
3. 支撑原文 ID：每条摘要记录其来源的父块 ID 与喂入的子块/原文块 ID 列表（`source_chunk_ids`），供原文回查。
4. 版本 hash/Prompt/模型绑定：每条摘要记录 `document_id`、`source_version_hash`（= `Document.content_hash`）、`chunk_plan_version`、`model`、`prompt_version`、`protocol_version`。绑定任一变化即视为不可复用旧摘要。
5. 失效语义：源版本软删（`deleted_at`）、被替换（`is_current=False`）、跨租户时，摘要读取**立即拒绝**；不自行物理删除（沿源文档保留政策）。
6. 成本限制：所有摘要 LLM 调用经有界计数器（单任务 `max_calls`）与 RAG-028 预算 Guard；预算不足以发下一次请求即停。

## 2. 现状（代码事实，已核对）

- 文档版本：`Document.version_group_id / version_number / is_current / version_state / deleted_at / effective_at / expires_at / content_hash / chunk_plan`。`content_hash` 来自清洗报告 `original_hash`，是源内容身份；`chunk_plan` 是版本化 JSON（`version: "auto-routing-v0.1"`，见 `app/rag/chunking/plan.py`）。
- 大章节形态：父块 `DocumentChunk.chunk_metadata = {"kind":"parent"}`，子块 `parent_id` 指向父块，`chunk_metadata["kind"]="child"`（见 `app/rag/chunking/strategies/parent_child.py`、`tests/test_rag_030_*.py`）。
- 授权继承：`app/rag/access.py::can_read_document(doc, user)` 已统一拒绝软删、跨租户、非当前版；摘要读路径直接复用它，不另造权限。
- 受控 LLM 调用模板：`app/rag/chunking/llm_boundaries.py::BoundaryAdvisor`——注入 `LLMProvider`、有 `max_calls` 计数器、超时/坏输出降级、Prompt/协议版本常量、默认关闭、元数据快照不含正文。本卡沿用同一形状。

## 3. 方案

### 3.1 新增表（`app/models/rag.py`）

`SectionSummaryJob`（独立状态任务）：

- `id, tenant_id, document_id(FK), status, source_version_hash, chunk_plan_version, model, prompt_version, protocol_version`
- `calls_used, max_calls, chapters_total, chapters_ready, chapters_failed, error, attempt_count, max_attempts, timestamps`

`SectionSummary`（一条章节摘要，绑定到源版本）：

- `id, tenant_id, document_id(FK), chunk_id(FK rag_document_chunks.id)`（被摘要的父块）
- `source_version_hash, chunk_plan_version, model, prompt_version, protocol_version`
- `summary_text, source_chunk_ids(JSON)`（喂入的原文/子块 ID，供回查）
- `status(ready/failed), error, timestamps`
- 唯一可复用键：`(document_id, chunk_id, source_version_hash, chunk_plan_version, model, prompt_version)`——重跑时命中即跳过，不重复副作用。

### 3.2 服务模块 `app/rag/section_summaries.py`

- `ChapterSummarizer`（注入 `LLMProvider`，仿 `BoundaryAdvisor`）：
  - `max_calls`、`max_chars_per_batch`、`output_tokens`、`timeout` 构造；`calls_used` 计数。
  - `summarize_chapter(text) -> ChapterSummaryOutcome`：空文本→空摘要（不发请求）；正文超单批预算→切批逐批摘要→合并；任一批失败/超时/坏输出/预算耗尽→`failed`，已成功批保留但不冒充完整。
  - 每次发请求前调用 `enforce_generation_budget`；`capability is None`（无批准配置）→不发，标 failed/degraded。
- `create_summary_job(session, user, document_id) -> SectionSummaryJob`：校验 `can_write_document`（或读权限，创建任务属写操作）；取文档当前父块清单；落 pending 任务，记录绑定元数据。
- `run_summary_job_once(...)`：独立会话取 pending；逐父块生成；命中已存在且绑定一致的 ready 摘要则跳过；写 `SectionSummary`；回写 job 统计；全部成功=success，有失败=partial，无可用父块=failed。**任何 LLM/DB 失败只写 job/trace，不触碰原文块、不触碰检索路径。**
- `get_readable_summary(session, summary_id, user) -> SectionSummary`：加载摘要→加载其 `document`→`can_read_document(doc, user)` 必须为真，否则拒绝（软删/非当前/跨租户统一拒绝）。**不做物理删除**。

### 3.3 配置（`app/core/config.py` + `.env.example` + README）

- `RAG_SECTION_SUMMARY_ENABLED: bool = False`（默认关闭）
- `RAG_SECTION_SUMMARY_MAX_CALLS: int = 8`
- `RAG_SECTION_SUMMARY_MAX_CHARS_PER_BATCH: int = 4000`
- `RAG_SECTION_SUMMARY_MAX_OUTPUT_TOKENS: int = 256`
- `RAG_SECTION_SUMMARY_TIMEOUT_SECONDS: float = 20.0`

### 3.4 真实保真评价骨架（`evals/section_summary/`）

`run.py` + 报告 schema：给定一个**注入的合成 provider**，跑一遍「生成摘要 → 回查原文 ID → 绑定元数据记录」，报告写模型/Prompt/协议版本、数据指纹、调用计数、延迟，`human_review_status="pending"`。**不发起任何真实收费调用**；真实保真（人工对摘要 vs 原文）在本卡标「未验证（无调用授权）」。

## 6. 失败边界清单（五类，每类至少一条反例测试随实现提交）

1. **数值边界**：空章节（不发请求、空摘要或跳过）；超长章节切批边界（正文恰为单批预算整数倍/多一字符）；摘要 token 上限约束输出；预算不足以发下一次请求（`calls_used==max_calls`）即停，不发第 N+1 次。
2. **失败路径**：注入 provider 抛错/超时/坏输出→该章节 failed、job=partial、原文检索不受影响；部分章节失败不阻断成功章节；中断重入（重跑同一 job）命中已 ready 且绑定一致的摘要则跳过，不重复副作用。
3. **权限与租户**：他租户读摘要被拒；授权继承——源 doc 不可读（软删/非当前/他租户）则摘要不可读；越权可见性——摘要不出现在未授权主体的任何列表/回查。
4. **身份与绑定**：摘要↔源版本 `content_hash`/`chunk_plan_version`/`model`/`prompt_version` 绑定；支撑原文 ID 回查到真实块；源版本 hash 变化（重解析后 content_hash 变）时旧摘要对新 doc 不可复用（按 doc.id 绑定，旧版本随软删/非当前立即不可读）。
5. **回滚与幂等**：`RAG_SECTION_SUMMARY_ENABLED=False`（默认）时原文路径行为不变；重跑幂等（同绑定 ready 摘要不重算）；不执行任何物理清理。

## 7. 存储细化与费用/质量门槛提案（ADR-0005 §9 要求落盘）

- **存储细化**：摘要与任务存主库 SQLite（生产目标 PostgreSQL）；摘要正文为 Text，`source_chunk_ids` 为 JSON；不进向量库。沿源文档保留：源文档物理删除政策另案，本卡不删摘要。
- **费用门槛提案**：单任务 `max_calls=8`、单批输入 ≤4000 字符、单摘要输出 ≤256 token；超限即停并记 job。这些是**护栏提案**，未经真实费用测量授权，不得据此声称成本达标。
- **质量门槛提案**：真实保真（摘要覆盖原文关键事实、无幻觉、引用块可回查）需人工 Gold 复核；本卡只交付评测骨架与零容忍（跨租户/越权摘要读取硬失败）。**发布数值门槛待用户授权真实调用后另卡确定**，本卡不写死达标结论。
