## 2. 排序原则

1. 先解决旧版不可用、检索越权和故障伪装成无资料等 P0 风险。
2. 对有前置依赖的 P0，先做其 P1 基础卡；例如 032 必须先于 015。
3. 评测审核链前置，避免在来源/分级不清的数据上建立质量结论。
4. 先权限、索引身份、模型预算、上下文来源，再做父块扩展、缓存、LLM 边界和摘要。
5. 真实模型/样本/费用未授权、架构细节未锁定或外部前置未完成时保持阻塞；不因编号相邻而连续开工。
6. 一次只实施一张卡。下面的数字是建议选卡优先序，只有 tasks.yaml 的 depends_on 才是显式强制依赖；本清单不新增隐式任务依赖。
