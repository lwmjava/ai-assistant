## PRAG-002 重排落地：开关、灰度与开销评估

目标/交付：重排配置开关，默认关闭，可灰度启用；落地后的开销报告：重排引入的延迟与资源占用

方案：在 allowed_paths 内按交付最小实施，先失败测试/案例后修改；依赖：REL-004, NFR-002。准入：现无已批准采纳候选；新的采纳证据与负责人决定落盘前不可开工，REL-004 done 不构成准入。

验收：重排开关可配置且默认关闭，可灰度启用；落地开销报告含重排引入的延迟与资源占用增量；关闭开关时行为与基线一致

## RAG-019 LLM 响应与检索结果缓存（P2）

目标/交付：检索结果缓存：相同查询+参数命中缓存，不重复打向量库；LLM 响应缓存：确定性请求（temperature=0 等）可命中缓存省成本；缓存键包含租户、有效授权域、数据/索引版本；LLM 键包含实际上下文与模型/Prompt 版本；命中再授权。

现状：无缓存：相同查询重复打 LLM / 检索，热点场景浪费延迟与成本；全仓无 Redis，仅 config lru_cache 与局部 doc_cache。

方案：在 allowed_paths 内按交付最小实施，先失败测试/案例后修改；依赖：RAG-026, RAG-032。准入：复核事实与测试基线，范围可隔离后开工。

非目标：不引入 Redis 依赖（先进程内缓存，评估是否需要外部缓存）；不对非确定性请求（temperature>0）强缓存；不以 temperature=0 单独证明答案可安全复用。

验收：相同检索查询命中缓存，向量库调用次数下降；相同确定性 LLM 请求命中缓存，不重复计费；缓存不泄露跨租户结果；发布、删除、重解析和改权使缓存失效；同查询跨租户/不同权限不复用。

回滚：回退缓存提交。
