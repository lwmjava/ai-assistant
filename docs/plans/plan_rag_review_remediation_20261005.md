## 1. 范围与执行规则

覆盖评审四轮共 23 条编号观察，以及四项未形成任务闭环的能力。以下使用 A/B/C/D/E 前缀作本文映射编号，不是新增任务 ID。A 对应“优先修正”，B 对应“尚未形成闭环”，C/D/E 对应后三轮补充，保持原顺序。

本轮只新增本计划，不修改业务、已有任务状态或用户正在编辑的文件。既有 done 卡保留历史验收；新增范围另拆后续卡，不把已完成任务整体重开。拟新增任务仅有工作名称，正式拆分时核对唯一 ID 并同时更新 tasks.yaml 与拆分计划。不能依据本文直接超出某卡 allowed_paths。

实施前复核代码现状与失败复现；静态观察不等于已证实事故。依赖、配置/权限决定和测试环境就绪后一次只推进一条任务。每条实际实现另写功能说明与验证结果。未知发布门禁不临时猜数，不用 Mock/holdout 制造质量结论。

## 3. 实施工作包契约

下列为正式拆卡前的工作包。每包需分成一次可验证的单任务，不能并行改全部检索变量。

|---|---|---|---|
| W0 契约与事实整治 | A1/A2/A5/A6/A7/A8/C5 的任务描述、路径、准入、索引映射 | 不更改运行行为、不宣称修复完成 | YAML/唯一 ID/依赖校验、证据链接检查；保持用户未提交改动 |

| W3 自适应与重解析 | RAG-022：特征路由、父内切子、参数持久化、统一解析块入口 | 不强行路由十种、不同时加入语义模型 | 依赖 W2；A6/D2 真实样本对照；持久化变化先迁移设计 |

## 4. 决策与审批边界

- ADR-0005 尚 Proposed：W4/W5/W6 不开工；结构规则与策略参数持久化按现有架构逐项审查，涉及边界变更同样先决策。
- D5 的引用只读范围需权限 ADR；B4 ACL 明确 Deferred。D4 先确认已有 uploader 的批准定义，不能用“关闭配置”代替隔离修复验收。
- C2 先保留允许少返回；改补位须证据。C3 改独立稀疏召回、E3 失败自动降级 BM25 均是未批准策略，不伪装例行修复。
- NFR 性能、生产编排、多实例、审计保留由既有 NFR/OPS 卡承接，不在这里重拆整个企业计划。
- 工作包不等于新任务卡，批准拆分后必须同时写入 tasks.yaml；不得仅在对话或本文留实际执行任务。
