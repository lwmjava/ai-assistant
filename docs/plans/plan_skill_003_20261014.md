现状：ChatService 两种对话入口调用同步 _match_skills；manifests_for_chat 已过滤内置/全局/当前创建者私有技能，manager.match 仅关键词/正则/always。方案：新增异步 match_semantic 以现有 match 为先；没有确定性命中时用请求现有 intent provider 单次 chat 做严格 JSON 选择。ChatService 增加异步匹配入口，在两种对话路径传安全脱敏输入；保留同步 helper 兼容既有调用/测试。选中后沿用 activate、私有/全局不可信围栏、持久化及工具执行规则。

边界：候选最多32项，用户输入最多4096 UTF8字节，候选描述最多512字节，整体payload有界；输出最多1024字节；超时5秒，无本层重试，max_tokens128、temperature0；无候选/超限不拨模型；只发送名称、描述与脱敏用户请求，禁止技能正文/凭据/历史入选择prompt。候选中的models非空时必须含请求model，否则不参加语义候选。不建立额外缓存/可变全局状态。模型只能建议一个允许的技能名与有限confidence，未知名/多余键/重复键/NaN/越界/非字符串/多输出/非法JSON拒绝；阈值max调用阈值和trigger阈值。语义选择仅触发，不授予权限。

失败清单与反例：数值NaN/Infinity/bool/负数/>1；远端异常/超时/取消；跨租户或其他用户私有名/disabled；身份不存在、模型不适配、未选JSON；过长输入/候选数量/输出；注入候选描述；确定性命中零额外请求；失败保留原路径/重试不重复注册或写状态。CancelledError必须传播，不吞取消；其余失败仅固定分类日志，不记录正文。回滚撤销异步调用回同步匹配，无数据迁移。
