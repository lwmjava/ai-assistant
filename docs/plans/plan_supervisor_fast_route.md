# 对话路由：不需要工具和知识库的问题只生成一次

> 状态：已实现。说明见 `docs/plans/implementation_supervisor_fast_route.md`
> 日期：2026-10-01

## 目标

`AGENT_ORCHESTRATION=langgraph` 时，先用代码决定路径，再执行。不需要工具、也不需要知识库的问题只调用一次模型并流式返回。需要工具或知识库时只打开对应的一条短路径。只有明确要求多轮调研的请求才进入 Supervisor，并且撰写只发生一次，调研最多两轮，每轮调研只是一次模型调用。

## 现状

- 配置为 `langgraph` 时，每条消息都进入 Supervisor。`run_stream` 先等整张图结束，再回放 token。
- 调研节点复用行动循环，最多 `AGENT_MAX_TOOL_ROUNDS` 轮，可能调用真实工具。
- 撰写之后还会回到调度节点。模型若反复输出 `draft`，撰写没有上限。
- 自研五阶段管线有理解之后的是否分流，但失败时会升到完整管线。本轮不改这条默认路径。

## 方案

路由只看用户原文里的明确说法，不另做一次模型分类。认不出就按简单问题。

| 路径 | 打开条件 | 执行 |
|---|---|---|
| 简单 | 没有下面任一说法 | 一次 `stream_chat`。不理解、不规划、不检索、不调工具、不反思、不进 Supervisor |
| 工具 | `算一下`、`帮我算`、`计算一下`、`计算器`、`运行这段代码`、`执行这段代码`、`代码沙箱`、`现在几点`、`当前时间`、`今天几号` | 只列出点名的工具，行动循环最多 2 轮 |
| 知识库 | `知识库`、`根据文档`、`根据资料`、`查一下` | 检索一次再生成一次。没有检索器或检索失败时改为简单回答 |
| 多轮 | `先调研`、`分步调研`、`多轮` | Supervisor。调研节点一次模型调用，最多 2 轮；撰写后直接结束 |

同时命中时，工具优先于知识库，知识库优先于多轮。这样「先调研知识库」走一次检索，而不是整张图。

Supervisor 的撰写边不再回到调度节点。调度结果只要不是「仍可继续的调研」，就进入一次撰写然后结束。

默认 `AGENT_ORCHESTRATION=self` 仍走现有五阶段管线。

一次远程模型调用做不到毫秒。本轮去掉的是多轮编排带来的分钟级等待。重复问题的缓存、额外记忆和按节点换模型不在本轮。

## 非目标

- 不改 `.env`，不把默认编排改成 `langgraph`。
- 不加回答缓存，不改记忆压缩，不按节点配置不同模型。
- 不把进行中的节点改成逐 token 推送。
- 不持久化分派记录。
- 当前工具箱没有文件读取工具，不因为「文件」二字打开工具路径。
- 不把 Supervisor 标成 `Implemented`。

## 验收

- 「一个agent应用平台系统需要具备哪些功能？以一个企业上线的项目作为衡量标准」判定为简单问题，只产生一次模型流式调用，检索器和工具循环都不运行。
- `算一下 1+1` 只允许 `calculator`，行动循环不超过 2 轮。
- `根据知识库回答` 只检索一次。没有检索器时改为一次直接回答。
- `先调研再写` 才进入 Supervisor。模型连续要求撰写时，分派记录里只有一条撰写。连续要求调研时，调研最多两条，然后一条撰写。调研提示词里不再走执行器的工具循环。
- `AGENT_ORCHESTRATION=self` 时仍构造五阶段管线。
