## 1. 锁定规则

1. 一条能力只有在差距表对应行的「1.0 还要补上」全部成立，并且命令输出可复现时，才算完成。
2. 完成后立即锁定：验收原文、默认行为和失败行为都记在实现说明里。之后不得把这条验收改小。新需求另开版本。
3. 主路径可用、验收没齐，保持 `Partial`，不得标完成，也不得锁定。
4. 第 3 表里还没写出判定的项，以及第 4 节尚未核对的项，不排进实现。先补判定或取证。
5. 级别为 `未定` 的行，阶段 0 没有书面裁决之前不得开工。
6. 1.0 锁定清单全部通过，并且 pytest、ruff、mypy、前端类型检查、Vitest、ESLint、前端构建退出码都为 0 之后，打附注标签 `v1.0.0`。标签说明只写这一版锁定了什么。打标前不把 `Partial` 算进 1.0。
7. 一次只把一条卡改成可开工。第 4 节与其他章节缺口卡均已追加为 `backlog`；对照见 `docs/plans/plan_v1_section4_card_ids_20261003.md` 与 `docs/plans/plan_v1_other_chapters_card_ids_20261003.md`。

产能按原排期：每个工作日约 5 小时，七成用于实现。阶段 0 若拖延，后面的日期整体后移，锁定清单不删项。

八项 P0 是功能范围。§4.5 的 11 条是验收清单。两者交叉，不是包含。
