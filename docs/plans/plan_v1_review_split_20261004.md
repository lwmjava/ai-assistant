## 0. 背景与原则

评审结论：9 域功能主路径基本都在，但无一个达到企业级 "已就绪"；失血点集中在网关（错误码 / SSE / 日志）、MCP（超时 / 权限 / 审计）、Agent（工具治理层）、沙箱（隔离深度）、记忆（持久化 / 治理）。本计划按 "可独立验收的单元" 拆，拆开职责混合卡，对 "无验收先实现" 的域先补验收定义，并显式连发布门禁依赖链。

本次改动范围：



* **新增 4 卡**：`MCP-REQ-001`、`SAND-004`、`MEM-002`、`MEM-003`

* **修改 3 组卡**：拆 `SAND-003`（并入 `LLM-001`）、重定性 `RAG-015`、降级并挂依赖 `PMCP-001/002/003`

* **连发布门禁依赖链**：`NFR-001 → QA-005 → COV-001 → REL-005`

* **已核对无需改**：`FLOW-003`（现状即 backlog/P1、facts 已写明 cron 走不到执行，与评审修正后一致）

* **第二轮补充（2026-10-04）**：新增 `PROMPT-001`(P0)/`SKILL-003`(P1)/`SKILL-004`(P1)；降 `NFR-003`/`NFR-009` 为 P2（见 §6）

## 1. 新增卡

### 1.1 `MCP-REQ-001` — MCP 产品验收定义（补 PRD §5 章节）



* **问题**：PRD 第五章无 MCP 章节，`PMCP-001/002/003` 在无产品验收下标 P0，存在 "能力先于验收上线" 的隐患（与评审 §2.8/§3.2 一致）。

* **交付**：补 PRD §5 的 MCP 章节，含可验收口径 —— 调用超时默认值、权限 / 风险分级口径、审计字段、凭据存储要求。

* **非目标**：不实现代码；不定技术方案。

* **验收**：PRD 新增 MCP 章节，四个验收项（超时 / 权限 / 审计 / 凭据）各有一条可判定的标准，能作为 `PMCP-001/002/003/004` 的验收依据。

* **状态**：backlog / **P1** / 无依赖（先行于 PMCP 各实现卡）。

* **用户决策**：认可 "先验收后实现" 顺序，MCP 域从 "无验收却标 P0" 改为 "先定义验收（P1）再实现"。

### 1.2 `SAND-004` — 沙箱隔离深度：非特权用户与网络隔离



* **问题**：沙箱缺 chroot / 非特权用户 / 网络隔离；`_BLOCKED_IMPORTS` 注释自认 "SKELETON：尚未覆盖完整"，且 "沿继承链拿到文件能力" 的绕过未处理（评审 §2.3）。

* **交付**：非特权用户运行、网络隔离、补全 `_BLOCKED_IMPORTS` 覆盖；Linux 实机记录。

* **非目标**：不做容器级隔离（未来）；不引入第三方沙箱。

* **验收**：以非特权用户运行被限制；网络访问被阻断；越权模块被拒；有 Linux 实机记录。

* **状态**：backlog / **P1** / depends\_on `SAND-003`。

* **用户决策**：现在就开 P1 卡。

### 1.3 `MEM-002` — 记忆增量压缩接线（existing\_snapshot）



* **问题**：`chat_service._build_memory` 每次从 DB 读全部消息且未传 `existing_snapshot`，`compressor` 已写好的增量压缩从未启用，长会话每次请求重算全部历史（评审 §2.9）。

* **交付**：`_build_memory` 传入 `existing_snapshot`，启用增量压缩；长会话第二次请求基于快照而非全量重算。

* **非目标**：不做跨会话记忆；不做记忆检索；不改压缩算法。

* **验收**：长会话后续请求复用快照；压缩结果正确保留最近消息（`keep_recent`）。

* **状态**：backlog / **P1** / 无依赖（低成本修正，可立即开）。

* **用户决策**：立即开。

### 1.4 `MEM-003` — 记忆治理：谁能读 / 存多久 / 如何删 / 防串租户



* **问题**：记忆授权 / 期限 / 删除 / 租户隔离治理完全空白（评审 §2.9，差距表第 3 表）。

* **交付**：记忆治理规则 —— 谁能读、存多久、如何删、如何防串租户。

* **非目标**：不实现跨会话记忆本身（PRD §5.7 排 v1.5）；不重复 `MEM-002` 的接线工作。

* **验收**：治理规则明确并落文档 / 代码校验；四条（读权限 / 期限 / 删除 / 租户隔离）各有判定。

* **状态**：backlog / **P2** / 无依赖（跨会话记忆排期时开）。

* **用户决策**：开卡；排期在 agent/rag/prompt/ 沙箱 /mcp/workflow 之后，但属核心能力，不可排到很晚 —— 定位为**打标后第一批（跨会话记忆排期启动即开）**，不拖到远期。
