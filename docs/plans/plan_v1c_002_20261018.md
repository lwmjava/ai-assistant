# V1C-002 统一各对话路径的工具执行入口实施计划

日期：2026-10-18。状态：已按原始任务卡与已批准拆分计划实施，不另造执行器。原始依据 `tasks.yaml` 的 V1C-002，以及 `docs/plans/plan_v1_chat_chain_closure_20261016.md` 同卡章节。用户授权读取 `docs/ai-prompts/skills/task-card-delivery/SKILL.md` 并开发本卡。该授权包含范围内实现、测试和文档；不包含提交、推送、合并、部署、生产操作或付费模型调用。用户没有把可自动验证的人工业务验收明确交给 Agent 代为关闭，因此自动验收通过后仍保留未完成状态，交用户决定。

## 目标与非目标

目标：默认管线与工具短路径执行同一工具时，身份、参数、超时、有限重试、预算计数和审计都走已有 `ToolExecutor`。路径之间只保留工具选择和轮次上限这两项已有有界策略。

非目标：不新建执行器，不扩大工具权限，不把 MCP 未治理工具补成完整契约，不改 Supervisor 的工具执行（V1C-004），不改技能接线（V1C-003），不改检索依赖（V1C-001）。

## 当前事实

- ADR-0010 已 Accepted。决定 1 把参数校验、超时、有限重试、权限委托和审计聚合放在 `ToolExecutor`；`ToolRegistry.run` 只有绑定执行器后才薄委托，否则仍是不含重试、不含严格校验的兼容实现。
- `ChatService._wire_runtime` 给默认自研管线赋值 `pipeline.executor`。工具短路径在 `iter_fast_path` 里新建 `AgentPipeline` 且不赋值，`_execute_tool` 因此落到 `tools.run`。
- 结构化计划路径 `plan_runtime.iterate_plan` 在执行器缺失时会自己构造 `ToolExecutor`。本卡不改这条已统一的计划执行。
- 短路径轮次上限仍是 `_TOOL_ROUND_CAP = 2`；默认管线使用 `max_tool_rounds`。这是有界策略差异，不是第二套执行规则。重复指纹、越出允许工具名、取消传播仍由同一个行动循环处理。
- 内置工具 `max_retries=0` 且 `strict_validation=False`。接到执行器后，计算器等既有成功文案不变。
- 前置 PAGT-006 为 done，执行器文件当前 SHA256 `dfd8203bf477ad0709a0fcbdd081c75a2313eb8a3756aa3135334424c3f233e6`。前置 RAG-044 为 done，`app/rag/service.py` 当前 SHA256 `df1bf2f720eec05613cc604a09c0022c5a054fbecd2bd222e02948a37c1628e6`。两条前置都不是本卡要改的检索或执行器算法。未发现指向这两张卡的未决 P1 审查阻断本卡接线。

## 方案

在工具短路径创建管线后，用同一注册表构造 `ToolExecutor` 并赋给 `pipeline.executor`，与 `_wire_runtime` 相同。`_execute_tool` 在注册表存在但尚未注入时也构造这一执行器，避免短路径或默认管线再落入不含重试的 `run()`。`ToolRegistry.run` 未绑定执行器时保持兼容实现，供既有 golden 对照；对话行动循环不再调用它。

不改权限判定函数、审计字段、观测拼装、轮次上限数值、允许工具名策略或 MCP 放行规则。Supervisor 仍不注入。

ADR-0010 追加 2026-10-18 补记：这是决定 1 的调用点补齐，不新增执行器、表或权限。未注入的 `Registry.run` 继续只服务直接调用和 golden 对照。

## 失败边界清单

| 类别 | 反例 |
|---|---|
| 数值 | 超时上限被遵守且不继续重试；幂等瞬时失败的尝试次数等于 `max_retries + 1`，不会超过；非有限数值由工具终态返回，不记成功 |
| 失败 | 工具抛错、超时、远端式连接错误分别给出 error/timeout 与有限重试；一条逻辑调用只写一条审计 |
| 权限与租户 | 未认证、缺少租户、伪造 `tenant_id`/`user_id`、角色不允许时函数零调用；审计 `allowed=false` |
| 身份与绑定 | 审计上的用户和租户来自日志上下文，不来自工具参数；短路径允许名单之外的工具不执行 |
| 回滚与幂等 | 重复指纹不第二次执行；取消向上传播且不留下成功审计；失败重试不额外插入成功审计 |

## 等价计划审查

`plan-eng-review` 技能要求交互式逐条向用户确认。本卡方案已由拆分计划和 ADR-0010 决定，任务交付技能要求常规技术选择连续执行。因此按架构、兼容、权限、失败路径、测试、性能做等价审查，不宣称跑过该交互技能。

- 架构：复用现有执行器，不新增层。Supervisor 保持原边界。
- 兼容：内置工具重试次数为 0、严格校验关闭，观测格式不变。`Registry.run` 的未绑定实现保留。
- 权限：仍调用 `_denied_reason`，不放宽角色、租户或伪造参数。
- 失败：超时、拒绝、非法参数、取消和重复调用都有终态，不新增重试类别。
- 测试：两条真实入口共用断言；单测执行器不能代替入口。
- 性能：只多一次执行器对象构造，不增加模型调用或默认重试。
