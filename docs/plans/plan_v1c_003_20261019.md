# 技能跨编排路径接线实施计划

2026-10-19。任务原文为 tasks.yaml 的 V1C-003；用户输入 V1C-0003，按任务表唯一对应卡处理。状态：方案待批准，尚未修改业务代码。用户要求使用 task-card-delivery 技能开始实现；本卡没有 allowed_paths，且 L2 执行边界尚未裁决，先完成事实核对与可评审方案。

## 1. 目标与当前事实

原始交付：技能Prompt与工具模式接线；匹配、注入及实际执行的状态和版本证据。原始验收：默认管线、短路径、Supervisor有明确支持矩阵；工具绑定被消费，缺失或无权限工具有明确结果；私有隔离、版本、撤权、不可信围栏通过。

- ChatService已按授权技能清单最多匹配一条，异步选择后复核主体及技能有效版本，私有/全局Prompt已有围栏。SKILL-003的匹配算法和选择次数不重做。
- 默认管线及fast路径已有Prompt注入；Supervisor构造未传入技能Prompt，research/draft实际不消费。
- SkillContext已有tool_names及versions，SkillManager.collect_tools可从注册表解析绑定，但ChatService未消费工具模式绑定。
- V1C-002已经使默认/短路径共用ToolExecutor；本卡不新增执行器，不绕过其权限、参数、预算、超时、重试和审计。
- 显式执行器可能由_wire_runtime使用完整注册表注入，单纯过滤另一个registry不足以约束执行；结构化计划还会直接调用执行器，必须覆盖两个入口。
- checkpoint含计划和进度，却没有技能来源/有效版本绑定。恢复后虽重新获取检索上下文，旧understanding/plan/tool_results仍可能来自已变更或撤销的技能，不能只重新匹配后继续。

## 2. 方案比较与推荐

A（推荐）：保持路径选择与既有权限不变，传递授权快照及运行状态；工具绑定只收窄现有路径可用工具；Supervisor只支持Prompt模式，注入research/draft；不支持的工具模式显式说明。恢复需精确版本绑定，冲突拒绝续跑。

B：技能触发后重写路由，并把绑定工具并入路径白名单。可执行范围扩大，且知识库/工具组合与Supervisor执行会跨到V1C-004/005，不选。

C：只给Supervisor追加Prompt和技能名，不处理绑定、执行状态和checkpoint。不能满足原始交付，不选。

本计划与Proposed ADR-0014整体批准后才编写失败测试及最小实现；不将本文件当成已经获得架构批准。

## 3. 支持矩阵与具体行为

| 实际路径 | Prompt模式 | Tool模式 |
|---|---|---|
| self完整管线（含结构化计划） | 使用已围栏的授权Prompt及版本 | 解析collect_tools，当前路径允许集与绑定集取交集；计划/执行两处校验；ToolExecutor保留最终权限判断 |
| self preflight短路 | 保留Prompt注入 | 只支持原短路白名单内绑定；空交集显式无可用绑定，不放宽白名单 |
| fast TOOLS | 保留Prompt注入 | route.tool_names与绑定集及已注册工具取交集；缺失工具有明确结果，空集合不得回退全部工具 |
| fast SIMPLE/RAG | 保留Prompt注入 | 明确不支持当前路径执行工具绑定，不冒称工具执行；不改变路由或增加检索/工具组合 |
| Supervisor | 只注入research/draft，不进入调度决策Prompt | 明确暂不支持，函数零调用，不把匹配名称当执行成功 |
| langgraph未安装回退 | 沿用self对应规则 | 沿用self对应规则，不绕过执行器 |

绑定不授予权限，不自动执行全部绑定工具，不扩展工具注册范围，不替代模型动作选择。同一个技能只选一条；Prompt模式不会额外改变原工具清单。工具模式下模型只看到有效交集，但即使伪造计划或调用其他注册工具，执行前仍须拒绝。

匹配、已注入、绑定可用、路径不支持、绑定缺失、执行成功/拒绝/失败/取消要区分。使用当前请求的安全元数据记录名称、origin、effective_version、实际路径及状态；不记录Prompt正文、参数或异常原文。缺失/不支持情况向用户给出确定性说明；执行结果沿用既有工具事件和审计，不只凭skill_names宣称成功。没有执行行为时不得记录executed。

匹配异步返回后，以及每次向模型注入技能、每次新工具执行之前，由Service提供的窄回调重新核对技能enabled、origin、effective_version及当前授权；Agent只调用回调，不放SQL。覆盖工具1成功后停用技能、工具2零调用的反例；结构化计划直接执行前同样调用。版本或主体失效时不继续消费旧Prompt/绑定。这是离散执行关口，不做逐token或后台轮询，不新增持续授权监控；已开始的工具动作不承诺可撤回。额外成本为这些关口的只读校验，不增加模型匹配或重试。

## 4. checkpoint与兼容

利用现有state_json添加有界、可校验的技能绑定元数据，不新增表/迁移。绑定包括是否无技能、有效身份版本/来源及请求内工具约束；不存正文或密钥。恢复前比较当前授权快照，再应用旧计划；不一致时固定拒绝并要求重新发起请求，不自动丢弃旧进度后执行已有副作用工具。

旧checkpoint缺绑定不能证明历史技能是否已撤销，采用保守兼容：明确拒绝恢复，保留记录，不自动重跑。恢复冲突必须用可识别的拒绝异常穿透_restore/run现有宽捕获；在任何新模型/工具调用前结束，不覆盖旧checkpoint为done/error，不把冲突当损坏数据discard或全新run。无技能的新快照也写显式空绑定。新增字段不能通过布尔/NaN/Inf/畸形容器绕过校验；原已执行指纹、工具预算和计划进度保持。该兼容变化须在ADR和运行说明中明确批准。
