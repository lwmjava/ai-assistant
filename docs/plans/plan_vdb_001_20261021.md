## 目标、现状与非目标

目标是空库默认使用 Milvus，首次上传完成索引登记、写入和检索；删除、重解析、租户隔离与索引身份有真实服务证据。
当前配置仍为 local，factory 对非 milvus 值返回 local，容器默认依赖与生产编排检查仍以 local 为前提。
已有 Milvus 适配与索引登记不能代替默认链路验收。

不实现 Lite（属于 VDB-002）、Chroma、重排、Query Rewrite、新稀疏召回架构；不清库、不迁移存量、不调用收费模型、不修改生产环境或发布 Git。
不删除冻结 local 评测；显式 local 仍用于隔离测试和离线评测。

## 准入缺陷与请求决策

独立审计在当前 HEAD 实跑 225 项专项通过，但 5 条领域边界反例失败。详见
[依赖审计](../reviews/2026-10-21-vdb-001-dependency-admission.md) 和
[独立工程审查](../reviews/2026-10-21-vdb-001-plan-review.md)。

1. 远端候选回查缺少 SQL 层 Document/Chunk 租户约束，合成外租户候选可以返回外租户正文。
2. 激活探针通过 SQL 向量 NumPy 自匹配，不能证明 Milvus 可读；部分重建也能激活；探针忽略调用 Session 绑定。
3. 评测脚本 `scripts/rag_hybrid_embedding_check.py` 接受同维但响应模型不符的结果。此反例测试的是评测脚本，不能冒领为真实 provider 已复现。
4. 真实 provider `app/rag/embeddings/openai_compatible.py` 静态可见同类响应身份缺口，须补独立真实入口隔离反例后确定修复。
5. `scripts/check_production_compose.py` 强制要求生产默认 local、仅 app/db 和默认不安装 Milvus，与本卡目标冲突。

推荐在本卡内先承接上述准入修复，再切默认；保留历史依赖卡的 done，不以历史状态证明本次准入。
请求将以下三个精确路径加入本卡 allowed_paths：

- `scripts/check_production_compose.py`：更新部署契约断言，保留既有安全保护。
- `scripts/rag_hybrid_embedding_check.py`：修复已复现的评测响应模型身份反例。
- `app/rag/embeddings/openai_compatible.py`：补真实入口反例并收紧响应身份核验。

这些路径尚未扩入任务卡，尚未修改；不扩整个 embeddings 或 scripts 目录。
响应模型策略建议：显式不符则拒绝；缺省响应或提供商别名不冒称已验证，先核对供应商契约，任何例外须有显式映射和测试。
如该策略改变现有批准的兼容要求，先记录 ADR 冲突再决策，不静默放宽。

## 恢复实施后的方案与顺序

1. 将已复现缺陷转为正式 tests 回归；增加真实 provider 响应身份反例，保留反例输入与最终指纹。
2. SQL 候选回查同时限制主体租户、Document/Chunk 租户与归属；不信任远端返回的 ID。
3. 激活使用调用 Session 的绑定和目标索引身份，先验证重建完整性及实际目标后端可检索，再提交 active/retired 状态；失败保持原 active，有限超时、明确错误且可重试。禁止用修改计数把不完整重建变成成功。
4. 修订 ADR-0002，锁定默认 Milvus 与首次摄取登记；配置 factory 仅接受已声明枚举，未知值报配置错误，连接失败不退 local。沿用现有 SDK 与服务版本，不借机升级依赖。
5. 默认构建安装既有 Milvus extra；开发/生产默认 Compose 纳入内部 Milvus、etcd、MinIO 依赖，保留健康检查、持久化和安全配置。默认启动命令能独立运行，不要求用户暗中补覆盖文件。
6. 首次摄取明确登记索引身份、写入和完成状态；失败不得假成功，不引入破坏性自动重建。普通非检索请求不强连 Milvus；检索故障返回 unavailable，不能转换成 no_hit。
7. 更新健康状态、README、配置示例、生产运行手册与 ADR。显式 local 测试使用隔离 fixture；新默认验收独立构造未覆盖设置，禁止全局强制 local 掩盖默认行为。
8. 跑真实 Standalone 闭环、回滚与独立复核；最终完整检查、Ubuntu 同 SHA CI、任务关闭对账及技能要求的独立人工审核。未获代行人工业务验收授权时不自行 done。

不新增表或外部 API 字段是初始设计假设；若具体实现必须改变 Schema/异常契约，先对照任务范围、补契约测试和文档，不绕过现有 Service。
Milvus 候选窗口后再做 SQL 可见性过滤，可能使有效候选不足；BM25 在候选窗口内计算，不声称等价全库稀疏召回或 local 排名。

## 失败边界清单

- 空库、重复上传、重复删除、重解析后旧向量、重试幂等与部分写入。
- 远端断连/超时、SDK 缺失、未知配置、错误 collection、错误模型/维度/索引身份。
- 重建缺块、计数漂移、激活中途失败、事务回滚与原索引保留、调用 Session 不同数据库。
- 外租户候选、文档与块租户不一致、删除/非当前文档、空候选与 unavailable 的区分。
- 非有限向量、零向量、维度不符、响应模型缺省/别名/不符；不得用数值异常制造激活成功。
- 非检索请求不受无关后端故障拖累；取消、超时、重试不重复登记或切换。
- 回退默认配置不清数据，不承诺 local 自动接管 Milvus 数据；Lite 不在本卡。
