# VDB-002 实施计划

日期：2026-10-21。状态：开始实施。前置卡仍是 `in_progress`，本卡不能据此关闭。

## 契约

| 原始要求 | 操作链 | 可观察期望 |
|---|---|---|
| 服务可用时优先 Standalone | 启动探测返回就绪 | 选择 standalone，不创建 Lite 文件 |
| 仅不可达或未就绪可兜底 | 本机开发地址探测为拒绝或超时 | 选择 Lite 并记下原因 |
| 配置、身份、Schema、凭据错误拒绝 | 探测结果为 auth/schema/config | 抛出选择错误，不改登记 |
| 生产与远程地址禁止 Lite | 生产环境或非回环地址 | 不可达也失败 |
| 进程内固定，重启不因 Docker 恢复换库 | 已登记 Lite 后再次选择 | 仍是 Lite |
| 归属不一致拒绝而不是空命中 | 索引存储与当前模式不同 | 读路径报不可用 |
| 真实 Lite 闭环与 Linux 证据 | 真实文件库摄取 | 当前 Windows 无 Lite 运行库，未验证 |

## 方案

启动时调用一次选择函数。探测由调用方注入，默认实现只用于进程启动。选择结果写入单行登记表，并用另一张表记住每个 Milvus 索引属于哪个实例。检索前比对，不一致就拒绝。

不逐请求换库，不在运行中把故障自动降级，不双写，不升级 `pymilvus`。

## 失败边界

- 数值：探测超时与零超时归为未就绪，不归为鉴权成功。
- 失败路径：不可达可兜底；Lite 运行库缺失、鉴权失败、Schema 错误、生产环境失败都不兜底。
- 权限与租户：沿用现有租户回查；本卡不放宽读范围。
- 身份与绑定：已登记 Lite 不被后来的 Standalone 就绪覆盖；索引存储不一致拒绝。
- 回滚与幂等：重复启动不另建一条模式；失败不写入新登记。

## 非目标

不实现显式切回 Standalone 的迁移工具，不删除 Lite 文件，不把 WSL 结果写成原生 Windows 通过。

## 前置复核

VDB-001 当前提交仍缺少真实 Standalone 闭环、全量 pytest 和 Linux CI。本卡不把该缺口写成已闭合。
