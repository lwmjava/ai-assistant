## 推荐设计

- 默认选择 Milvus，复用现有 VectorStore 接口，不引入 Chroma。
- 应用主库继续管理身份、文档、分块、版本、任务及审计；Milvus 承担向量索引和稠密检索。
- 默认开发部署启动 Milvus 及必要依赖，使用持久化卷，记录启动、停止及就绪检查方式；远程 Milvus 地址可配置。
- 空库首次上传可正确登记索引、写入并检索，不要求用户先使用 local 建库。
- 生产环境 Milvus 不可用时明确报告检索不可用，不自动切回 local 或 Lite、不把故障包装成无命中；普通非检索路径保留既有隔离行为。开发环境启动兜底按下节执行。
- 保持已有混合检索行为并披露候选窗口限制；本批不自动引入独立稀疏索引，不宣称切库带来质量提升。
- local 暂限显式隔离测试及冻结历史评测；不是正常部署选项或自动容灾。删除其全部代码另行立项。
- 不执行存量迁移，不重建或清理现有数据库。运行验证使用独立测试库、独立集合。

## 开发环境 Milvus Lite 启动兜底（用户追加需求）

本节为追加设计，尚未完成平台准入验证或业务实现。Lite 是 Milvus 本地文件部署形态，不恢复 SQLite + NumPy 自研向量检索。

- 仅显式开发环境开启启动兜底；生产必须禁用，显式远程服务地址不触发本机 Lite 兜底。
- 启动时对配置的本机 Standalone 做有限时长的就绪探测；仅连接不可达/服务未就绪允许选择 Lite。鉴权失败、索引身份错误、Schema 错误和配置错误不触发兜底，避免掩盖真实故障。
- 选定后在本次运行固定后端；服务恢复不自动切回，运行中故障不逐请求换库。后续启动须识别先前选择的数据归属，不能仅因 Standalone 恢复就自动切换。
- Lite 使用持久化文件；健康状态和日志明确实际模式、兜底原因及可用性，不记录凭据。数据库中的索引登记必须区分 Standalone/Lite 存储实例，缓存身份亦需区分。
- Standalone 与 Lite 不共享数据。仅空的开发知识库或已明确归属 Lite 且身份核验通过的数据可自动进入 Lite；存在 Standalone 文档而 Lite 缺向量时报告未就绪，不返回空结果伪装无命中，不静默创建已可用状态。
- 从 Lite 切回 Standalone 需要显式切换并通过目标索引完整性验证；本批不实现双写、同步、自动重建或重要数据删除。用户已免除历史迁移，但兜底后产生的新测试数据仍须有明确归属。
- 先在项目声明的 Python 环境验证现有 pymilvus==2.5.11、ORM Collection/连接接口、Lite 版本、索引类型和平台支持。Lite 的索引能力不假定与 Standalone 的 AUTOINDEX/IVF 参数一致。Windows 若缺兼容包，记录阻断并提供显式 Lite 开发模式的 WSL/Linux 运行说明，不在失败后重新退回 local；不默默升级依赖或宣称原生 Windows 已支持。
- 新增验收：空库无 Docker 时 Lite 摄取/检索/删除/重解析及重启持久化；服务运行时优先 Standalone；进程内固定后端；重启不静默跨库；生产拒绝兜底；鉴权/身份/Schema 错误不降级；Lite 不可用报错；存量归属不一致拒绝；租户与引用契约不退化。真实 Lite 与真实 Standalone 证据分别记录。

备选方案：若启动自动选择显著增加索引生命周期复杂度，则用显式 standalone/lite 开发模式，复用同一 Milvus 适配接口。这一备选不作为未经确认的默认实现。
