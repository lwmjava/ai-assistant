# 后端实现说明

> 说明当前 `ai-assistant` 后端已实现的模块与功能，供开发者快速了解代码结构。

## 一、已实现的模块

| 模块 | 文件 | 说明 |
|------|------|------|
| 项目配置 | `pyproject.toml` / `requirements.txt` / `.env.example` | 锁定版本依赖（Apache-2.0，Python ≥3.11,<3.14）；环境契约 |
| 配置系统 | `app/core/config.py` | pydantic-settings，集中管理 DB/JWT/CORS/LLM 路由；`is_production` / `cors_origin_list` 辅助 |
| DB 持久化 | `app/core/database.py` + `app/models/` | SQLModel + SQLAlchemy；`init_db` / `get_session`；SQLite 默认、Postgres 可切换；自动建库目录 |
| 认证权限 | `app/core/security.py` + `app/api/deps.py` + `app/services/auth_service.py` + `app/api/routes/auth.py` | 五级角色、bcrypt、JWT access/refresh（`token_version` 撤销）、`PermissionGuard`、`/auth/login|refresh|me`、启动种子管理员 |
| Channel 抽象 | `app/channels/`（base / registry / http_channel） | `AbstractChannel` + `ChannelRequest/Response` + `ChannelRegistry` 单例；登记 API_HTTP |

| Agent 编排 | `app/agents/`（prompts / pipeline） | 五阶段管线（理解→规划→行动→反思→响应），`run`/`run_stream` 两种模式；「行动」阶段预留 `Retriever` 钩子供检索接入 |
| 会话模型 | `app/models/conversation.py` | `Conversation` + `Message`，`tenant_id`/`user_id` 多租户隔离，级联删除 |

| 应用入口 | `app/main.py` + `app/api/router.py` + `app/api/routes/health.py` | FastAPI + lifespan（建表→种子→安全校验→登记 Channel）；`/`、`/api/health` |
| 部署 | `Dockerfile` + `docker-compose.yml` | 非 root 多阶段镜像；app + Postgres 编排；健康检查 |
| 测试 | `tests/conftest.py` + `tests/test_health.py` | 冒烟测试（root/health/鉴权/登录），已通过 |

## 二、关键设计说明

1. **配置系统用 pydantic-settings**：集中管理核心配置，类型安全、天然支持 `.env`；模型路由等复杂配置在此扩展。
2. **五级角色模型**：`system_admin / system_viewer / tenant_admin / member / viewer`，配套 `ROLE_PERMISSIONS` 矩阵与 `require_permission` 守卫依赖。
3. **refresh token 撤销**：令牌载荷写入 `token_version`（`tv`），用户改密/登出自增，旧 refresh 立即失效。
4. **生产安全启动校验**：`ENV=production` 且 `JWT_SECRET_KEY` 为默认值时，**拒绝启动**（RuntimeError），避免密钥泄露。
5. **依赖保持精简**：仅引入运行所需依赖（Web 框架、ORM、认证、httpx）；LangChain / Chroma / Milvus 等按模块需求引入。RAG 检索能力通过 Agent 管线「行动」阶段的 `Retriever` 钩子接入，不耦合管线主体。
6. **LLM 提供商可替换**：`app/llm` 以抽象接口隔离具体模型服务，OpenAI 官方与 Ollama（`/v1`）共用一套兼容客户端；未配置 API Key 的开发环境自动降级为 Mock，保证离线可跑、可测。
7. **五阶段 Agent 管线**：将一次问答拆为理解 → 规划 → 行动 → 反思 → 响应，每阶段独立提示词与子目标；`run` 一次性返回，`run_stream` 以 SSE 增量返回阶段进度与最终 token。
6. **多租户 RBAC**：`Tenant` + `User`（含 `tenant_id` / `role` / `token_version`）已建模，为会话、知识库、Agent 等业务实体提供基础。

## 四、如何本地测试接口（Postman / Swagger / curl）

提供 3 种测试方式，详见 `docs/postman/api.postman_collection.json`：

1. **最省事 — Swagger 网页**：启动后浏览器打开 `http://127.0.0.1:8000/docs`，可直接点 `/api/auth/login` 填 `{username,password}` 试调，响应里能看到 `access_token`。
2. **Postman 导入**：把 `docs/postman/api.postman_collection.json` 导入 Postman；先设集合变量 `base_url`（默认 `http://127.0.0.1:8000`）；先发「登录 Login」，测试脚本会自动把 token 存入集合变量，随后「当前用户 Me / 刷新令牌 Refresh」自动带上 Bearer。
3. **curl 脚本**：见下方「快速启动 + 实测命令」。

### 快速启动 + 实测命令

```bash
cd ai-assistant
cp .env.example .env          # 开发默认即可；.env 已被 .gitignore 忽略
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# 另开终端：
curl http://127.0.0.1:8000/api/health
curl -X POST http://127.0.0.1:8000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"change-me-admin-password"}'
# 取 access_token 后：
curl http://127.0.0.1:8000/api/auth/me -H "Authorization: Bearer <ACCESS_TOKEN>"

# 对话（需 Bearer Token；未配置 LLM_API_KEY 时由 Mock 模型应答）：
curl -X POST http://127.0.0.1:8000/api/chat \
  -H "Authorization: Bearer <ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"message":"介绍一下 RAG"}'
```

> 默认管理员：`admin` / `change-me-admin-password`（来自 `.env` 的 `INITIAL_ADMIN_*`）。
> 仅在库中无用户时由 `ensure_initial_admin` 创建，**生产务必改密码或移除该环境变量**。
