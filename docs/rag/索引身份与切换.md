# Embedding 索引身份与受控切换（ADR-0008 / RAG-032）

日期：2026-10-07
代码：`app/rag/index_identity.py`、`app/rag/index_registry.py`、`scripts/rebuild_embedding_index.py`

---

## 1. 为什么需要索引身份

向量的可比性不只取决于维度。**同维度不同模型产出的向量空间互不通用**；
归一化与度量约定变了，数值同样不可比。改造前只有三处零散的维度校验，
而最关键的检索过滤用的是「本次查询向量的长度」——同维异模型时长度相同，
这条分支根本不会触发，混用是静默发生的。

```
改造前：len(查询向量) != len(分块向量) → 跳过
        同维异模型 → 长度相同 → 不跳过 → 混用（静默）

改造后：索引登记 dim / provider / model / version / normalization / metric
        查询按「生效索引」过滤，维度以索引登记为准
        身份不符 → 拒绝（写入抛错，检索判 unavailable）
```

## 2. 身份包含什么

`EmbeddingIndexIdentity`（`app/rag/index_identity.py`）：

| 字段 | 来源 | 为什么必须绑定 |
|---|---|---|
| `backend` | `RAG_VECTOR_STORE` | local 与 Milvus 是两套索引 |
| `provider` | `EMBEDDING_PROVIDER` 配置标签 | 配置的真实服务商，类名区分不了兼容端点 |
| `model` | provider 的 `model` | 换模型即换向量空间 |
| `deployment` | provider 显式声明，或由 `base_url` 派生 | 同模型不同部署也可能不同 |
| `dim` | provider 的 `dim` | 基础校验 |
| `index_version` | `EMBEDDING_INDEX_VERSION` | 显式版本，重建时递增 |
| `normalization` | `EMBEDDING_NORMALIZATION` | 影响向量数值 |
| `metric` | `EMBEDDING_METRIC` | 影响相似度语义 |

**身份里不含密钥与凭据**：`deployment` 只保留 `scheme://host[:port]/path`，
userinfo 与查询串一律剥离，可以安全落库、落日志、进 health 响应。

### 归一化与度量：只接受真实生效的那一组

当前实现固定按 **L2 归一化 + cosine** 执行：Local 在检索时对候选矩阵与查询向量
做 L2 归一化后点积；Milvus 建索引与检索固定 `COSINE`。因此
`normalization` 只允许 `l2`、`metric` 只允许 `cosine`，其它值在身份构造时直接
`IndexIdentityError`。不允许出现「登记了一套、实际按另一套算」的身份。

## 3. 存储

新表 `rag_embedding_indexes`（迁移 `b2c3d4e5f607`），
`rag_document_chunks` 新增 `index_id`（**可空** —— 历史行没有身份）。

状态机：`preparing → active → retired`，失败为 `failed`。
**旧索引只转 `retired`，不删**，保留回退能力。

## 4. 校验点

| 位置 | 行为 |
|---|---|
| 写入（`service.py` 摄取与重解析） | 落 `index_id`；目标索引（active 或显式 `write_index_id`）身份与当前模型不符 → 抛 `IndexIdentityError` |
| 检索（`vectorstore/base.py` 的 `identity` 参数，Local 与 Milvus 共用） | 先按 `resolve_read_index_for()` 定生效索引：无 active 但库里有分块 → 抛 `IndexUnavailableError`；无 active 且空库 → no_hit；身份不符 → 抛 `IndexIdentityError` |
| 父块复核（`service.py::_expand_parent_chunks`） | 回查限定同一 `index_id`，retired 索引的 stale hit 不展开 |
| 激活/回退（`index_registry.activate_index`，脚本只是调用者） | 目标不存在 / `failed` / 实际分块为 0（除非 `allow_empty`）/ 完整身份不符 → 全部拒绝 |

最后一条是 ADR-0008 的硬要求：**回退不能只改集合名而仍用新模型查旧向量**。
校验下沉到 `activate_index` 这个领域入口，是因为脚本层先判一次、领域层不判，
等于给了调用者一条绕过路径。

Milvus 侧：集合名不再固定为 `MILVUS_COLLECTION`，而是取生效索引的 `name`
（含版本与身份指纹）；schema 必须带 `index_id` 字段，检索表达式与 SQL 回查都按
`index_id` 过滤。

## 5. 历史数据怎么办（重要行为变更）

`index_id IS NULL` 的历史分块**默认不参与检索**。这是有意的收紧：
ADR-0008 明确禁止自动认定历史索引与当前配置兼容——维度相同不等于模型相同。

它们不是被删掉，而是被隔离：

- `/api/health` 的 `checks.vector_store.embedding_index.legacy_chunks` 暴露数量，不静默；
  出现被隔离数据时向量库检查项状态为 `degraded` 并带 `reason`，不会伪装成 `ok`
- 要纳入当前索引：`python scripts/rebuild_embedding_index.py adopt --confirm \
  --evidence "声明人=张三; 依据=部署记录; 原模型=text-embedding-v3" \
  --declared-model text-embedding-v3`
  —— 必须显式确认并给出**可追溯证据**（证据写入 `EmbeddingIndex.notes`），
  声明的原模型必须与目标索引一致，且**全部历史分块维度抽样必须与索引登记一致**，
  有一条对不上就整体拒绝、不写一半。
  注意：**维度相同不能证明向量空间相同**，无法举证时只能 rebuild
- 更彻底的做法：`rebuild --apply` 用摄取快照全量重建（会调用嵌入接口，产生费用）

**升级前已存在的知识库，在登记或重建之前会查不到东西。** 这是预期行为，不是 bug。
没有生效索引但库里有分块时，检索会抛 `IndexUnavailableError`（上层收敛为
`unavailable`），而不是返回空列表冒充「库里没有」。日志留 `warning`。

## 6. 切换流程

```bash
# 1) 登记新索引（不切换，旧索引继续服务）
python scripts/rebuild_embedding_index.py prepare --model text-embedding-v4 --dim 1024

# 2) 全量重建（读摄取快照回放，不需要重新上传源文件）
python scripts/rebuild_embedding_index.py rebuild --apply

# 3) 校验通过后显式激活（旧索引自动转 retired）
python scripts/rebuild_embedding_index.py activate --index-id <id>

# 出问题回退
python scripts/rebuild_embedding_index.py rollback --index-id <旧索引 id>
```

`rebuild` 失败时索引标记 `failed`，**旧索引仍为 active，读路径不受影响**。

## 7. 重建期间旧索引继续服务

`rebuild --apply` 会把 `ensure_index` 得到的目标 `index.id` 作为
`RAGService(write_index_id=...)` 传给写入链路：

- 写目标 ≠ 当前 active 时，**不删旧分块**，新增一套绑定目标索引的分块；
- 旧 active 索引继续可读，新旧分块同时存在；
- 任一文档失败 → 旧索引数据完全不变，目标索引标记 `failed`；
- 激活时才切换，且此时目标索引必须已有真实分块（空索引拒绝激活）。
