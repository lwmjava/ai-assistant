## 一类原因

多数报错来自同一件事：mypy 只看见模型字段的 Python 注解。`is_current: bool`、`deleted_at: datetime | None`、`updated_at: datetime`、`id: str` 在查询里仍是列对象，类型检查器却把 `.is_()`、`.desc()`、`.asc()` 和 `==` / `<` 当成普通值运算。`join` 和 `where` 因此收到 `bool`。

其余是注解、导入和失败路径没有写完：宽字典下标、分支赋值类型不一致、`bytes` 传给 `str`、把 `str` 赋给已经是 `list[str]` 的名字、用 `**dict` 构造数据类、把 `None` 赋给导入的类、`None in (...)` 不能收窄、未注解的字典被推成 `dict[str, object]`、Alembic head 的 `str | None` 被声明成 `str`。

`Session.exec` 的重载只覆盖 `Select`。`delete` 语句上已有 `# type: ignore[arg-type]`，实际错误码是 `call-overload`。`pyproject.toml` 里 `warn_unused_ignores = false`，对不上的忽略不会被单独报成「未使用的忽略」，原错误继续存在。SQLModel 0.0.22 的 `exec` 对非 `Select` 语句本来就转调 `execute`。

## 方案里险些留下的问题

修复方案初稿有三处会在落地时制造新问题，评审拦住了：

1. 调用点改成 `col()`，import 没有写。五个文件当前都是 `from sqlmodel import Session, select`（审计文件另有 `delete`）。照做会 `NameError`。`local.py` 没有 `from __future__ import annotations`，`Sequence` 也必须导入。
2. 未知 `ChunkParams` 键从现在的构造失败改成跳过。这会把显式失败变成静默降级。改为抛 `ValueError` 并列出键名。
3. `get_head_revision()` 在 head 为空时抛错。`auto_migrate()` 里调用它的 `_stamp_if_schema_already_at_head()` 在 `upgrade("head")` 的 `try` 之外。开发环境因此会直接退出，盖过「迁移失败不阻塞启动」。抛错保留，但这一个调用单独接上现有的开发/生产处理，不挪进那段已经在「无待迁移就返回」之后的 `try`。

## 以后避免同类问题

规则正文在 `AGENTS.md` 第 10 节「类型检查」。这里只保留判断顺序：

1. 写 SQLModel 条件、排序、连接时用 `col()`。
2. `delete` / `update` 用 `session.execute`，不用配错错误码的 `type: ignore`。
3. 查询结果按 `Sequence` 接收；注解里出现的名字要能导入。
4. 固定结构用 `TypedDict` 或显式注解，不用宽字典和下标碰运气。
5. 子进程输出、可选导入、数据类构造和空值收窄按上表写完。
6. 把可空值收成非空并抛错时，先看这个异常会不会逃出已有的失败处理。
7. 不放宽 mypy 配置，不改 `follow_imports`，不用整文件忽略换退出码 0。验证用 conda 环境 `ai-assistant` 的解释器。
