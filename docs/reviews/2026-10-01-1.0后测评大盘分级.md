# 1.0 之后的测评大盘分级

> 日期：2026-10-01
> 状态：决策记录。未写入 `tasks.yaml`，不是当前排期。
> 进入条件：交付排期第 20 项完成之后。在此之前不实现本页列出的大盘。
> 不替代 `tasks.yaml`。要开工时，按下面的顺序一次只加一条任务卡。

企业上线要看质量会不会在上线后变差。会变差、而且现有测试看不出来的模块，必须有持续评测，并且能看到趋势。行为确定的模块，测试和审计就够。

当前 38 张打磨卡没有测评大盘。RAG 评估大盘和 Prometheus 在交付计划里是 P2，不在 1.0 交付内。

## 必须做

1.0 里只有零散用例，没有可持续查看的结果。顺序固定为下面四步，做完上一步再加下一条任务卡。

| 顺序 | 模块 | 要看到的结果 | 现在缺什么 |
|---|---|---|---|
| 1 | RAG | 召回、排序、引用是否对准、该拒答时是否拒答 | 检索基线已冻结。生成层和引用准确率没测 |
| 2 | Agent | 分流、任务是否做完、不该答时是否停下 | 10 条 Silver，正式跑过一次。不执行工具，不建会话 |
| 3 | 安全护栏 | 注入是否被拦住、是否跨租户、是否把秘密写进回答 | 有围栏。默认不阻断用户输入。真实模型拒答没测 |
| 4 | 工具 | 该用的用了、不该用的没用、执行失败和副作用 | 正式评测只解析工具名，不执行 |

## 需要做

1.0 会对客户可见。第一批可以先留版本化评测报告，等必须做的四块有了可持续结果再做成板。

| 模块 | 为什么要评 | 为什么晚一步 |
|---|---|---|
| 工作流 | 成功率、到点是否触发、失败后有没有按策略重试 | 到点目前不会执行，也没有重试 |
| 技能 | 条件命中才选用，不串租户 | 创建和选用还没做完 |
| MCP | 超时、越权、降级是否符合声明 | 外部调用的打磨还在待办 |
| 记忆 | 超窗后关键事实还在不在 | 已有条数回归。对话路径仍不读记忆配置 |
| 沙箱 | 逃逸、超时、进程是否结束 | 要有安全回归。单独的板排在护栏之后 |

## 可以不做测评大盘

| 模块 | 原因 |
|---|---|
| 登录、邀请、租户和用户管理页 | 结果确定，功能测试和权限测试够用 |
| 配额、限流 | 要告警和剩余等待时间，不是质量评分 |
| 审计 | 要查得到、留得住。合规报表不在这期 |
| 备份、迁移命令、接口文档、测试门禁 | 用演练记录和命令退出码证明 |
| 基础设施监控 | 那是运行监控，不是测评 |

## 开工时怎么写回任务卡

一次只加一条。标题写要看到的结果，不写「大盘」二字就算完成。验收要有版本化用例、一次可复现运行，以及和上一次相比变好、变差或持平。Mock 结果不能写成质量达标。
