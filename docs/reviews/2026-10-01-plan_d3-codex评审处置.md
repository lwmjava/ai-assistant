# Codex 评审处置：`docs/plans/plan_d3.md`

> 日期：2026-10-01
> 对象：对 `docs/plans/plan_d3.md` 的 Codex 评审（4 项阻断、8 项补充）。
> 结论：同意「做完这四条不等于企业上线门禁通过」。不同意把 Redis、训练数据脱敏、全量存储占用和 PostgreSQL 演练拉进本批。本批仍可按修订后的计划实现。处置已写入计划。

| # | Codex 意见 | 处置 |
|---|---|---|
| 1 | 配额检查必须原子，含异步预占 | 部分采纳。同一数据库上，检查与写入放在锁住该租户行的同一事务里。不引入跨进程锁，不把多副本称为已关闭。多副本仍是 `OPS-002` |
| 2 | 所有产生存储的入口都要设闸 | 部分采纳。配额改称源文件字节，覆盖每一个 `save_source_file` 调用，含批量上传和 URL 拉取。纯文本摄取不写源文件，继续不设闸。索引体积不在本批 |
| 3 | 限流改为 Redis，否则不能上线 | 不在本批改存储。采纳部署门禁：默认只允许单进程；水平扩展前必须完成 `OPS-001`。README 写明重启会清空桶 |
| 4 | 导出必须脱敏并做成训练格式 | 不采纳为本批范围。原文导出保持为例外：只给当前租户的租户管理员，不是训练数据放行。脱敏和双格式留到第 20 项之后的缺口清点 |
| 5 | `rate=0` 会除零 | 采纳 |
| 6 | 先全量序列化再判断 32 MiB 仍会撑满内存 | 采纳 |
| 7 | 错误契约不稳定 | 部分采纳。本批固定配额和限流的错误字段。九种错误码的统一信封仍是 `ERR-001` |
| 8 | 孤儿文件要有清理任务和对账 | 部分采纳。文件确实不存在才计 0；读取失败则拒绝本次写入。不在本批做后台对账 |
| 9 | 改配额的审计不能失败放行 | 采纳 |
| 10 | CLI 并发和密码强度 | 部分采纳。同一数据库事务里创建，避免两名引导管理员；密码至少 8 位。不新增「全局只能有一个系统管理员」约束，管理接口仍可有多名。密钥轮换不在本批 |
| 11 | 迁移要在 PostgreSQL 上演练 | 不采纳为本批验收。本批只在临时 SQLite 上证明升级和降级。生产库验证仍是 `NFR-005` |
| 12 | 审计要区分请求与下载完成 | 采纳前半。只记 `export_requested`，表示服务端开始返回。不记「用户已收完」 |
