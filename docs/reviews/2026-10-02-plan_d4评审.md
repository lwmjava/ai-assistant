- 四条顺序、一次一条、以及「做完不是企业上线」写在文首。CI、PostgreSQL、三份备份脚本、覆盖率、cross-encoder、错误码信封都留在已有任务卡，没有把它们提前做进 D4。
- OpenAPI 以进程内路由表为准，不另写第二份接口手册。前端回退和静态资源排除在业务路由之外。
- 备份演练明确不打开 `data/ai_assistant.db` 和 `data/test_ai_assistant.db`。源文件在 `data/knowledge`、Milvus 与本地库不是同一份数据，这两句是对的。
- 测试门禁不允许改断言、跳过失败或换解释器换一个通过结果。2026-09-28 的 8 个失败不当作本次结果。
- 检索实验禁止改冻结基线、禁止用 Mock 或 smoke 采纳、禁止扫 k、禁止 holdout 调参、没有密钥就 `blocked`。默认关闭、不采纳就不改 `app/rag/`，能避免实验直接改变线上排序。

允许路径已写入 `tasks.yaml`。计划第 82 行的「下表写入」与任务卡一致。

## 2. 必须先改计划

### 2.1 重排落地的位置和实验不是同一个变量

第 74 行写对照和处理共用同一次 `hybrid_search` 结果，只重排这深度 10 的一批。第 76 行又写把函数放进 `hybrid_search`，「位于 RRF 截断之前」。截断之前重排的是完整融合列表，候选集合会变，不再是实验测过的那 10 条。

计划改为：实验和采纳后的代码都只重排已经按 RRF 截断好的那一批，位置在截断之后、返回之前。不扩大候选池。Milvus 路径仍然不改。

### 2.2 词面覆盖不能写成企业检索质量结论

词面覆盖用的是已经参与 BM25 和 RRF 的同一套分词。它不是 cross-encoder，也不是新的相关性信号。冻结基线的语料是 13 篇、37 个分块，报告自己写明不能据此宣称生产检索质量。计划现在的「三条同时升高就采纳」，会被读成独立重排已经验证。

计划改为：

- 本轮仍只做这一个词面变量，不加新依赖，不改成 cross-encoder。那是未批准的依赖。
- 「采纳」只表示把该函数留在本地检索里且默认关闭。结论必须写明：语料规模、该信号与 BM25 同源、本轮不能作为生产检索质量提升，也不能把独立 Reranker 标成 `Implemented`。
- 「不采纳」仍表示不改 `app/rag/`。`PRAG-002` 只有在本轮采纳时才做开关、灰度和开销；即便采纳，也不把重排写成已经上线。
- 决策数字只取 development 与 validation，与 `RAG-007` 相同。holdout 只附在报告里。越权案例用现行评测器，不用 2026-09-19 基线里后来已经改过定义的违规率。

### 2.3 写给操作者的备份步骤必须就是演练过的步骤

README 写「拷贝默认库文件」，演练却用标准库 `sqlite3.backup`。热库上只拷主文件、不处理 WAL，恢复出的库可以缺页。企业恢复不能验收一种方法、交付另一种方法。

计划改为：README 与演练使用同一种方法，即标准库 `backup`。不把裸文件复制写成步骤。演练在临时库上完成备份后，用该恢复文件作为 `DATABASE_URL` 启动应用，`GET /api/health` 返回成功，并且 `alembic_version` 与源库相同。标记行只证明拷贝内容还在，不能代替应用启动。

README 同时写明：备份文件与数据库同等敏感，含口令哈希和对话时不得提交、不得写入日志；本次步骤不包含 `data/knowledge`。回滚仍是删除临时目录。

### 2.4 门禁记录完成，不等于发布合格

第 128 行允许 pytest 或构建非 0 退出时仍把 REL-003 做完。清单要求失败案例保留，同时要求未通过项有负责人、原因和截止日期。只有一份失败名单时，第 20 项会被说成测试已经过门禁。

计划改为：

- REL-003 的完成条件仍是四条命令都有真实退出码和失败节点。非 0 可以结束「记录」这项，发布结论另写「未达到发布合格」。
- 每条失败写明负责人（个人开发者）、当次原因、处置任务或豁免，截止日期不晚于把本系统当作企业上线之前。不在本条改测试。
- 同一次记录补上 `mypy app/` 的退出码、git 提交、日期、Python 版本和 Node 版本。mypy 非 0 同样只记录不修。不把没跑的覆盖率写成 ≥ 70%。

### 2.5 覆盖测试不要拆真实路由，README 不能广告不存在的路径

「故意少挂一条测试内路由」若作用在正在服务的 `app` 上，会把覆盖测试做成一次拆路由。比较逻辑用一张假路由表断言失败即可。

README「API 端点」是操作者会照着调用的清单。计划不要求它列全全部路由，但其中每一行方法加路径必须是当次 OpenAPI 的子集。对不上的行改到与路由一致，不把 README 扩成第二份手册。

`POST /api/chat/stream` 实际返回 SSE。若生成的 OpenAPI 没有 `text/event-stream`，只给这一条补响应媒体类型，不改事件字段。

### 2.6 恢复和实验报告要能复现，且不带走敏感数据

演练命令、评测命令和门禁命令都要写明工作目录。评测报告沿用已有字段：数据集版本、代码提交、嵌入 provider、模型、维度、向量库、机器规格、对照与处理的 Recall@1、MRR、越权案例数。密钥和连接串不进入报告、README 和门禁说明。

REL-004 没有真实嵌入密钥时保持 `blocked`。不改用 smoke 填一份采纳结论。
