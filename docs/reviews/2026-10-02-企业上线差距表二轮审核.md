## 2. 本轮新增的确定结论

### 2.1 `.env.example` 覆盖不全，且可量化

- `app/core/config.py` 有 **125** 个配置字段（缩进 4 空格的大写字段）
- `.env.example` 只有 **83** 个 key，且**没有** config 之外的多余项
- 差集 **42** 个，且集中在生产上线必须调的开关上

缺的 42 个（按模块归拢）：

```
安全      SECURITY_ENABLED / SECURITY_INPUT_FILTER / SECURITY_OUTPUT_FILTER
          SECURITY_INJECTION_DETECTION / SECURITY_INJECTION_THRESHOLD
          SECURITY_BLOCK_ON_INJECTION / SECURITY_LOG_SANITIZE
沙箱      SANDBOX_ENABLED / SANDBOX_TIMEOUT_SECONDS / SANDBOX_MAX_CPU_SECONDS
          SANDBOX_MAX_MEMORY_MB / SANDBOX_MAX_DISK_MB / SANDBOX_MAX_OUTPUT_CHARS
审计      AUDIT_ENABLED / AUDIT_RETENTION_DAYS
记忆      MEMORY_ENABLED / MEMORY_STRATEGY / MEMORY_WINDOW_SIZE / MEMORY_KEEP_RECENT
          MEMORY_COMPRESSION_THRESHOLD / MEMORY_MAX_SUMMARY_CHARS
技能      SKILL_ENABLED / SKILL_DIRS
工作流    WORKFLOW_SCHEDULER_INTERVAL / WORKFLOW_MAX_EXECUTION_SECONDS
          WORKFLOW_DEFAULT_TIMEZONE
进化      EVOLUTION_ENABLED / EVOLUTION_REFLECT_ENABLED / EVOLUTION_REFLECT_ASYNC
          EVOLUTION_DISTILL_*（7 个）
导入      RAG_IMPORT_ENABLED / RAG_IMPORT_INTERVAL_SECONDS
          RAG_IMPORT_MAX_CONCURRENCY / RAG_IMPORT_FETCH_TIMEOUT
调试      DEBUG_ENABLED / DEBUG_TRACE_MAX_SIZE
```

这条直接否掉 §4.5.1 第 1 步的要求（「每项有注释，标注必填/选填」）—— 缺 42 项就谈不上完整。

建议：第 2 表单开一行 P0「`.env.example` 覆盖全部配置项（当前 83/125）」，验收写成数字，不用形容词。

### 2.2 `.env.example` 带一个可直接用的管理员口令

```
.env.example:37  INITIAL_ADMIN_USERNAME=admin
.env.example:39  INITIAL_ADMIN_PASSWORD=change-me-admin-password
```

代码侧是对的：`config.py:58` 默认空串，`auth_service.py:299` 只在用户名与口令**都**非空时才创建，compose 里 `INITIAL_ADMIN_PASSWORD: ${INITIAL_ADMIN_PASSWORD:-}` 也默认空。

但 `cp .env.example .env && docker compose up` 这条路径（正是 §4.5.1 第 1–2 步）会生成一个 `admin / change-me-admin-password` 的系统管理员。§5.3.3 第 12 条写的是「无默认密码；首次登录强制改密」。

而「首次登录强制改密」在代码里**确认未实现**：全仓 grep `must_change` / `force_change` / `首次登录` 在 `app/` 下零命中。

建议：把这一条从「模型与安装」行的笼统表述里拆出来，单独开行，并写明「`.env.example` 的示例口令会随 cp 落进生产」。

### 2.3 「无变更历史注释 / 无硬编码密钥」——已通过，但表里查不到

- `app/` 下 grep `Phase [0-9]` / `阶段[一二三四五]` / `迭代[0-9]` / `本批新增` / `上一版`：**零命中**
- `app/`、`frontend/src/`、`docker-compose.yml` 下 grep `sk-[A-Za-z0-9]{16,}` / `AKIA…` / `-----BEGIN`：**零命中**

两条都通过。但§4.5 的这一条在表里没有行，所以谁也说不清它是过了还是没过。建议补一行并标「已核对通过」——验收清单要能勾，不能靠记忆。

（注：`docs/product/` 下仍有 `Phase 0` / `Phase 1` 字样，但那条验收只约束代码。）

### 2.4 权限矩阵：已发现冲突，不再是「未核对」

PRD §5.3.2 矩阵「对话/Chat」行：`system_admin ✅ | system_viewer ❌ | tenant_admin ✅ | member ✅ | viewer ❌`

代码 `app/core/security.py:165-174`：

```python
"conversations": {
    "read": [SYSTEM_ADMIN, SYSTEM_VIEWER, TENANT_ADMIN, MEMBER, VIEWER],
    "write": [SYSTEM_ADMIN, TENANT_ADMIN, MEMBER],
    "delete": [SYSTEM_ADMIN, TENANT_ADMIN, MEMBER],
},
```

`write` / `delete` 与 PRD 一致；`read` **两处冲突**——`system_viewer` 与 `viewer` 都能读对话，PRD 都写 ❌。

表里那行写的是「§5.3.2 整份矩阵未逐条核对」。现在至少这行可以确定：**不是未核对，是已发现冲突**。建议把该行改成「`conversations.read` 与 §5.3.2 冲突（system_viewer / viewer 可读对话，PRD 为否）；其余行待核对」。

### 2.5 §4.5.2 的 403 页：确认不存在

§4.5.2 要求「非系统角色访问显示 403 页」。在 `frontend/src/pages/*.tsx` 与 `App.tsx` 中 grep `403` / `Forbidden` / `无权限`：**零命中**。

表里「停止生成、只读成员、六种页面状态」一行写「未逐页核对」——403 页这一项现在可以定论为**缺失**。其余五态（初始加载/空数据/错误/操作成功/操作失败）前端有 `Toast.tsx`、`Feedback.tsx` 与 `ConversationList.tsx` 的空态基础，但没逐页走查，保持「未核对」。

### 2.6 重新生成：确认不存在

`frontend/src/` 下 grep `重新生成` / `regenerate`：**零命中**。§5.1.5 的 P1 项。表里那行「未逐页核对」可以改成确认缺失。

### 2.7 日志脱敏字段清单（供逐条验收用）

`app/security/log_sanitizer.py` 现有：

- **字段名 11 个**：`token` / `api_key` / `apikey` / `authorization` / `auth` / `credential` / `private_key` / `access_key` / `jwt` / `bearer` / `password`
- **值模式 2 个**：JWT 三段式（`eyJ…`）、API Key 前缀式（`sk-` / `api-` / `key-` + 20 位以上）

§5.8 要求的「身份证、手机号、银行卡号」检测在 `input_filter.py`（`_PII_PATTERNS`，三条正则）里，是**输入过滤**路径，`log_sanitizer` 里**没有**这三类。所以「日志脱敏」这一行如果按 §5.8 的字段清单验收，PII 三类在日志侧是缺的。

建议：把「日志脱敏」一行拆清楚——输入侧有 PII 检测并替换为 `***`；日志侧只有凭据类字段，没有 PII 类。
