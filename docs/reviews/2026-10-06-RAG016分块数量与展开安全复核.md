## 87 到 407 的精确根因

配置实际为 parent_child、chunk_size=500、chunk_overlap=64、backend=langchain、vector_store=local。保存的原文快照有 996 个 CRLF，189 个双 CRLF，没有双 LF。

paragraph.py:22 使用 text.split("\n\n")，无法识别 CRLF 空行。原文本被视为一个超长段落，按字符硬切：父尺寸 1500 得 22 块，子尺寸 500 得 65 块，共 87 块。

cleaning.py:45 的规范化将 CRLF 转 LF。同一份快照仅规范化换行后，原有空行变成可识别段落边界；paragraph 策略不会合并短段，而是每段单独成块。复现得到父 193 块、子 214 块，共 407 块。

同一份输入的旧父子数量算法和新逐父生成算法分别复现：CRLF 输入均为 87，规范化 LF 输入均为 407。因而此次 4.68 倍增幅不是逐父生成子块单独造成，而是清洗换行规范化暴露了段落策略的缺陷。显式重建此前被同内容去重跳过，现在修复后真正应用了规范化与切分。

数据库核查实际保存 407 行，父 193、子 214，无父子内容包含关系错配。176 个子块与父块内容全文相同；仅 214 种不同内容。137 块长度不超过 20 字符，36 块仅为 ---，134 块为单行标题样式。父子总数是保存条数，不是不同语义单元数。没有旧块累积或计数虚报证据。

当前上传源文件与保存快照不是字节完全相同的输入，本报告对历史 87 的解释采用已保存快照自身的换行对照复现，不把当前仓库文件字节等同于历史上传版本。当前仓库文件使用相同参数也复现 407。

## DeepSeek 六点逐项核验

1. top_k：展开后最多约两倍这一事实成立，但用户已批准 top_k 为初始检索命中上限、展开可增加，并已同步 README 和 UI。当前不应以二次截断修复，否则可能丢父块、违反方案 A。API 注释“返回融合排序后的分块”与平铺展开结果解释仍需同步；这是契约说明缺口，不直接定成新增 P1 数量缺陷。

2. 评分与排序：自身命中父块若后出现，会被此前构造的父块记录去重，真实 score/similarity 被丢弃，成立。当前已把 origin 标为 hit，但只是展示修正，未修评分；测试曾锁定继承值而不是验证真实命中值，应纠正。数值排序“必然破坏”则不成立：初始 hits 降序时，插入一个与前一子块同分的父块不会必然打破非递增顺序。实际问题是混合列表语义与原始命中评分丢失，应以真实命中记录优先，扩展上下文独立展示或明确定义。

3. N+1：循环同步 Session.get 成立。identity map 命中时未必每次发 SQL，所以最多约 2*top_k 是上界而非固定实测次数；仍有异步事件循环同步 DB 访问风险。可先批量查询命中和父块，避免未经批准整体切换异步 ORM；性能结论需查询计数/耗时证据。

4. 权限红线：父块按全局 ID 读取，没有 tenant_id、document_id 的一致性条件，成立，应阻断关闭。修正生成逻辑不能代替读路径验证，必须用损坏 parent_id 的跨租户/跨文档拒绝用例验证。

5. 可见性：父块没有复用检索可见性和生效日期过滤，成立。同文档合法关联时父子本应共享文档版本，不能声称正常数据下一定跨版本；错误关联、并发变更和版本过滤开启时仍需复用规则，不能仅复制子块 version_status。与第 4 项一起处理。

6. 全文预算：父块全文返回属当前知识库搜索行为，默认父大小上限 1500 字符；它不等于对话送模预算缺失，后者属于 RAG-030。可以为搜索增加独立响应体积限制或折叠显示，但不能为凑 top_k 或预算静默切掉上下文。当前作为容量治理建议，不直接定义为 RAG-016 关闭阻断。

补充安全缺口：backend 在返回 hits 前调用 drop_injected_chunks，但父块在其后从数据库追加，不再执行注入过滤。普通子块可引出包含其他注入段落的父块。该代码路径应随父块可见性校验一并覆盖；本轮未运行攻击验证，不声称已观测真实攻击或泄露。

## 根因归类与建议顺序

- 分块数量：CRLF/LF 行为不一致 + 段落不合并 + 父子同文重复索引。不能以恢复错误的 CRLF 硬切或单纯加大 chunk_size 作为正确修复。
- 父块展开：读取完整父块时未复用权限/版本/注入检查；真实父块命中未优先保留；测试和元数据展示不足以证明这两项已解决。
- 建议先补父块安全过滤及真实命中优先，作为本卡关闭条件；批量查询可在同一读取流程优化。按已批准结构感知架构解决短段合并、标题/分隔线/代码和表格完整性；该部分先与 RAG-021 的范围对齐，不能在本轮只读审核中实施。

此前“父子映射正确、测试通过”只证明局部关系和重建行为，未覆盖行尾等价、碎片数量/重复率、读路径安全和评分真实性；不应因此关闭本卡或宣称整体切分合理。
