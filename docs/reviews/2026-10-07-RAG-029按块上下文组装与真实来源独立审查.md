## 1. 结论

**不建议关闭。**

发现统计：**High 3 / Medium 1 / Low 0 / Info 3**。

21 条专项测试全部通过，但 7 条独立构造性反例全部失败；其中有三类直接违反卡片或 ADR-0005 §9 的已批准契约：

1. `langgraph` 配置下的 RAG 短路径和 Supervisor 路径完全绕过 Context Builder，真实模型 payload 不受 `RAG_CONTEXT_CHARS` 的按块预算约束；
2. 首块超预算时会截成半块后仍加入 `selected`，与「优先保留相关完整证据；不能安全装入时明确超限或证据不足」相反；极小合法配置下甚至会出现 `selected=['c1']`、对外来源 `['c1']`，而 payload 中没有任何 `[资料 N]` 标记或证据正文；
3. 字符串降级路径仅在“发生截断”时补闭合标记；未超预算但输入本身缺闭合标记时会原样进入模型。降级检索器若以 tuple 暴露 `last_hits`，还会回落全部 `last_hits`，再次产生来源多于实际 payload 的旧缺陷。

另外，代码围栏修复只按 `text.count("```")` 奇偶数处理，四反引号 Markdown 围栏会被三个反引号“闭合”，语义上仍未闭合。两项针对未覆盖分支的新变异均存活（各 `21 passed`），按审查规则均为必修。

## 3. High

### H-01 LangGraph 的 RAG 短路径与 Supervisor 路径绕过 Context Builder

- **现象**：实现只在 `AgentPipeline._fill_retrieval()` 接入 `_assemble_context()`。当 `AGENT_ORCHESTRATION=langgraph` 时，显式知识库问题走 `iter_fast_path()`，多步问题走 `SupervisorGraph`；两条路径都把 `retriever.retrieve()` 返回的完整字符串直接拼进模型输入，不调用 `build_context()`，也不回写 `last_selected`。
- **代码位置**：
  - `app/services/chat_service.py:211-218`：`langgraph` 配置启用短路径；
  - `app/services/chat_service.py:303-315`：短路径与 Supervisor 的真实分流；
  - `app/agents/fast_path.py:114-120`、`app/agents/fast_path.py:152-165`：检索结果 `snippet` 原样进入 `## 知识库`；
  - `app/agents/supervisor.py:244-270`：`snippet` 原样追加到 `state.context`；
  - 对照仅默认路径接入的位置：`app/agents/pipeline.py:474-494`。
- **实测证据**：设置 `RAG_CONTEXT_CHARS=400`，让真实 `HybridRetriever` 返回 4 个、每个正文 300 字符的 `ChunkResult`：
  - Fast RAG：模型 user payload 长 **1435**，markers=`['1','2','3','4']`，`last_selected=None`，sources=`['c1','c2','c3','c4']`；按当前 Builder 至多只会出现第 1 块（按 H-02 恢复完整证据契约后可为 0），不可能是 4 块；
  - Supervisor `_retrieve()`：`state.context` 长 **1407**，markers=`['1','2','3','4']`，`last_selected=None`，sources=`['c1','c2','c3','c4']`；
  - 两条独立断言均失败。当前 `tests/test_fast_route.py:145-153` 只验证“检索一次/文本出现”，没有预算或 `last_selected` 断言；RAG-029 新测试也只覆盖 `AgentPipeline`（`tests/test_rag_029_context_builder.py:301-364`）。
- **影响**：开启项目支持的可选编排后，RAG-029 的预算能力整体失效；真实模型调用仍收到未裁剪的全部命中。测试通过不能证明卡片覆盖所有生产路径。
- **建议修法**：提取共享的检索上下文组装入口，`AgentPipeline`、`iter_fast_path`、`SupervisorGraph` 都必须调用同一入口；结构化命中均回写本次 `last_selected`。分别补 Fast RAG 与 Supervisor 端到端测试，断言最终模型 payload 的 markers、`last_selected` 和 `_reply_sources()` 三者数量与顺序一致，且 RAG 段不超过预算。

### H-02 首块被截成不完整证据后仍宣称 selected；极小预算下来源甚至没有对应 marker/正文

- **现象**：首块装不下时，代码不是把整块判为未选并明确证据不足，而是截断 `render_block()` 后把完整 `ChunkResult` 加进 `selected`。这直接违反 ADR-0005 §9 的「知识问答优先保留相关完整证据；不能安全装入时明确超限或证据不足，不截坏块/围栏」。
- **代码位置**：
  - 批准契约：`docs/adr/0005-rag-adaptive-chunking-context-budget.md:68-74`；
  - 违规实现：`app/rag/context_builder.py:224-231`；
  - `safe_truncate()` 在极小正预算下只返回省略号：`app/rag/context_builder.py:86-104`；
  - 现有测试反而锁定了半块被选中：`tests/test_rag_029_context_builder.py:74-83`；
  - 实施说明把该偏离写成设计取舍：`docs/plans/implementation_rag_029_context_builder.md:23-30`、`:120-122`。
- **实测证据 A（完整性）**：正文为 `BEGIN-` + 500 个 `X` + `-END-SENTINEL`，RAG 预算 300。结果 `selected=['c1']`、`drop_reason={'c1':'budget_truncated'}`、`has_begin=True`、`has_end=False`；断言“selected 为空或全文完整出现”失败。
- **实测证据 B（对齐）**：`_FENCE_OVERHEAD=109`，预算设为 110。最终文本只有前导说明、`…` 和闭合标记，markers=`[]`；但 `last_selected=['c1']`，`ChatService._reply_sources()` 返回 sources=`['c1']`。因此「数量与顺序一一对应」在合法配置边界直接失败。
- **影响**：对外来源会声称一个没有证据正文、甚至没有 `[资料 1]` 标记的块已进入模型；同时把不完整正文当作完整证据使用，可能切掉限定条件或结论后半段。
- **建议修法**：结构化路径不得截断证据块。首块完整渲染后仍超预算时，`selected=[]`，把该块记入 dropped，并通过现有预算错误/证据不足契约明确失败；若产品另行批准“首块摘要/裁剪”，必须先修改 ADR 与卡片，且 selected 需指向真实派生产物而不是完整原块。补最小预算边界测试，强制 `markers == selected == reply_sources`。

### H-03 字符串降级路径没有建立“闭合与真实来源”的出口不变式

- **现象 1（围栏）**：`_trim_rag_text()` 先判断 `len(body) <= limit` 并原样返回，之后才执行补闭合逻辑。自定义 Retriever 返回短小但缺 `[/UNTRUSTED_SOURCE]` 的字符串时，半截围栏原样进入模型。
- **现象 2（来源）**：`_structured_hits()` 只接受非空 `list[ChunkResult]`；其它合法 iterable 会走字符串降级。降级分支不写 `last_selected`，而 `_reply_sources()` 在 `last_selected is None` 时回落全部 `last_hits`。实施说明已经在“已知边界”中承认该旧缺口，但卡片没有批准这个例外。
- **代码位置**：
  - 先原样返回、后补围栏：`app/rag/context_builder.py:159-182`，关键顺序在 `:170-181`；
  - 降级入口未回写 selected：`app/agents/pipeline.py:490-503`；
  - 来源回落：`app/services/chat_service.py:515-528`；
  - 文档承认来源缺口：`docs/plans/implementation_rag_029_context_builder.md:123-128`。
- **实测证据 A**：自定义 Retriever 返回 `'[UNTRUSTED_SOURCE]\n短内容'`（远小于默认预算），`AgentPipeline._fill_retrieval()` 后 `state.context` 仍为同一未闭合字符串，闭合断言失败。
- **实测证据 B**：自定义 Retriever 返回完整格式化字符串，并以 tuple 暴露 3 个 `ChunkResult`；预算 400 后实际 payload 只有 marker `['1']`，但 `last_selected=None`，`_reply_sources()` 返回 `['c1','c2','c3']`，来源数量 **3 != 1**。
- **变异佐证**：新变异 N1 把未超预算分支改成移除闭合标记，官方 21 条测试仍 **21 passed**；说明该出口没有测试守护。实际未闭合输入反例进一步证明不是纯测试问题。
- **影响**：明确要求覆盖的自定义 Retriever 降级路径既可留下半截不可信围栏，也可重现本卡要修复的「声明来源多于实际证据」。
- **建议修法**：所有 `_trim_rag_text()` 返回前统一验证/规范化围栏，不能把“未超预算”等同于“结构有效”；降级组装必须显式把本次 `last_selected` 写成可证明的集合（无法证明就写 `[]`，禁止 `_reply_sources()` 回落旧/全量命中）。同时让 `_structured_hits()` 接受经过拷贝验证的 `Sequence[ChunkResult]`，或明确收紧 Retriever 协议并拒绝非契约实现。补短小未闭合输入与 tuple 命中的端到端断言。

## 4. Medium

### M-01 代码围栏平衡算法只识别恰好三个反引号，四反引号围栏仍被截坏

- **现象**：Markdown 允许三个及以上反引号作为 fenced code block。当前实现用 `text.count("```") % 2` 判断平衡，并固定补三个反引号；四反引号 opener 被截断时，补出的三个反引号不能闭合它。
- **代码位置**：`app/rag/context_builder.py:71-72`、`app/rag/context_builder.py:92-104`。
- **实测证据**：首块内容以 ````python 开始，预算 300。输出尾部为 `…\n```\n[/UNTRUSTED_SOURCE]`；独立逐行解析仍得到 `active_fence=4`，闭合断言失败。新变异 N2 专门破坏四反引号分支，官方专项仍 **21 passed**，说明现有 `tests/test_rag_029_context_builder.py:74-102` 只覆盖三个反引号。
- **建议修法**：不要以子串奇偶数判断 Markdown 围栏；按行识别 opener 的字符种类（反引号/波浪号）和宽度，closer 必须同种且宽度不小于 opener。若按 H-02 改为结构化证据整块保留/整块丢弃，仍需为字符串降级路径保留正确的围栏解析。补四反引号、五反引号、`~~~` 和截在 delimiter 内部的边界用例。

## 9. 必修项

1. **闭合 H-01**：Fast RAG 与 Supervisor 必须接入同一个 Context Builder，并补真实模型 payload / selected / sources 三方一致的端到端测试。
2. **闭合 H-02**：服从 ADR-0005 §9 的“完整证据”决定；首块装不下时不得截成半块再列入 selected，必须明确超限或证据不足；补极小预算边界。
3. **闭合 H-03**：降级路径所有出口强制围栏不变式；无法证明来源时不得回落全量/旧 `last_hits`；补短小未闭合字符串和 iterable hits 的端到端测试。
4. **闭合 M-01 / 存活变异 N2**：正确处理任意宽度 Markdown 代码围栏及 `~~~`，或在所有结构化路径彻底禁止块内截断。
5. 修复后重跑本文 7 个独立反例、8 个变异、专项/关联/全量回归，并再次证明目标文件无变异残留。

**最终结论：不建议关闭。**
