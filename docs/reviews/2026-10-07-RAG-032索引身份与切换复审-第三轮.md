## 5. 是否引入新问题（`index_registry.py` +155 / `index_identity.py` +9）

### 5.1 既有语义未破坏

- `EmbeddingIndexIdentity.__post_init__` 的改动只新增「先归一化再校验」两步，把原本会抛错的 `L2` / `Cosine` 变成合法且与 `l2` / `cosine` 同 `key()`。这是**放宽**而非收紧，且放宽的是同一个语义（`L2` 就是 `l2`）。`identity_matches_row`（`index_identity.py:153-159`）与 `identity_of_row`（`index_registry.py:251-262`）因此对同一行得到一致的 `key()`，不存在新旧格式分裂。
- `activate_index` 的既有四项校验（不存在 / failed / 身份不符 / 空索引）顺序与语义全部保留，检索校验是**追加**在 `:194`，且受 `chunk_count_for > 0` 前置保护——`resolve_write_index` 的空库首次激活（`allow_empty=True`，`:333`）不会触发抽样，无额外开销与风险。
- 抽样检索走的是 `get_vector_store(session)` 的常规入口，Milvus 侧自带 RAG-038 的 `current_or_new_deadline()`（`app/rag/vectorstore/milvus.py:286,288`），`deadline_from_settings()` 取值有限（`app/rag/resilience.py:148-150`），**不存在无上界挂起**；`probe_retrieval_hits` 的 `ThreadPoolExecutor` 分支（`:316-317`）虽然 `.result()` 没传 timeout，但被检索侧自己的 deadline 兜住。
- `activate_index` 只有三个调用点（`index_registry.py:333`、脚本 `:190` / `:207`）与测试，没有把抽样检索意外引入高频写入路径。

### 5.2 新发现（Low，均不阻塞）

#### N-01（Low）`_revert_switch` 漏还原 `target.retired_at`

`_apply_switch`（`index_registry.py:215-232`）在 `:229` 把 `target.retired_at = None`，但 `_revert_switch`（`:235-248`）只还原 `target.status` 与 `target.activated_at`（`:246`），**没有还原 `retired_at`**。

亲手复现（新建临时库，直接调 `_apply_switch` 后 `_revert_switch`）：

```text
before : target.status='retired'  target.retired_at=2026-10-04 11:58:23  target.activated_at=2026-09-27 11:58:23  other.status='active'
applied: target.status='active'   target.retired_at=None        target.activated_at=2026-10-07 11:58:23  other.status='retired'
reverted:target.status='retired'  target.retired_at=None        target.activated_at=2026-09-27 11:58:23  other.status='active'

  OK  target.status: 'retired' -> 'retired'
  GAP target.retired_at: 2026-10-04 11:58:23 -> None
  OK  target.activated_at: 2026-09-27 11:58:23 -> 2026-09-27 11:58:23
  OK  other.status: 'active' -> 'active'
```

影响面：只在「对一个**已经是 retired** 的索引做 activate/rollback，且检索校验不通过」时出现，结果是该索引的退役时间戳丢失（状态仍正确回退为 retired）。属审计字段瑕疵，不影响读路径与数据正确性。修法一行：`_apply_switch` 把 `retired_at` 一并纳入 `previous` 元组。

#### N-02（Low）`identity_of_row` 对非 l2/cosine 的历史行会抛错

`identity_of_row`（`:251-262`）走 `EmbeddingIndexIdentity(...)` 构造函数，`__post_init__` 对非 `l2` / 非 `cosine` 直接抛 `IndexIdentityError`。它的两个调用方是 `_probe_retrieval_hits`（`:274`）与脚本的 `_describe_index`（`:126`）。当前所有登记行都由 `ensure_index` 从合法身份写出，因此**实际不可达**；但如果将来导入过带其它 normalization 的历史行，`prepare --json` 与激活抽样会以「不支持的 normalization」报错，而真正想报的是「身份不符」。建议在 `identity_of_row` 里对既存行做一次宽容转换（或直接比 `identity_key` 字符串）。

#### N-03（已验证**不是**缺陷）未向量化分块对抽样校验的影响

我担心「目标索引里存在 `embedding IS NULL` 的分块」会让抽样恒为 0 从而误拒激活，实测两种场景：

```text
场景 A：目标索引名下只有未向量化分块 → 拒绝：名下有分块，但抽样检索命中数为 0
场景 B：1 条未向量化 + 5 条正常        → 通过（抽样命中 >= 1 即放行）
```

场景 A 拒绝是**正确**的（`if not vector: continue` 在 `:284`，跳过而非计 0；整批都没向量就等于读路径确实读不出东西），场景 B 证明单条脏数据不会误杀。不构成缺陷，记录在此以免下一轮重复怀疑。
