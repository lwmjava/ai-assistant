## 1. 结论

**仍不建议关闭。**

一轮的 8 条契约反例**全部由红转绿**，一轮 High 6 / Medium 5 中除 H-06 与 M-04 各剩一条尾巴外均已真修，专项用例 18 → 55 条（54 passed / 1 skipped），12 处变异中 11 处被官方用例抓红（M-12 只被复审临时用例抓红，即 M-08 的成因），ruff 与 mypy 在 `app/rag/`、`app/api/routes/health.py`、`scripts/` 上零告警。整改质量整体是高的。

但复审发现一处**可复现的功能缺陷**：`scripts/rebuild_embedding_index.py` 自己合成身份时把 `deployment` 固定为空串，而运行时身份由 `base_url` 派生出非空 deployment。在仓库默认配置（`EMBEDDING_PROVIDER=openai` + `EMBEDDING_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1`）下，`prepare --model/--dim` 与 `rebuild --model/--dim --apply` 登记出来的索引**永远通不过 `activate` 的完整身份校验**。模块 docstring 与 README 推荐的 `prepare → activate` 链路实测 rc=3。这直接命中本卡 deliverable「新模型新索引构建、校验再切换」，也让 H-06「运行时与脚本共用同一身份生产函数」只完成了一半。

它之所以能溜过，是因为 **`scripts/rebuild_embedding_index.py` 在整个 `tests/` 下零测试覆盖**——这也是一轮 M-04 未真正收口的部分。

发现统计：**High 1 / Medium 4 / Low 4**（均为本轮新增或一轮残留，不含已关闭项）。

### 关闭前必修项（按优先级）

1. **【High】H-07** 让脚本 `_identity()` 与运行时共用 `identity_from_provider()`（或显式禁止 `--model/--dim`），并补 CLI 级用例锁住 `prepare → activate`。
2. **【Medium】M-06** 为 `prepare / rebuild / activate / rollback / adopt` 五个子命令各补至少 1 条端到端用例（用 monkeypatch 的 provider，不连真服务）。
3. **【Medium】M-09** ADR-0008:23 点名的五项切换校验（数量、身份、授权、检索、故障）本轮只做了三项；「检索校验」缺失，需补激活前抽样检索命中校验，或显式落一个「已人工验证」的凭证。

1–3 完成后即可关闭；4 不单独阻塞。

### 2.1 两处测试契约修订的独立复核（复审委托事项 2）

- **`(a) tests/test_rag.py::test_hybrid_search_skips_mismatched_embedding_dimensions` 第二段由「返回空」改为「抛 `IndexIdentityError`」——认可。** 这是**收紧**而不是放宽：查询向量维度与索引登记不符属于「走错索引」，按 ADR-0008:22 必须显式失败，返回空列表会让调用方把故障读成「查过了没有」。副作用也在可控范围——显式检索接口把它收敛成 503 + `X-Retrieval-Status: unavailable`（`app/api/routes/rag.py:1061-1074`），对话路径由 `HybridRetriever` 收敛为 `unavailable`（`app/rag/retriever.py:93-99`）。没有放过真实风险。
- **`(b) test_identity_exposes_no_secret_material` 删掉「key 不含 `://`」——方向正确，但替换后的断言实际空转。** `deployment` 按设计就是 `scheme://host/path`，断言 `://` 必然与实现冲突，删掉是对的。然而新断言写在 `if identity.deployment:` 内（`tests/test_rag_032_index_identity.py:1092-1094`），而用例用的桩 `_Provider()`（`_Provider.__init__` 的 `deployment=""` 且没有 `base_url` 属性）恒产生 `deployment == ""`，于是 `@` / `?` 两条断言**永不执行**。变异 M-9（去掉 `deployment_from_base_url` 的凭据剥离）实测：`test_deployment_from_base_url_strips_credentials_and_trailing_slash` 变红，而 `test_identity_exposes_no_secret_material` **仍绿**，直接证明它是空转的。结论：**没有放过真实风险**（剥离行为由另一条用例真正覆盖），但这条用例本身是装饰性的，建议把桩换成带 `base_url` 的 `OpenAICompatibleEmbeddingProvider`。

## 3. 本轮发现清单

### High（1）

#### H-07 脚本自造身份的 `deployment` 恒空，`prepare → activate` 在默认配置下必然失败

`scripts/rebuild_embedding_index.py` 有两套身份来源：

```python
# scripts/rebuild_embedding_index.py:66-75（脚本自造，deployment 固定空串）
def _identity(model, dim, version) -> EmbeddingIndexIdentity:
    return EmbeddingIndexIdentity(
        backend=current_backend(),
        provider=settings.EMBEDDING_PROVIDER.strip().lower(),
        model=model or settings.EMBEDDING_MODEL,
        dim=int(dim or settings.EMBEDDING_DIM),
        index_version=version or settings.EMBEDDING_INDEX_VERSION,
        deployment="",                      # ← 不派生、不猜测
        normalization=settings.EMBEDDING_NORMALIZATION,
        metric=settings.EMBEDDING_METRIC,
    )

# scripts/rebuild_embedding_index.py:78-82（运行时，deployment 由 base_url 派生）
def _current_runtime_identity() -> EmbeddingIndexIdentity:
    return identity_from_provider(get_embedding_provider())
```

`cmd_prepare` / `cmd_rebuild` 只要带 `--model` 或 `--dim` 就走第一套（`scripts/rebuild_embedding_index.py:118,229-231`），而 `cmd_activate` / `cmd_rollback` / `cmd_adopt` 一律用第二套校验（`:143,148,161,165,185`）。默认配置下 `EMBEDDING_BASE_URL` 非空，第二套的 `deployment` 是 `https://dashscope.aliyuncs.com/compatible-mode/v1`，于是两者永不相等。

**CLI 实测**（临时库 `data/tmp-re032-cli.db`，`EMBEDDING_PROVIDER=openai`、默认 base_url，不连任何外部服务）：

```text
$ rebuild_embedding_index.py prepare --model text-embedding-v3 --dim 1024
  已登记新索引 local__v1__164f09ccfc9f（status=preparing）   rc=0
  登记行 identity_key = local|openai|text-embedding-v3||1024|1|l2|cosine

$ rebuild_embedding_index.py activate --index-id 5800c9e5...
  索引身份错误：当前配置身份 local|openai|text-embedding-v3|https://dashscope.aliyuncs.com/compatible-mode/v1|1024|1|l2|cosine
                与目标索引 local__v1__164f09ccfc9f 的身份 local|openai|text-embedding-v3||1024|1|l2|cosine 不一致。
  rc=3
```

影响面：

- 模块 docstring（`scripts/rebuild_embedding_index.py:7-12`）与 README「B. 无法举证 → 重建」之外的 `prepare` 用法全部不可用；`prepare` 登记出来的 preparing 索引只能留在库里当垃圾。
- `rebuild --model X --dim N --apply` 更糟：`RAGService(write_index_id=...)` 会用运行时身份去核对目标索引（`app/rag/service.py:650-654`），deployment 不符 → 每一篇文档都抛 `IndexIdentityError` → `rebuilt=0`、索引标 `failed`（`scripts/rebuild_embedding_index.py:283-296`），运维看到的是「重建全部失败」，而不是「目标身份写错了」。
- 唯一能走通的路径是不带覆盖参数的 `rebuild --apply`（`:229` 走 `identity_from_provider`）。

严重性判定：它**失败得很响**（rc=3 / failed），不会静默写坏数据，所以不是数据损坏级缺陷；但它让本卡的「准备新索引 → 重建 → 校验 → 显式切换」这条主流程在默认配置下少一半可用命令，且模块自己的用法说明就是错的。修复成本约 3 行。

必修建议（二选一，并在 `tests/` 里锁住）：

1. `_identity()` 改为以 `identity_from_provider(get_embedding_provider())` 为基底，只覆盖显式给出的 `model / dim / index_version`（`deployment`、provider 标签、normalization、metric 都随运行时）；
2. 或明确禁止 `prepare --model/--dim`，要求先改配置再 `rebuild --apply`，并在参数层拒绝。

### Medium（4）

#### M-06 `scripts/rebuild_embedding_index.py` 五个子命令零测试覆盖

`tests/` 下没有任何文件 import 或调用 `cmd_prepare` / `cmd_rebuild` / `cmd_activate` / `cmd_rollback` / `cmd_adopt`（全仓 grep `rebuild_embedding_index|cmd_activate|cmd_prepare|cmd_rebuild|cmd_rollback|cmd_adopt` 在 `tests/` 零命中）。一轮 M-04 明确点名「文件没有覆盖脚本 rebuild/activate/rollback」，本轮 55 条用例补的全是领域层（`activate_index` / `adopt_legacy_chunks` / `RAGService`），脚本层依旧是空白——这正是 H-07 能溜过整改的直接原因。

必修：至少 5 条 CLI 级用例（用 monkeypatch 替换 `get_embedding_provider`，不连真服务），覆盖：prepare 登记的身份能被 activate 接受；activate 拒绝 failed / 空 / 身份漂移；rollback 后旧索引恢复 active 且旧分块可命中；rebuild 失败时旧索引数据不变且目标标 failed；adopt 缺证据 / 声明模型不符 / 成功落 `notes`。

#### M-07 「三种 backend 都传身份」未获运行时证明，且该用例锁的不是它声称的东西

- 本机 `llama_index` 未安装，`test_all_backends_carry_query_identity[llamaindex]` 被 `pytest.skip` 跳过（`tests/test_rag_032_index_identity.py:399-400`），专项实际只跑了 native 与 langchain。llamaindex 分支的 `identity=self._current_identity()`（`app/rag/backend/llamaindex_backend.py:230`）只有静态依据。
- 更关键：变异 M-1（把 Local 的 `resolve_read_index_for(..., identity, ...)` 改成传 `None`）只让 **1** 条用例变红；`test_all_backends_carry_query_identity[native]`、`test_same_dim_different_model_service_search_is_refused` 仍绿——因为它们是靠 `service._read_index_id()` 这道**第二道**检查（`app/rag/service.py:741-763`）兜住的。也就是说该用例并没有真正锁定「backend → store 的身份传递」，它锁定的是另一条路径。防御纵深是好事，但用例名与断言意图不符，容易让人误以为 backend 侧已被覆盖。

必修：补一条直接对 backend 断言的用例（例如 monkeypatch `LocalVectorStore.hybrid_search` 记录入参，断言 `identity is not None` 且等于 provider 身份），native / langchain 各一，llamaindex 在依赖缺失时保持 skip 并在报告里注明。

#### M-08 `search()` → `_read_index_id()` 这条真实生产链路的索引收窄没有官方用例

`_expand_parent_chunks` 在生产侧唯一调用点是 `search()`（`app/rag/service.py:739`），`index_id` 来自 `_read_index_id()`（`:741-757`）。但现有父块用例都是**显式传 `index_id` 直接调私有方法**（`tests/test_rag_032_index_identity.py:682,691`），绕过了 `_read_index_id()`。变异「`_read_index_id()` 恒返回 `None`」时，官方的 `test_parent_expansion_drops_stale_hits_of_retired_index` 仍然绿（它自己传了 `active.id`）；只有复审临时用例 CE-6（走 `_read_index_id()`）变红。

必修：补一条从 `search()` 进入的端到端用例——构造「retired 索引名下有一个 stale 命中」，断言该命中不会经父块展开返回。

#### M-09 ADR-0008:23 的「检索校验」缺失

ADR-0008:23 要求「新索引完成**数量**、**身份**、**授权**、**检索**与**故障**校验后才显式切换」。本轮 `activate_index()`（`app/rag/index_registry.py:122-194`）落实了三项：数量（实际分块数 > 0，`:157-162`）、身份（全字段 key 比对，`:151-156`）、故障（`failed` 拒绝，`:146-150`）。**「检索校验」没有任何实现**——一个名下有几万条分块、但因为切分/嵌入异常导致检索永远 0 命中的索引，照样能被激活，激活后整个知识库表现为正常 no_hit。这与 H-03「空索引不得激活」是同一类静默数据丢失，只是更隐蔽。

必修：在激活路径上加抽样检索校验（取 N 条目标索引名下的分块，用其原文做一次 `hybrid_search`，断言至少命中 1 条），或要求调用方显式传入「已人工验证」的凭证并落 `notes`；两种做法都要有对应的正例与反例用例。

### Low（4）

#### L-02 配置注释与 `.env.example` 仍声明已被拒绝的取值

- `app/core/config.py:120-121`：`# l2 | none` / `# cosine | ip | l2`
- `.env.example:123-125`：`# 向量写入前的归一化方式：l2 | none` / `# 相似度度量：cosine | ip | l2`

而 `EmbeddingIndexIdentity.__post_init__`（`app/rag/index_identity.py:92-102`）对非 `l2` / 非 `cosine` 直接抛 `IndexIdentityError`。README 已改成「当前只支持 l2 / cosine」，这两处没改，且两者都在 RAG-032 的 `allowed_paths` 内（`tasks.yaml:9754-9764`）。运维照注释配 `EMBEDDING_METRIC=ip` 会让所有摄取与检索直接报错。建议同步为「当前实现只按 l2 / cosine 执行，其它值会导致身份构造失败」。

#### L-03 `test_identity_exposes_no_secret_material` 的凭据断言空转

见 §2.1(b)。桩 `_Provider()` 无 `base_url`，`identity.deployment` 恒为 `""`，`if identity.deployment:` 内的 `@` / `?` 断言永不执行（变异 M-9 验证）。

#### L-04 `normalization` / `metric` 只做小写校验却原样入库

`__post_init__` 用 `.strip().lower()` 比较（`app/rag/index_identity.py:92,98`），但 `key()` 用的是原值（`:104-117`）。登记 `L2` 能通过校验，却会与运行时的 `l2` 永久不匹配；而 health 的 `unsupported` 判定也用小写（`:115-118`），会把这种行误判为 `supported`。建议入库前统一 `strip().lower()`。

#### L-05 `prepare --json` 恒输出 `{}`

`scripts/rebuild_embedding_index.py:132` 写的是 `index.describe() if hasattr(index, "describe") else {}`，但 `EmbeddingIndex`（`app/models/rag.py`）没有 `describe` 方法（`describe()` 在 `EmbeddingIndexIdentity` 上）。因此 `--json` 永远打印 `{}`。要么改用 `fingerprint_of_key(index.identity_key)` + 字段字典，要么删掉这个参数。

## 7. 委托事项的三个判断

### 7.1 `RAGService.__new__` 桩导致的查询身份退化——**不阻塞关闭（Low）**

实现方说的退化是：`_read_index_id()`（`app/rag/service.py:741-757`）在 `getattr(self, "_embedding", None) is None` 时退化为 `active_index()`（不比较身份），拿不到 active 索引时返回 `None`（父块复核不按索引收窄）。

判断依据：

1. 该分支的触发条件是 `_embedding` 属性缺失或为 None；`RAGService.__init__`（`:256`）写的是 `embedding_provider or get_embedding_provider()`，永远不为 None。全仓只有两处 `RAGService.__new__` 桩（`tests/test_rag_safe_parent_expansion.py:35`、`tests/test_rag_search_explanation.py:32`），都在测试里。
2. `_expand_parent_chunks` 在**生产侧唯一**调用点是 `search()`（`:739`）。而 `search()` 必然先走 `backend.retrieve()` → `hybrid_search(identity=...)`，身份不符在那里就被拒（H-01 已修），根本到不了父块复核。
3. 「不收窄」只在「库里没有任何 active 索引」时发生；而那种情况下 `hybrid_search` 已经抛 `IndexUnavailableError`（有分块）或在空库返回空（本来就没有可展开的分块）。所以即使对桩而言，这条退化也不会放行跨索引数据。

结论：**不构成生产绕过**，是单元测试桩的历史包袱，允许带着关闭。但建议在关闭前顺手补一条断言（见 M-08），否则将来有人把 `_read_index_id()` 改成直接 `return None` 不会被任何官方测试发现——变异 M-12 已经证明这一点。

### 7.2 两处测试契约修订——见 §2.1

`(a)` 认可（收紧，风险未放宽）；`(b)` 方向认可但替换后的断言空转（L-03），建议换桩使其真正生效。

## 8. 关闭前最低补测清单

1. **【必修】** H-07 修复对应的用例：脚本 `_identity()` 与 `identity_from_provider()` 派生的 `deployment` 一致；`prepare --model X` 登记出的索引能被 `activate` 接受（默认 base_url 配置下）。
2. **【必修】** `scripts/rebuild_embedding_index.py` 五个子命令各 ≥1 条 CLI 级端到端用例（M-06），至少覆盖：空索引激活被拒、failed 激活被拒、身份漂移激活被拒、rollback 后旧分块可命中、rebuild 失败时旧索引数据不变、adopt 缺证据/声明模型不符被拒且成功时证据落 `notes`。
3. **【必修】** ADR-0008:23 的「检索校验」（M-09）：激活前抽样检索命中的正例与反例（目标索引有分块但检索全 0 → 拒绝激活）。
4. **【必修】** backend → store 身份传递的直接断言（M-07）：native / langchain 各一条，用 monkeypatch 记录 `hybrid_search` 入参并断言 `identity` 非空且等于 provider 身份；llamaindex 依赖缺失时保持 skip 并注明。
5. **【必修】** `search()` → `_read_index_id()` 端到端收窄（M-08）：retired 索引的 stale 命中经 `search()` 不返回。
6. **【建议】** L-02/L-03/L-04/L-05 四项随同批提交：配置注释与 `.env.example` 对齐实际约束；凭据断言换用带 `base_url` 的桩使其真正生效；`normalization` / `metric` 入库前归一化；`prepare --json` 改为真实输出或删除该参数。
