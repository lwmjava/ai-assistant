## 4. 本轮新发现

### Medium（1）

#### N-01 报告级 G5 检查改写了 `blocking_rules` 却没有同步 `meets_gate`，且这一跳零测试守护

- **现象**：`apply_report_level_checks()` 在 G5 命中时重写 `checks.G5` 与 `blocking_rules`，最后一步把 `meets_gate` 重算为 `False`。删掉这最后一步，门禁会同时写出「`blocking_rules=['G5']`」和「`meets_gate=True`」这种自相矛盾的结论，而**54 条测试全绿**。
- **文件:行号**：`scripts/parse_quality_report.py:544`（`gate["meets_gate"] = not gate["blocking_rules"]`）；守护缺口在 `tests/test_rag_033_parse_quality.py:717-725`（`test_used_mock_true_blocks_gate_via_g5` 只断言 `checks.G5.passed is False` 与 `"G5" in blocking_rules`，**没有断言 `meets_gate`**）与 `:637-643`（`test_gate_g5_blocks_when_report_claims_verification` 断言了 `meets_gate is False`，但当前语料下 G4 本来就让它是 `False`，**该断言对 G5 的写入行为不可证伪**）。
- **实测证据**：变异 R24（把 `        gate["meets_gate"] = not gate["blocking_rules"]\r\n    return report` 替换为 `    return report`）→ **`54 passed`，0 条变红**（还原后字节级一致）。对照：删掉整段 `apply_report_level_checks` 调用（R3）会红 1 条、删掉禁用表述扫描（R11）会红 1 条——**说明「改写 G5」与「改写 blocking_rules」都有人守，唯独「改写最终结论」没人守**。
- **现实影响**：当前环境 G4 恒真阻断，`meets_gate` 本来就是 `False`，所以今天不会出错；但**本卡明确预期 G4 会被解除**（补齐 tesseract + chi_sim 后重跑），那一刻只要有任一 G5 违规（报告里出现禁用表述、`used_mock=True`），报告就会一边写 `blocking_rules=['G5']` 一边写 `meets_gate=True`。
- **建议修法**（一行）：在 `test_used_mock_true_blocks_gate_via_g5` 末尾补 `assert report["gate"]["meets_gate"] is False`。该用例的 gate 由 `evaluate_gate([], failure_rate=0.0)` 产出（`meets_gate=True`、`blocking=[]`），加这一条即可让 R24 变红。建议再补一条不变式断言：`assert (not report["gate"]["blocking_rules"]) == report["gate"]["meets_gate"]`。

#### N-04 语料文件缺失时 `failure_reason` 说「文件损坏/加密」，排查方向被带偏

- **现象**：`evaluate_sample` 对「文件不存在」和「文件存在但解析失败」给的是同一条文案。
