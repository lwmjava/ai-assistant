## 发现

### F1 / P1：仅改配置切回 local，会静默隐藏 Milvus 期间新增的文档

位置：`app/rag/vectorstore/local.py:208`；`docs/plans/implementation_rag_015.md:46-49`。

local 只读当前 active local 索引的 `index_id`。Milvus 期间摄取的分块虽然同时存在 SQL 中，但绑定的是 Milvus 索引，因此切回 local 时被过滤掉。实现说明由“SQL 行没有删除”推导“之前摄取的文档仍可见”，推导不成立。影响是检索可见性丢失，不是物理数据删除；不能通过移除索引身份过滤来修复，否则破坏已有隔离约束。

复现：同一租户、同一合成 provider，先 local 摄取 A，再切 Milvus 摄取 B（真实 service → Milvus validate_add/upsert，只有远端 collection 替换为记录写入的假对象），确认 B 的 SQL 分块存在且 upsert 被调用；切回 local 搜索 B 的关键词，只返回 A，B 未命中。测试断言 B 仍可检索失败。

历史真实报告 `evals/reports/rag-015-local-milvus-switch-20261007.json` 的 switch_back_local 命中集合只包含 default_local 的三个文档，不包含 milvus_upload_visible 的三个新文档。`scripts/milvus_switch_check.py:1045` 仅核对原 local 文档，因此该报告不能反证本缺陷。

建议明确两种切换场景的支持范围，并给出保留新文档可见性的受控重建/切换步骤及失败诊断；补齐 Milvus 期间新增文档的回滚验收，修正当前说明中的无条件可见承诺。

### F2 / P2：写入归一化缺少有限数检查，且平方求和会溢出

位置：`app/rag/vectorstore/base.py:88-91`；`app/rag/service.py:453-463`，重建写入也调用同一函数。

`sqrt(sum(value * value))` 不检查 NaN/Infinity。provider 返回 `[NaN, 1.0]` 时产生 `[NaN, NaN]`，`json.dumps` 默认接受 NaN，local add 又没有等价数值校验，因此摄取成功提交不可用向量。Milvus 的有限数检查仅保护 Milvus 路径，无法保护默认 local。

另一个同源边界是有限大输入 `[1e308, 1e308]`：平方和溢出为 Infinity，除法得到 `[0.0, 0.0]`，范数为 0。Milvus `validate_add` 的 `norm > 0` 条件也不会拒绝该结果。这是非零输入被归一化过程破坏，不是在要求改变已明确允许的原始零向量策略。

复现：local 摄取后直接读取已提交 SQL embedding，有限数断言失败；直接调用 l2_normalize 的单位范数断言失败。影响是 provider 异常输出被写入，以及极端数值下“写入侧范数为 1”的保证失效；未声称正常生产模型会常规输出这些数值。

建议统一校验输入有限数，采用可防止平方和溢出的归一化算法，并在写入前验证输出；异常时走已有拒绝/回滚路径。确定性反例即可验证，无需付费模型。
