## 3. diff 代码审查（任务 2）

- **展开时机**：`HybridRetriever.retrieve()` 在阈值过滤 `kept = [h for h in results if h.similarity >= threshold]` **之后**、`_settle` **之前**调用 `_expand_parents(kept, search_text)`。✅ 父块不可能越阈。
- **status 不被展开污染**：`RetrievalOutcome.hits = list(expanded)`，但 `status = classify(candidates=len(results), kept=len(kept))`、`dropped_by_threshold` 只数阈值丢弃。✅ 与 RAG-037 状态契约兼容。
- **失败回退**：expander 抛异常 → `logger.exception` + 回退原 `kept`，不向上炸、不丢已过 SQL 过滤与阈值的子块；`kept` 为空/未绑定 expander → 短路不查库。✅
- **复用 RAG-016 授权链**：`make_retriever()` 始终绑定 `_dialog_parent_expander(index_id)` → `_expand_parent_chunks`，后者在 `load_rows` 中同时施加 `DocumentChunk.tenant_id == self.tenant_id`、`Document.tenant_id == self.tenant_id`、`deleted_at IS NULL`、`index_id == index_id`、uploader（`Document.user_id == read_scope.uploader_id`）、`is_current`，并经 `visible_chunks_with_status` 复核有效期。✅
- **注入复核**：`drop_injected_chunks` 对 child 集合与 expanded 集合各跑一次。✅
- **去重**：`seen` 集合，子块与父块各只追加一次。✅
- **定位元信息**：父块 `chunk_kind=parent`、`retrieval_origin=parent_expansion`、`expanded_from_chunk_id`、`score_inherited_from_chunk_id`；子块 `parent_id` 回填。✅
- **预算/来源对齐**：父块作为一个块进 `_select_rag_blocks` 顺序累加、整块装入/整块丢弃；`assemble_retrieval` 回写 `last_selected`，`sources_from_hits(session, last_selected)` 只从实际选入出来源。✅
- **依赖方向**：Context Builder 仍为纯函数，父块回查留在 Service 层闭包，未给 Context Builder 新增 DB 直连。✅ 符合 ADR-0005 §4。
