### F1 / P1：Milvus 候选 SQL 回查没有再次校验租户

位置：`app/rag/vectorstore/milvus.py:374`，SQL 过滤374–385行。

远端 search 表达式包含 tenant_id，但 SQL 回查只核对候选 ID、index_id、软删、上传者和版本，没有 `DocumentChunk.tenant_id == tenant_id` 与关联 Document 的租户核对。外部结果的块 ID 因错误元数据、残留或错误返回指向另一租户时，这一层会返回该租户的真实正文。共享索引下 index_id 相同不能代替租户校验。

独立反例保持真实 MilvusVectorStore/SQL 回查/BM25/RRF，仅在 `_remote_search` 外部边界返回另一租户真实 SQL 块 ID。调用方为 caller 租户、ReadScope 为 tenant 模式；实际返回 `FOREIGN_EVIDENCE`，期望空结果的断言失败。没有替换 SQL 查询结果或权限函数。

现有 visibility 切片的 foreign_tenant 行在远端元数据与 SQL 一致时被远端表达式排除，因此没有覆盖此错误映射。此反例证明故障边界下的隔离缺口，不证明普通用户能通过公开 API 操纵远端候选 ID。建议在 SQL 回查按鉴权租户再次收口，并增加跨租户错误候选反例；任务归属由负责人确定，不能因前卡已 done 忽略安全事实。

位置：`scripts/rag_hybrid_embedding_check.py:104`、108行；报告身份构造250行。

脚本验证请求配置为 text-embedding-v3/1024维，但响应的 model 只被写入 budget，未与授权模型比对；输出报告身份又固定写 text-embedding-v3。返回维度正确、usage 合法而明确声明其他模型的响应仍被当作成功向量，之后可保存带错误模型身份的证据。向量 manifest 的 hash 校验不能纠正首次记录时的错误归属。
