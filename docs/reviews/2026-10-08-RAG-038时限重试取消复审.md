## 3. 独立反例

探针：`data/pytest-tmp/review038_independent_probe.py`（合成故障注入，无网络、真实模型费用或生产数据）。运行真实 NativeRagBackend → LocalVectorStore → HybridRetriever；在本地 store 的同步 `resolve_read_index_for` 查询位置注入 time.sleep(0.15)，返回空库值 None。此形状与同步 Session 查询等待一致，不改写 native/store/retriever 控制流。

```
P1 sync-local deadline=0.02 elapsed=0.141 status=no_hit
P2 concurrent ContextVar isolation passed
P3 zero-backoff config_enabled=True actual_attempts=1
```

### P1：同步本地查询不能由 asyncio.wait_for 兜住（阻断）

app/rag/vectorstore/local.py 的 hybrid_search 是 async 函数，但内部 SQL、numpy 与 BM25 无 await 让出事件循环。asyncio 定时器无法在同步调用阻塞期间运行；且查询结束后 native 不再检查过期，结果直接返回。实际 20ms 总预算等待约 141ms，且收敛 no_hit。README/实现说明“本地 SQL 由 wait_for 兜住”的表述不成立。修复须令同步阶段可被调用方限时等待（保持 SQLModel Session 线程安全与权限过滤），并拒绝迟到结果；只加返回后预算检查只能避免迟到结果伪装 no_hit，不能证明调用等待有界。

### P3：零退避配置的启动判据与执行不一致

BACKOFF_BASE/MAX=0、deadline=1、MAX_ATTEMPTS=3 时，配置判据返回重试有效，但 runtime 因 wait<=0 标成 give_up_budget，实际只调用一次。可以选择支持零等待重试或明确配置禁用/拒绝，需使判据、日志和文档一致。另 `min(base,max)*(1+jitter)` 上界未考虑 runtime 再夹 max，相关“必然禁用”措辞须保持准确。
