## 4. 缺陷清单

### P2-1（未修复，阻断关闭）：读路径不校验版本绑定新鲜度，原地重解析后旧摘要仍可读

- **现象（CE-A 实跑）**：摘要绑定 `source_version_hash=H1`；随后把同一 `Document` 行的 `content_hash` 改成 `H2`（保持 `is_current=True`、不软删、同租户），`get_readable_summary` 仍返回该旧摘要，未拒绝。
- **真实触发路径**：`app/rag/service.py:1166 _reindex_document_in_place`（docstring 自述「就地替换分块与向量，不改变 is_current 与版本组」）在第 1296 行 `document.content_hash = content_hash`，**确实在同一行上原地变更 content_hash 且保持当前**。这不是理论假设——本系统存在该操作。
- **后果**：原地重建后，旧摘要（绑定 H1）继续被读路径返回，但其 `chunk_id` 指向已被删除的旧父块、其概括内容已不再匹配 H2 正文。违反 ADR-0005 §9「摘要绑定内容 hash…源版本变化后应不可读」，也使验收项「过期摘要拒绝」只覆盖软删/非当前，未覆盖原地 hash 变更。
- **写路径是对的**：`_existing_ready` 按 `doc.content_hash` 匹配，hash 变了不会复用旧摘要、会重新生成；漏洞只在**读路径**。
- **严重度判定**：P2（非 P1）——功能默认关闭且未接入检索/对话主链路，无跨租户/越权泄露，无数据丢失；但它是验收项「过期摘要拒绝」与「版本 hash 绑定」在读取侧的真实缺口，且由既有支持操作触发。修复成本低：在 `get_readable_summary` 中除 `can_read_document` 外，追加断言 `summary.source_version_hash == doc.content_hash` 且 `summary.chunk_plan_version == _chunk_plan_version(doc.chunk_plan)`，不一致即拒绝（不物理删除）。
- **实现者测试缺口**：12 例只测了「新 row 替换旧 row（is_current=False）」，未测「同 row 原地改 content_hash」。

### 观察项（不阻断，记录在案）

- **O-2**：`RAG_SECTION_SUMMARY_ENABLED` 开关无运行时读取方（见 §2.3）；翻 true 当前无效果。
