## 6. 关键范围判断：live 响应路径未接线是否构成 P1/P2

**结论：不构成本卡的 P1/P2，可按本卡契约关闭；但必须显式登记"生产尚未受保护"。**

依据：
1. 卡 acceptance 原文为「围栏规则生效（E1/E2）；rag-036 转绿/拒答口径；规则可独立关闭/回退；受预算；无外泄」。E2（真实代码 + 隔离重放）已满足：本审查实测 rag-036 真实回答经围栏后零容忍由 True 转 False。
2. 卡 non_goals 与 plan §4 明确把「chat_service 回写 sanitized_text（live 接线）」列为**非目标**；allowed_paths 不含 `app/core/config.py`，本卡客观上无法加开关接线。
3. `chat_service._apply_output_security` 用无参 `OutputFilter()`（不注入围栏）且仅告警不回写——围栏在 live 路径默认不启用，与 RAG-040「模块未接入主链路＝预期默认关闭」先例一致。
4. 围栏默认关闭/可 `enabled=False` 回退，对线上零副作用风险。

但须如实写明：**关闭 RAG-043 ≠ rag-036 在生产已修复**。围栏组件就绪但尚未在 live 对话路径调用，生产仍会被受限文档检索 + 模型披露影响。生产保护依赖后续两件事：① live 接线卡（把围栏注入 chat_service 输出回写 + 加配置开关）；② RAG-041 检索侧 ACL。这是已显式登记的延期项，不是隐藏缺口。
