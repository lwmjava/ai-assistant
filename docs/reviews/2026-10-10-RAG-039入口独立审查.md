## 缺陷 F-01：claim 阶段后续提交失败泄漏已抢占任务

优先级 P2，置信度 10/10。`run_import_jobs_once` 在候选循环中逐个 commit 并注册 active，但清理 try 仅从创建任务后开始。第二个 claim 的 commit 失败时，第一项已持久 running 并注册 active，却从未启动执行协程；函数退出也不释放它。下一轮恢复会因 active 排除第一项，容量永久占用，直到进程重启。until_idle 随后会无限等待。

实际反例：两个不同源文件、concurrency=2，在第二个 pending→running 的 SQL 提交点注入一次 RuntimeError。恢复原 commit 后调用真实 until_idle，1 秒内不能退出，TimeoutError；对应 `test_claim_commit_failure_does_not_leak_earlier_capacity`。

修复计划：将本轮 claim 与任务启动都纳入异常清理生命周期；claim 失败时释放本轮已注册且尚未执行的所有 job，保留已经提交的 running 行以便下一次 orphan 恢复；不能移除其他 runner 的 active。已失败事务 rollback 后继续使用新 Session。保留正式回归测试，修复后重跑该用例、独立整文件与受影响并发/恢复子集，再由本审查身份复核。
