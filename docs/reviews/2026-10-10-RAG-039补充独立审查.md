## F05 / P2：软删文档仍参与新上传去重，虚假成功

位置：`app/rag/import_jobs.py:603` `_dedupe_or_version_existing`，尤其 `:625` 起查询，以及 `:725` 起 `existing is not None` 成功分支。查询限定 tenant、is_current、source_kind 与来源，但没有 `deleted_at IS NULL`。正常 `RAGService.delete_document` 仅持久设置 `deleted_at`，保留 is_current、原块与源文件，这是现有软删除语义。

独立真实入口操作如下：

1. 创建 `again.txt` 文件任务，内容为合成 `synthetic identical after delete`，执行 `run_import_jobs_until_idle(limit=1)`，正常成功。
2. 新 Session 使用真实 `RAGService.delete_document(docid, actor)` 软删，返回 True。
3. 同一主体创建**新 ID**的同名、同内容上传任务，执行真实 runner。
4. 执行恢复与直到空闲，再用新 Session 读取任务、文档、块、默认列表，并实际调用 `RAGService.search`。

最终持久观察：

| 观察项 | 实测 |
|---|---|
| 第二任务 ID | 与第一任务不同 |
| 第二任务 status/attempt | success / 1 |
| 第二任务 document_id | 仍指第一任务软删的原文档 |
| 文档数量 | 1，无新文档 |
| 文档 deleted_at/is_current | deleted_at 非空；is_current=True |
| Document.import_job_id | 仍为第一任务，非第二任务 |
| 分块 IDs | 完全不变 |
| 第二任务**摄取** Embedding 增量 | 0 |
| 默认列表 / 实际 search | 0 / 0 |
| recover + until_idle | 不修正结果，任务仍 success |

查询 Embedding 本身会计入 provider.calls，因此精确复确认在调用 search **之前**采样摄取调用计数；不能拿包含 search 的总增量冒充摄取调用。第一次正式确认输出中的 `calls_increment=1` 正是 query 的一次调用，第三次精确复确认得到 ingestion_embedding_increment=0。

不同内容对照：相同软删前置下，重新上传同名但不同内容时创建新未删除文档，任务 success，默认列表 1、实际 search 1。这排除“所有软删后上传都设计为拒绝/不可见”的推断。事实是同内容去重分支报告 success 却没有可用知识。

影响：用户删除后重新上传原文件，导入页面显示成功，但知识没有重新进入默认知识库/对话检索。应按既定删除/版本语义明确创建新可用版本，或明确拒绝并向用户说明；**本报告不授权自动取消软删除或恢复重要数据**。不能继续静默复用已删候选并宣称成功。

这属于**既有导入去重残余，不是最新批次修复引入**。区别于 F02：F02 是同一 job 的已发布文档 marker 被删除/错绑定后恢复应拒绝重放；本例是另一个新 job，本来不存在本 job 的 Document.import_job_id receipt，随后业务去重选中了旧软删文档。合法新上传的成功路径必须与恢复凭据路径分别验证，不能将 F02 已修推导为本例已修。

建议修复时补正式回归：正常上传→软删→同内容重新上传→新 Session 默认列表与真实 search；再加不同内容对照。候选筛选排除不可用于本次成功结果的软删行，保留原文和软删审计语义，不改重要数据。若既有同来源版本策略需要裁决，应按原产品约束处理，不由本审核直接改变产品语义。

首轮错误来自 `can_control_document` 明确允许租户管理员查看软删文档；控制面详情与默认列表/检索可用性不同。本审核据真实权限语义纠正，保留首轮失败记录。最终缺陷以默认列表、真实 search 和持久任务/document 状态证明，不依赖错误的管理员详情假设。

核心复算代码（隔离 fixture 提供 db/provider）：

```python
first = support.upload(db, source="again.txt", text="synthetic identical after delete")
await import_jobs.run_import_jobs_until_idle(limit=1)
with Session(db) as session:
    original_id = session.get(ImportJob, first).document_id
    assert await RAGService(session, "t-a").delete_document(
        original_id, session.get(User, "u-a"))
second = support.upload(db, source="again.txt", text="synthetic identical after delete")
assert first != second
calls_before = provider.calls
await import_jobs.run_import_jobs_until_idle(limit=1)
calls_after_import = provider.calls
import_jobs.recover_interrupted_import_jobs()
await import_jobs.run_import_jobs_until_idle(limit=1)
with Session(db) as session:
    task = session.get(ImportJob, second)
    doc = session.get(Document, task.document_id)
    hits = await RAGService(session, "t-a").search("synthetic identical after delete")
    assert task.status == "success" and doc.id == original_id
    assert doc.deleted_at is not None and not hits
    assert calls_before == calls_after_import
```

脚本 exit0 表示已按断言**复现错误状态**，不表示业务验收通过。若改为期望重新上传知识可检索的断言则失败；修复时应建立这样的正式失败回归。
