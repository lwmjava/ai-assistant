### F03：深 JSON 未安全拒绝（P2，已修复并复验）

`app/agents/tools/file_ops.py:63` 的 `json.loads(raw)` 可能抛出 `RecursionError`，但 availability 的异常列表不包含它。配置 `FILE_OPS_ALLOWED_ROOTS='['*1500+'0'+']'*1500` 仅 3001 字符，在配置长度上限内，却让 `default_tools()` 抛异常；真实 TestClient `/api/health` 请求同样抛异常。这违背非法工具配置不可阻断应用可用性的原始契约，也可能影响模块加载时的工具状态校验。

`app/agents/tools/web_search.py:206` 远端 JSON 解码同样缺少此处理。3001 字节深层合成响应引发 RecursionError；注册器虽最终脱敏，却返回自由文本意外错误，未返回约定的 invalid_response 结构化观测。

复现：声明解释器运行 `pytest tests/test_pagt001_review.py -k deep_json -q --tb=short --basetemp=data/pagt001-review-deep-json`，3 failed / 12 deselected，exit 1，2.64s。三个失败均针对实际注册/HTTP health/工具调用入口；属于有效业务断言，不是测试导入或环境失败。建议最小修复为在 JSON 解码处将 RecursionError 收成已有分类安全拒绝，保留三个正式回归，不放宽数值/体积门禁。

修复后：文件配置 JSON 解码将 RecursionError 收为 ValueError invalid_configuration；搜索响应将 RecursionError 收为 invalid_response。独立 Agent 实际重跑完整 review 正式测试：15 passed，1.89s，exit 0，包含三个原失败回归。实际 Windows junction、硬链接、文件替换和实际 health 启动验收均通过，没有跳过。测试 Ruff --no-cache exit 0。
