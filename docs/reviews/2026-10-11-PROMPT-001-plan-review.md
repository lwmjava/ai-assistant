## 测试审查与失败图

采用项目 pytest 与指定 conda 解释器。原卡不允许 tests/、evals/，将正式回归和版本化 Smoke/Adversarial Case 放 docs/ai-prompts/ 可遵守范围，但必须给出显式执行命令，不能假设全仓 pytest 自动收集。

```text
源/登记/非敏感配置输入
  -> 结构与路径校验 -> 新进程 CLI
  -> 源发现与摘要 / 配置规范化版本
  -> 一致: 明确版本与来源
  -> 缺失/漂移/非法: 非零退出，保留原文件
隔离源与配置改动 -> 失败 -> 恢复已登记内容/快照 -> 再次通过
```

| 失败边界 | 必须实跑的反例 | 期望与证据 |
|---|---|---|
| 数值 | NaN/Infinity，负超时或非合法参数类型 | 明确拒绝，输出不含非标准 JSON 数字 |
| 失败路径 | 坏 JSON、源缺失、登记缺失、内容变化 | 非零退出；源与登记指纹不变 |
| 权限/租户 | 注入密钥、凭据 URL、业务租户内容，路径逃逸 | 不序列化秘密，不读越界文件，无业务写入 |
| 身份绑定 | 新增实际模板；修改 provider/model/路由/端点身份；切换 cwd | 发现漂移或版本变化；cwd 不影响项目绑定 |
| 回滚幂等 | 新进程重复导出；隔离恢复源与旧配置快照 | 输出稳定；恢复后原版本恢复，不触及真实 .env |

新进程 CLI + 临时目录真实读写可作为本卡 E2；仅 helper 相等断言属于 E3，不能独自关闭。需要字符化回归证明原 Pipeline/Fast-path/Supervisor 生成行为保持，且执行实际 Ruff 与完整 mypy。应保留有效业务失败红灯，不以模块导入缺失充当业务失败。
