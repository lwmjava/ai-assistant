## 原始契约与范围挑战

原卡必须交付“Plan 输出为结构化步骤，含依赖与预期产出”和“步骤可逐步执行与失败定位”；验收是可解析与具体步骤失败定位。不得省略依赖，也不能把可解析 JSON 展示当成逐步执行。非目标是通用 DAG 与五阶段结构变更。

| 方案 | 覆盖与代价 | 推荐 |
|---|---|---|
| JSON 展示，继续自由工具循环 | 不能证明声明步骤与实际执行对应，失败缺少确定步骤归属 | 不采用 |
| 固定顺序 tool/reason，显式 depends_on，工具固定 JSON 参数 | 校验完整计划后按顺序受控执行，最小覆盖原卡；不支持工具间动态参数绑定 | 采用，待用户批准 |
| 动态输出引用、模型逐步补参数或 DAG | 增加不可信观测传参、恢复绑定、权限校验及成本复杂度 | Deferred |

具体参数由规划阶段决定并不违反当前原卡。前步输出可由后续 reason 和最终草稿消费；不能把本方案宣传为任意跨步数据流。依赖字段必须成为运行前置条件，不能只有数组顺序。

- ToolExecutor 已有权限/审计、参数校验、超时、有限重试与结构化基础设施状态；必须复用，不能绕回直接 func 调用。
- StateManager 的快照校验已由服务层读路径调用，新增结构字段可在 agents 内集中验证，不必为形式合规改服务/API。
- 同消息恢复、进程内执行互斥、累计工具预算、指纹与 TTL 已存在于当前工作区；本卡不能重新实现或将单实例升级为多实例承诺。
- 原工具格式化与脱敏是兼容契约，结构化失败分类要保留 legacy 观测 golden。

## 架构与代码质量要求

固定顺序即执行顺序；depends_on 只引用更早存在 ID，并要求实际依赖 succeeded。全计划在任何工具调用前验证，运行时错误有安全代码并停止后继。未知工具、参数类型错误和身份伪造必须拒绝；工具无注入 Executor 时组合已有 ToolExecutor，不能从任意观测文案反推 status。

计划解析、状态验证和文本展示应共用模型/校验逻辑；run/run_stream 共用迭代器。reason 和最终草稿不得暗中执行工具。新增字段仅持久化受限、脱敏内容，不把完整参数或内部异常写进 Trace 或用户错误。

完整代码回退与运行开关回滚需区分：已有 v1 快照的安全续跑仅由保留新解析能力的开关回滚保证。若回退到不识别 v1 的旧代码，应停止活动执行并人工核查，不能声称旧代码保证新快照恢复或 exactly-once；请在最终实现说明/运行手册明确该限制。

## 测试图与失败模式

当前是测试要求，**本审查未执行这些验证**。应使用真实 Pipeline/Executor/Service 与隔离 SQLite、新 Session，脚本 provider 明确为合成输入，不证明真实模型质量。

```text
新规划响应 -> 完整 schema 验证
               +-- 类型/版本/ID/依赖/NaN/超限错误 -> plan 失败，零工具
               `-- 合法 -> running checkpoint
                           -> tool：参数/权限/注入/预算 -> Executor
                                +-- ok -> 状态+指纹+checkpoint
                                `-- 业务/参数/权限/超时错 -> step_id，后继零执行
                           -> reason：有界模型调用
                                +-- 成功 -> 脱敏输出+checkpoint
                                `-- 超时/工具意图/异常 -> step_id，后继零执行
                           -> 草稿 -> QualityGate（不再执行工具）
                           -> 反思 -> 响应
取消/关闭 -> 新 Session 恢复 -> 校验成功前缀 -> 跳过完成步骤
旧 checkpoint -> 原文本行动链；新 v1 + 关闭新规划 -> 按 v1 恢复
```

| 失败模式 | 正式反例的可观察期望 | 计划是否纳入 |
|---|---|---|
| 畸形 JSON、后向/未知/自依赖、重复 ID | 全计划失败，工具零调用，不部分改变 State | 是 |
| 非有限数值、布尔版本、超大或深层参数 | 执行前拒绝，无预算绕过或无限扩展 | 是 |
| 工具异常被转换为正常字符串 | 真实错误对应 failed，后继零执行；legacy 文本不变 | 是 |
| reason/规划超时及取消 | 安全错误；取消不伪造完成并保留成功前缀 | 是 |
| 权限或身份不匹配、检索指令诱导 | 既有受控入口拒绝，准确步骤定位及适用审计 | 是 |
| 第二步中断，第一步已完成 | 新 Session 恢复不重复第一步；工具剩余预算不刷新 | 是 |
| 损坏结构快照与错游标 | 显式恢复拒绝，不启动新的副作用执行 | 是 |
| 低质量修订、同步/流式差异 | 工具计数不增加，终态及步骤状态一致、code_result 保留 | 是 |
| 旧 checkpoint、关闭新模式 | 旧工具行为可运行；已有 v1 不改走旧行动循环 | 是 |

不存在被计划故意忽略的“无测试、无处理且静默”的新失败模式；实际实现仍须逐条反例及独立入口复核，计划写到不等于已验证。

## 性能与并行策略

计划限制 1–16 步并复用既有工具预算，避免 DAG 与逐步自动重规划。每个 reason 会增加一次模型调用，需记录实际调用数及超时；步骤上下文、观测与 JSON 大小限制必须落实，否则每步重复带全部结果会放大上下文。

新增 checkpoint 将包括规划及 reason 步边界，因此不能复用 PAGT-006 的“仅工具轮加终态”写次数说明作为本卡事实；最终说明记录新上限与实际恢复路径。无必要引入新缓存、并发任务或分布式基础设施。

共享 Pipeline/State/Prompt 顺序整合；执行逻辑、状态恢复及兼容不能在同模块独立乱序开发。测试与独立审查角色可分工，pytest 共享数据库必须串行。Sequential implementation, no parallelization opportunity for shared runtime edits.
