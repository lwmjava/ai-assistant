## 必须解决的发现

1. **INST-004 缺必要路径**。`app/schemas/auth.py` 无改密输入和首次标记响应，原卡不允许 schemas。API/配置同步需 README；计划、说明与审查也未列原路径。依据 AGENTS 第9/11/12节与技能 Constraints，需精确补充后再实施，不能合并其他卡的路径。
2. **NFR-012 缺前置**。NFR-003 在当前任务契约中是 backlog，且不在用户八卡集合；只读核验不能替代其生产编排交付。保留阻塞或由用户明确纳入前置，不能自行删依赖。
3. **ERR-001 数量冲突**。原卡两处要求九种错误码，PRD §6.6 是八码加一行无错误的刷新成功。需裁决权威验收集合，不新增第九码凑数。
4. **CLI-002 初始化输出冲突**。原卡禁止 `.env`，PRD §5.11 要 init 写 `.env`。建议将程序支持生成用户指定配置与本次执行不得读取/覆盖工作区真实 `.env` 分开，测试仅用临时目录；若原禁令也禁止功能则需先裁决。
5. **API-001 旧调用方在范围外**。`Dockerfile:45` 仍以 `/api/health` 检查容器健康，`scripts/milvus_switch_check.py:703/724` 仍请求旧路由；必须批准这些精确文件。Vite 现有 `/api` 前缀代理天然覆盖 `/api/v1`，无功能性修改必要。
6. **SSE-001 新生命周期缺 ADR**。当前 chat 路由生成器退出关闭 Service 流，Service 将关闭/取消作为停止并保存部分回复。PRD §5.1.6 要求断线后 ActiveRun 继续、回放、终态查询，改变执行所有权/恢复语义。ADR-0010 明确保留原流契约，不覆盖此变化；先落 Proposed ADR，不能以 checkpoint 现成目录证明已批准。
7. **CHAT-007 多模态必需路径缺失**。`app/llm/base.py` 的 `ChatMessage.content` 仅 str；`openai_compatible.py` 按该值序列化。至少需 LLM 层适配，并核对 Agent 消息构造、预算及历史表示；不在仅 API/Service/Model 内绕过模型契约。若决定新增附件表，另核迁移路径。
8. **LLM-001 配置同步及真实验证**。README 未列允许路径。Embedding 档须与当前 RAG 配置集成，禁止混淆不同索引身份；rerank 配置不等于批准启用未采纳重排。真实两提供商切换需要可用且获授权的测试服务与数据，Mock 不算第二家。

## 首卡最小方案审查

既有 2026-10-04 裁决可直接沿用：角色管权限，独立 `is_test_user` 管测试身份，不新增角色。User 增加两个持久化布尔值；旧用户默认 false，仅新建的三内置账号设首次改密。引导须幂等，不凭同名用户认领、提权或重置密码；缺环境配置和冲突的失败不得留下半批账号。

后端必须统一拒绝未改密主体访问所有业务入口，仅允许自身信息、改密及必要会话结束操作，不能只改前端或 require_permission。改密校验当前密码、拒绝相同新密码、bcrypt 保存、清标记、撤销旧刷新令牌并审计。独立 Session 检查成功/失败后的持久化状态。

前端在统一受保护布局做改密跳转，覆盖登录、刷新与深链；浏览器必须走真实操作路径，构建不替代验收。产品写 SYSTEM_ADMIN_*、现有配置为 INITIAL_ADMIN_* 的漂移需记录；HTTPS 是部署传输约束，本地隔离 HTTP 测试不能证明 HTTPS 已验收。
