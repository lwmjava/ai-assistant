# 会话附件后端工程审查

审查者：Codex 子 Agent `/root/inst_review`；只读核对原始 CHAT-007 契约、批准计划、模型/消息/恢复/解析/迁移实现。未运行测试、未外发、未读取工作区 `.env`。本页为开工工程审查，不是最终 diff 或真实视觉质量验收。

## 契约与当前事实

用户批准计划 `docs/plans/plan_chat_007_20261015.md` 及必要迁移范围。请求附件为 `{name, content_base64}`；精确扩展白名单、每项解码后不超过 1048576 字节，不增加文件个数限制。当前 ChatRequest 会忽略该额外字段，Message 没有持久化列，模型消息只有字符串。因此必须以真实入口证明当前附件被忽略，而不是以导入新模块失败作为红测。

现有 `parse_uploaded_document` 是纯文件解析入口，不执行知识库摄取。现代文档直接解析 bytes；旧 doc/ppt 使用已有受控 LibreOffice 临时目录转换，xls 使用 xlrd。文本解析器支持的扩展比本卡少且允许 GB18030 等自动回退，源码不能直接全交该解析器；按本卡约定，源码/文本严格 UTF-8，错误编码固定拒绝，不用 Latin-1 掩盖损坏输入。文档扩展通过已有服务处理，不新增 RAG 策略或依赖。

## 最小实现与关键失败边界

1. 新附件 Service 完整验证全部项目后返回不可变内部描述。严格 base64、解码大小、扩展、图片签名/有效结构、文档解析任何一项失败，必须在创建会话/用户消息及调用模型之前拒绝。文件名只作为显示数据，传给解析器的临时文件名使用固定安全 basename 与已验证扩展，不把原始名称拼路径。图片保存规范 data URL；返回历史接口只暴露名称、大小、MIME，不暴露 base64 或图片 URL。
2. 非流式和 ActiveRun 流式统一调用相同 Service；即使路由验证过，ChatService 直接入口也不能绕过。流式必须在 run 注册前做确定性附件验证，不能先发 run.started 后才把非法文件当成功消息处理。解析结束后旧格式的失败/超时也不得写新用户消息。
3. 图片视觉能力预检需与模型角色对齐：无已核对视觉能力、非官方部署同名模型，均在新消息写入前明确拒绝。逐跳实际预算和 payload 检查继续执行；只有官方已批准 gpt-4o-mini/low 规则可用，不能把运营者文本窗口声明当视觉能力。附件不会因超预算被丢弃或换成文件名占位。
4. 文档正文围栏作为不可信 user 内容；图片单独进入当前消息的 typed image 部分。保持原始用户 message 作为落库与 resume 内容匹配依据，增强的模型 user_input 不可反写原始内容、日志或 RAG 查询。RAG 检索、技能选择/意图、记忆摘要不能把图片 data URL 当字符串输入。
5. 用户 Message 增加可空 JSON 文本列，保存经过验证的模型必需数据。迁移父修订必须先以 ScriptDirectory 实查唯一当前 head；新表 create_all 后幂等，旧库新增列保留既有消息；stamp 检查只有新列确实存在才跳迁移。新 head 缺列视为损坏库明确失败，不再维护另一套长期手写补列。
6. resume 先以现有主体/租户/消息绑定校验读取原 Message；附件复用原持久化内容，不接受请求输入替换或重新写附件。无附件旧消息按空列表兼容。历史元数据通过既有对话权限路径返回，新增字段不引入越权下载 ID。

## 协作接口和待证据

后端负责附件验证/持久化/HTTP历史及迁移；模型角色负责 typed 图片内容、AgentState 图片通道、能力与预算预检、实际模型 payload/缓存/阶段传播。两方必须在实施前固定 `user_images` 或等效字段与无外发 preflight 方法，防止业务路径保存后才发现图片永远无法交模型。

当前 Message 历史与 Memory 只读取 content；不应自动把旧图片反复发给后续消息。当前用户消息的文档正文/图片由当前 state 承载，resume 才从原附件重建。若附件模型正文需要截断或另外的总量限制，必须报告，不能为通过预算静默裁剪。

必须验证：全部扩展与 1MiB 边界、错误编码/伪造图片/损坏文档、多个附件中后项失败零副作用、新 Session 持久化、模型实际收到正文/图片、历史仅元数据、resume 原绑定、跨用户/租户拒绝、知识库 Document/Chunk 数不变。Mock 仅证明载荷与协议，不证明真实视觉理解。旧 Office 与临时资源涉及 Linux/最终 Ubuntu CI；无证据保持 in_review。最终全量回归与独立审查仍是关闭门禁。
