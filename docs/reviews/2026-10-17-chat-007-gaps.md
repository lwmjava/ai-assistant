## 当前隔离页面

API `127.0.0.1:18775`，Vite `127.0.0.1:5177`，`VITE_PROXY_TARGET` 指向该 API。临时库 `data/chat007-page/case.db`。用户 `chat007` 用 bcrypt 口令创建，`must_change_password=false`，角色 member。模型是本地记录器：文档正文含 `PAGE_DOC_MARKER` 时回复「文档已收到」，消息里出现 `data:image/png;base64,` 时回复「图片已收到」。进程环境清空了模型密钥，禁止这次页面去外网。登录没有替换认证函数。

页面顺序：

1. 用真实口令登录后进入 `/chat`，没有被改密页拦住。
2. 向页面上的 `input[aria-label=选择消息附件]` 派发 change，放入 `blocked.tsx`（2 字节）和 `oversized.md`（1048577 字节）。列表出现「不支持此附件类型」和「附件超过 1 MB（1048576 字节）」，发送按钮禁用。系统文件框没有打开，这一步是向真实 file input 派发 change。
3. 逐项移除后，再以同样方式选择 `notes.md`（16 字节，正文 `PAGE_DOC_MARKER`）。
4. 粘贴：`navigator.clipboard.write` 返回 `NotAllowedError: Document is not focused`，没有完成系统剪贴板写入，也没有用 Ctrl+V。随后向真实 `textarea[aria-label=消息输入框]` 派发带 PNG File 的 `ClipboardEvent`；事件里有 1 个文件，`defaultPrevented` 为 true，列表出现 `pasted.png` 859 B。这走的是页面 `onPaste`，不是文件选择框，也不是操作系统粘贴。
5. 输入「请看附件」并发送。回复为「隔离载荷：文档已收到，图片已收到。」用户消息显示 `pasted.png · 859 B image/png`、`notes.md · 16 B text/plain`。Markdown 在产品里按文本附件标成 `text/plain`。
6. 刷新后从会话列表重新打开该条。名称、大小、MIME 和回复仍在，页面正文没有 `base64`，也没有长 base64 串。
7. 发送前 `rag_documents`、`rag_document_chunks`、`rag_import_jobs` 均为 0，`messages` 为 0。发送后前三项仍为 0，`messages` 为 2。知识库页显示「共 0 篇」。

页面顶部出现「当前没有接入可用的真实模型」，因为这个隔离进程没有模型密钥。回复来自本地记录器。会话时间仍显示约八小时偏差，本轮没有改。
