## 1. 页面九场景

隔离入口 `python -m tests.manual_error_ui`，只监听 `127.0.0.1:18767`，临时 SQLite，登录名 `ui-fixture`，密码框使用夹具说明中的占位文本。真实控制台由当前前端构建提供。除 `model_unavailable` 走真实管线并抛出类型化模型故障外，其余失败响应由夹具按统一错误体返回，只证明页面展示。

| 场景 | 页面结果 | 请求 |
|---|---|---|
| user_disabled | 停留登录页，显示「用户已被禁用，请联系管理员」 | 本次点击时请求记录尚未安装 |
| session_expired | 回到登录页，显示「登录已过期」 | `POST /api/v1/chat/stream` 401 `session_expired`，随后 `POST /api/v1/auth/refresh` 401 `session_expired` |
| token_revoked | 回到登录页，显示「您的登录凭证已被管理员重置，请重新登录」 | `POST /api/v1/chat/stream` 401 `token_revoked`，没有继续刷新 |
| tenant_suspended | 退出后登录页保留「租户已停用，请联系系统管理员」 | `POST /api/v1/chat/stream` 403 `tenant_suspended` |
| rate_limited | 发送按钮变为「8 秒后可重试」，页面出现「请求过于频繁」 | `POST /api/v1/chat/stream` 429 `rate_limited` |
| quota_exceeded | 页面出现「本租户配额已用尽」 | `POST /api/v1/chat/stream` 429 `quota_exceeded` |
| model_unavailable | 页面出现「模型服务暂不可用，请联系管理员检查模型配置」 | `POST /api/v1/chat/stream` 200，错误在流事件中 |
| file_too_large | 真实文件输入的 change 收到 1048577 字节的 `oversized.py` 后显示「附件超过 1 MB」 | 没有发出上传请求 |
| silent_refresh | 页面出现「隔离验证成功」，没有「登录已过期」 | 第一次 stream 401 `session_expired`，`POST /api/v1/auth/refresh` 200，第二次 stream 200 |

`file_too_large` 没有打开操作系统文件框，文件对象交给页面上真实的隐藏 file input。系统管理员对停用租户的例外不在这个夹具里，仍由既有服务测试覆盖。

## 2. 两处缺陷复验

复验人没有参与这两处修复。直接运行当前 `frontend/src/lib/error-contract.test.ts`，它加载真实 `http.ts`。

```text
npm test -- --run src/lib/error-contract.test.ts

```

其中覆盖原审查的两类失败：

- `inflight refresh cannot revive or overwrite session after logout/account-switch`：旧刷新成功不再覆盖新会话。
- `old refresh rejection cannot clear a newer account`：旧刷新失败不再清掉新会话。
- `refresh body silence is bounded after successful response headers`：响应头已到、正文不结束时，15 秒内结束并提示会话过期。
