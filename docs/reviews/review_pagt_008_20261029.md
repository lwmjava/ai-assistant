## 发现与复核

1. **P2，已修复：组合 Schema 的合法参数被误拒绝。** 原实现对每个 `allOf` 分支独立禁止其他分支声明的字段；第一轮修复后，同层 `properties` 与 `anyOf` 的合法组合仍失败。现实现有界收集组合分支和引用声明，传递同层字段集合，同时保留显式 `additionalProperties: false` 限制。正式测试加入合法 `allOf`、引用、公共字段加 `anyOf`、自由对象与未知字段反例。
2. **P2，已修复：检测到写入竞态后，外部硬链接仍保留正文。** 原实现写前/写后验证失败时只删除目标名，不能擦除同一新 inode 的其他链接。现实现失败时在关闭新建文件描述符前清空该 inode，再按设备号和 inode 清理自己的目标名。正式测试加入真实硬链接，以及 Linux 写入前目录搬移加硬链接的反例，断言拒绝后外部别名为空、既有文件不变。静态复核确认清理嵌套 `finally` 保留描述符关闭和父目录描述符释放路径；测试执行结果仍以交付记录为准。
3. **P2，已修复：计划准入提前吞掉伪造身份的权限拒绝审计。** 此项由实现方运行真实 API 回归发现，独立审查者增量复核调用链和修复。`Pipeline._validate_executable_plan` 使用 `_validate` 做业务参数诊断，新未知字段规则曾将伪造 `tenant_id` 提前判为无效计划，未进入既有权限拒绝及审计。现仅在该诊断投影中排除保留的 `user_id`/`tenant_id`；`execute` 仍验证原始参数，且 `_denied_reason` 仍对原始调用检查保留字段，命中后零工具调用并写身份上下文下的拒绝审计，没有把投影传给执行函数或授权判断。既有 `test_real_entry_permission_refusal_audited[forged_tenant]` 保留失败步骤、权限错误、零调用及审计身份/四键断言；该身份诊断修复未修改 Pipeline 或既有拒绝断言；后续网页入口扩展另见补充审查。专项重跑状态由交付记录提供。
4. **P2，已修复：网页路由误将代码/文字读取与明确禁止访问的请求作为联网意图。** 在下述用户批准的路由扩展中，初版仅匹配起始读取动词和任意位置 URL，导致“读取这段代码并解释，不要访问其中的网址”或“请总结以下文字，不要访问……”启用网页工具。现增加明确否定和代码/引用文字筛查；正式路由负例覆盖上述两例及无否定的代码读取请求。此修复收紧工具暴露，不改变 URL、身份或资源守卫。

独立执行一次仅使用标准库加载参数策略模块的确定性探针：合法 `allOf`、合法公共字段加 `anyOf`、显式禁止额外字段三例的 `passed` 分别为 `True / True / False`，断言通过，退出码 0。解释器为 `D:\DepTooL\anaconda3\envs\ai-assistant\python.exe`；未加载项目配置。前述两个失败反例及修复均已进入正式 `tests/`，不以临时探针替代回归。
