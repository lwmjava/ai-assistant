# 真实资源统一评测平台设计

日期：2026-10-24  
状态：已批准，待形成实施计划  
影响范围：EVAL-003、EVAL-004、EVAL-005，以及平台管理页面权限收口

## 1. 背景与纠偏

当前 EVAL-003～005 候选实现把产品评测入口收窄为固定仓库数据集、零外部调用 runner 和任务生命周期验证。该实现能证明任务状态、取消、幂等和报告链路，但不能回答“系统对已导入真实文档、真实 Agent 流程和真实 Workflow 流程表现如何”，不符合本轮产品目标。

本设计将产品能力纠正为真实资源评测。固定 runner 仅保留为内部 CI/Smoke 链路测试，不再作为用户可见的质量评测方式，也不得生成真实质量结论。

`personal-ai-assistant` 的 RAG 评测体验作为交互和指标参考：从知识库真实文档创建测试集、执行真实检索、展示 Recall、MRR、nDCG、延迟和逐问题结果。本项目不直接复制其 Chroma、数据库或权限实现，而是复用当前 RAGService、Agent Pipeline、Workflow Executor、租户和版本治理能力。

## 2. 目标与非目标

### 2.1 目标

- 提供独立“测评”页面，对系统内真实 RAG 文档、系统默认 Agent 和已有 Workflow 发起评测。
- 提供独立“测评报告”页面，展示统一摘要、类型专属指标、逐用例证据和同口径对比。
- 使用统一评测编排器和三个内置资源适配器；契约允许未来升级为受控插件注册表。
- 每次评测固定租户、资源、测试集、索引、模型和实现版本，防止结果混用或失去解释能力。
- 默认支持不依赖 LLM Judge 的确定性评测；生成、Judge 或自动生成用例产生调用前必须展示预算并获得平台管理员确认。
- 评测过程沿用真实执行入口，同时隔离副作用、强制租户边界、支持取消和明确失败终态。

### 2.2 非目标

- 本期不实现动态加载第三方 Python 包、目录扫描或远程插件安装。
- 不新增虚构的 Agent 实体；第一阶段只展示真实存在的“系统默认 Agent”。
- 不以 AI 生成测试集冒充 Gold；AI 生成数据只能是 Silver。
- 不允许一次任务混用多个租户的资源。
- 不在评测中默认执行 webhook、外部写操作、权限修改、删除、财务或其他 L1～L3 副作用。
- 不用 Mock、HTTP 200 或固定 Smoke runner 声称真实质量达标。

## 3. 权限与租户边界

### 3.1 平台管理员

平台管理员使用现有 `system_admin` 角色，不硬编码用户名。当前 `admin` 账号因具备 `system_admin` 角色获得访问权；未来给其他用户分配该角色后，无需修改评测代码即可获得同等能力。

以下页面及其后端 API 只允许 `system_admin`：

- 测评
- 测评报告
- 运行历史
- 审计
- 系统状态

`system_viewer`、`tenant_admin`、`member`、`viewer` 均不显示这些菜单；直接访问页面显示 403，直接请求 API 返回 403。授权必须在后端统一依赖中执行，前端隐藏不是安全边界。

### 3.2 目标租户

平台管理员进入测评页后必须先选择一个启用中的租户。后续知识库文档、测试集、Agent 评测上下文和 Workflow 列表均限定在该租户。任务创建时重新校验目标租户和所有资源归属；执行每个用例前复核身份与绑定，禁止跨租户拼接。

平台管理员的登录租户不限制其选择目标租户，但所有被测业务入口以显式目标租户和经过校验的评测主体运行，不通过临时修改登录用户 ORM 对象实现跨租户。

## 4. 页面信息架构

### 4.1 测评页 `/evaluations`

该页面只负责配置、预算确认、启动和运行态控制：

1. 选择租户。
2. 选择评测类型：RAG、Agent、Workflow。
3. 选择系统内真实资源及执行版本。
4. 选择已有测试集、上传/维护人工测试集，或从真实资源生成 Silver 测试集。
5. 展示用例数、模型、Embedding、Judge、预计调用次数和预算上限。
6. 启动任务、查看实时进度或取消。
7. 完成后提供“查看报告”链接。

本页不堆叠历史报告、趋势和复杂失败分析。

### 4.2 测评报告页 `/evaluation-reports`

该页面只负责历史结果与分析：

- 按租户、类型、资源、版本、状态和时间筛选。
- 展示统一摘要：通过率、用例数、耗时、调用量、费用、资源身份和门禁结论。
- 展示 RAG、Agent、Workflow 的类型专属指标。
- 展示逐用例期望、实际结果、脱敏证据和失败类别。
- 仅允许相同目标类型、指标 Schema、测试集口径和关键运行配置的报告计算差异。
- “再次测评”把原配置带回测评页创建新任务，不修改旧任务或旧报告。

### 4.3 其他平台页面

运行历史、审计和系统状态继续使用独立页面。它们与测评、报告共同归入平台管理导航组，并采用相同的 `system_admin` 路由和 API 守卫。

## 5. 统一评测编排器

### 5.1 组件职责

- `EvaluationOrchestrator`：预检、预算、状态机、并发、取消、恢复、逐用例调度和报告生成。
- `EvaluationAdapterRegistry`：按目标类型返回显式注册的适配器。
- `EvaluationAdapter`：资源枚举、版本固定、测试集校验、单用例执行和指标聚合。
- `EvaluationDatasetService`：测试集版本、Gold/Silver、审核和导入导出。
- `EvaluationReportService`：统一报告协议、类型专属指标、失败切片和可比性判定。
- `EvaluationSideEffectPolicy`：评测上下文中的 Tool、Workflow 和外部调用准入。

编排器不直接了解 RAG、Agent 或 Workflow 的内部实现。适配器不自行管理任务状态、租户授权、预算、审计或报告持久化。

### 5.2 适配器契约

```text
EvaluationAdapter
├─ target_type
├─ adapter_name
├─ adapter_version
├─ list_targets(tenant)
├─ resolve_snapshot(tenant, target)
├─ validate_dataset(snapshot, dataset_version)
├─ estimate_budget(snapshot, dataset_version, options)
├─ execute_case(context, case)
├─ aggregate_metrics(case_results)
└─ cancel(run_context)
```

所有方法通过受控 Service/Executor 访问能力，不直接拼 SQL、任意命令或跨租户资源。

### 5.3 当前注册与未来插件化

第一阶段只显式注册：

- `rag.builtin.v1`
- `agent.default.v1`
- `workflow.builtin.v1`

不扫描目录、不动态导入第三方模块。未来插件注册表可提供相同契约，并增加插件签名、来源、依赖、权限、费用、副作用等级和兼容版本校验。现有编排器、任务状态、预算、报告和页面不因插件化而更换。

报告必须保存 `adapter_name`、`adapter_version` 和 `metric_schema_version`，使旧结果在适配器升级后仍可解释。

## 6. RAG 真实文档评测

### 6.1 目标选择与快照

平台管理员在目标租户内选择：

- 全部当前已发布文档；或
- 一个或多个指定的当前已发布文档。

任务快照固定文档 ID、版本组、版本号、内容哈希、分块计划、活动索引 ID、Embedding provider/model/dimension、向量后端和检索后端。已删除、未发布、身份未知或不属于活动索引的资源不能启动评测。

当前系统没有独立 KnowledgeBase 表，因此界面和 API 使用“租户文档集合”语义，不伪造 `kb_id`。如果未来增加知识库容器，适配器可把容器解析为同样的文档及索引快照。

### 6.2 测试集来源

- AI 生成：从所选文档的真实分块采样，生成问题、参考答案要点和证据绑定，标记为 Silver。
- 人工上传/维护：平台管理员录入问题、期望文档/块、答案要点，经审核后可标记 Gold。
- 已有反馈候选：必须经过现有候选接受和版本审核流程，不能自动加入 Gold。

每个检索用例绑定期望 `document_id`、`chunk_id`、文档版本和证据摘要。不得只用文件名或模糊文本匹配判断相关性。

### 6.3 执行与指标

默认只执行真实检索，不需要 LLM Judge：

- Recall@5、Recall@10
- MRR
- nDCG@5
- 命中数量
- 检索延迟
- 逐问题候选、来源、排名和版本

可选生成质量评测调用真实回答模型和 Judge，并记录：

- Faithfulness
- Answer relevancy
- Context precision
- Hallucination rate

开启生成或 Judge 前必须展示预计调用次数和预算并再次确认。无模型密钥时，人工测试集仍可执行纯检索评测；AI 生成测试集和生成质量评测明确不可用，不得使用 Mock 代替。

### 6.4 快速诊断

现有单查询检索策略对照保留为 RAG 的“快速诊断”。它复用真实索引，可展示候选和耗时，但不生成批量质量结论，也不能代替正式 RAG 评测报告。

## 7. Agent 真实评测

### 7.1 目标

第一阶段只展示真实存在的“系统默认 Agent”。任务快照固定 Agent 源码版本、Prompt 版本、模型配置版本、编排模式、Tool 契约和适用 Skill 版本。可以选择默认全流程、指定 Skill 场景或 Supervisor 编排场景。

未来增加持久化 Agent 定义后，适配器的 `list_targets()` 返回真实 Agent 列表；编排器和报告协议保持不变。

### 7.2 执行主体

系统默认 Agent 没有独立所有者，而 Tool、RAG 和 Skill 的可见范围依赖用户身份。任务必须固定一个目标租户内的执行主体，不能直接沿用平台管理员的登录身份，也不能只用抽象角色绕过真实资源授权。

平台管理员在创建任务时选择一个启用中的真实租户用户作为评测执行主体；后端校验其当前租户成员关系和角色，并把用户 ID、角色及权限版本写入任务快照。界面明确提示这是受控评测执行，不创建普通会话、不代表该用户主动操作；审计同时记录发起评测的平台管理员和被选执行主体。执行前若用户停用、退出租户或权限变化，任务以 `authorization_changed` 失败。

本期不新增专用评测服务账号，避免引入额外的账号生命周期、角色授予及资源授权管理。

### 7.3 测试用例

Agent 用例可定义：

- 用户输入和必要的会话历史。
- 期望路由：直接回答、RAG、Tool 或拒绝。
- 期望或禁止的 Skill。
- 期望或禁止的 Tool。
- Tool 参数 Schema 和调用次数范围。
- 期望终态、错误码或安全拒绝。
- 可选答案要点、证据要求和评分规则。
- 最大步骤、Token、耗时及外部调用预算。

人工确认和反馈晋升用例可成为 Gold；AI 根据 Skill/Tool 契约生成的用例只能是 Silver。

### 7.4 执行与指标

使用真实 Chat/Agent Pipeline、Skill 选择和 Tool Executor，但运行于评测隔离上下文：

- L0 只读工具可真实执行。
- L1 及以上副作用默认拦截，记录 Agent 是否正确提出动作和审批要求。
- 不写入普通用户会话，不触发 Workflow、Webhook 或外部写操作。
- RAG 场景可以绑定同一目标租户的真实文档和活动索引。

默认确定性指标包括：用例通过率、路由准确率、Skill 选择准确率、Tool/参数契约通过率、禁止动作拦截率、平均步骤、Token、延迟及失败分布。答案语义质量仅在显式开启 Judge 后计算。

## 8. Workflow 真实评测

### 8.1 目标与快照

平台管理员选择目标租户中的已有 Workflow。当前 Workflow 没有独立版本表，因此任务创建时冻结名称、Prompt 模板、所有者、超时、重试/调度相关配置和实现版本，并生成不可变快照哈希。后续修改 Workflow 不改变旧任务和报告。

### 8.2 执行边界

Workflow 评测采用“真实执行链 + 评测隔离”：

- 使用真实 Prompt、所有者上下文、Agent 管线、超时和重试逻辑。
- 不注册或触发 cron。
- 不发送 webhook。
- L0 只读工具可真实运行。
- L1 及以上副作用默认拦截并形成审批/副作用结果。
- 不写入普通 WorkflowExecution 历史；结果进入评测用例记录，并带 `trigger_source=evaluation`。

### 8.3 测试用例与指标

用例可提供模板变量、输入上下文、期望输出断言、期望步骤、允许/禁止 Tool、最大重试和超时。指标包括步骤完成率、输出断言通过率、审批/副作用判定、重试次数、超时率、执行耗时、Token 和错误类别。语义输出质量可选 Judge。

## 9. 任务、用例结果与报告

### 9.1 任务状态

沿用明确状态机：

```text
queued → running → succeeded | failed | cancelled | interrupted
              ↘ cancel_requested ↗
```

任务保存目标快照、测试集版本、选项、预算、幂等身份和进度。相同幂等键及相同规范化请求返回原任务；相同键不同请求返回 409。

### 9.2 逐用例结果

逐用例记录统一字段：状态、耗时、调用量、费用、断言结果和脱敏失败类别；类型专属证据存入版本化投影。不得保存密钥、完整系统 Prompt、敏感 Tool 参数、原始异常或未经脱敏的文档正文。

### 9.3 报告

统一报告头包括：租户、目标类型、资源快照、适配器及指标 Schema、测试集版本/等级、模型/Embedding/Judge 身份、预算、执行版本、时间和门禁结论。

类型专属指标按独立 Schema 保存。报告不可修改；重跑创建新任务和新报告。只有同目标类型、同指标 Schema、同测试集口径和关键运行参数的报告允许计算差异，否则显示“不可直接比较”。

## 10. 预算与费用

适配器在启动前返回预算估算：用例数、Embedding、回答模型、Judge、Tool 和预计 Token/费用。预算值进入任务快照。

- 纯 RAG 检索在已有索引上不新增 Embedding 调用。
- AI 生成测试集、回答生成和 Judge 分别开关并独立计数。
- 实际调用达到上限后不启动下一次调用，任务以明确预算终态结束。
- 未配置密钥时禁止需要真实模型的步骤，但允许不依赖模型的评测路径。
- Mock 只能用于自动化链路测试，产品报告必须标记 provider 和模型来源，禁止混入真实趋势。

## 11. 失败、取消与恢复

- 启动前目标不存在、租户停用、资源未发布、版本漂移或索引不可用：拒绝创建运行任务。
- 执行中索引、资源身份或权限发生变化：以 `resource_changed` 或 `authorization_changed` 失败，禁止混合版本继续聚合。
- 单用例业务失败：保存失败类型并继续剩余用例；系统级失败终止任务。
- 取消：停止调度新用例，对当前模型/工具执行发出合作取消。
- 进程重启：仅恢复满足幂等、身份和资源快照校验的待执行用例；无法安全恢复时标记 `interrupted`，不静默重跑。
- 报告持久化失败：任务不得标记成功；事务回滚并保留可诊断终态。
- 外部错误对用户只暴露稳定错误码和脱敏说明。

## 12. API 边界草案

平台管理 API 使用统一 `/api/v1/evaluations` 前缀并要求 `system_admin`：

- `GET /targets?tenant_id=&type=`：列出真实目标资源。
- `POST /datasets/generate`：从目标快照生成 Silver 测试集并确认预算。
- `POST /datasets`、`POST /datasets/{id}/versions`：人工维护/上传版本。
- `POST /datasets/{id}/versions/{version}/review`：审核和 Gold 晋升。
- `POST /jobs`：创建真实资源评测任务。
- `GET /jobs`、`GET /jobs/{id}`：运行态与进度。
- `POST /jobs/{id}/cancel`：合作取消。
- `GET /reports`、`GET /reports/{id}`：报告列表和详情。
- `POST /reports/compare`：同口径对比。
- `POST /rag/diagnose`：单查询快速诊断。

请求中必须显式提供目标租户；后端根据目标快照解析资源，不接受任意文件路径、任意模块名或任意 shell 命令。

## 13. 兼容与迁移

- 复用现有数据集版本、审核、任务状态和报告协议中仍适用的部分，补充真实目标快照和逐用例结果。
- 当前固定 runner 任务不能改写成真实任务；历史记录明确标记 `internal_smoke`，从产品默认列表隐藏，可在系统诊断中保留。
- 当前静态仓库报告继续可读，但与真实资源报告分组展示，不能计算跨口径提升。
- 现有 `/evaluations` 页面拆分时保留旧链接重定向到测评报告或明确迁移页，避免书签无提示失效。
- 数据迁移只增加字段/表和分类，不删除旧任务、报告或数据集。涉及删除的 downgrade 在发现数据时拒绝。

## 14. 测试与验收

### 14.1 确定性测试

- 适配器注册、目标枚举、目标快照和 Schema 版本。
- 三类资源的租户隔离、停用、撤权和漂移。
- 任务幂等、预算、取消、恢复和报告事务。
- RAG Recall/MRR/nDCG 的固定输入计算及真实 RAGService 调用契约。
- Agent 路由、Skill、Tool、参数、安全拒绝和步骤预算。
- Workflow 模板、步骤、重试、超时、Webhook/副作用隔离。
- Gold/Silver、审核、人工导入和无密钥行为。
- 报告可比性与历史协议兼容。

### 14.2 权限测试

前后端矩阵覆盖 `system_admin`、`system_viewer`、`tenant_admin`、`member`、`viewer`：只有 `system_admin` 能访问测评、报告、运行历史、审计和系统状态。必须覆盖菜单隐藏、直接路由、直接 API 和跨租户资源 ID。

### 14.3 真实业务验收

- 对目标租户已导入并发布的文档生成 Silver 测试集，运行真实检索并查看逐问题命中。
- 上传人工测试集，审核为 Gold 后运行纯检索评测。
- 显式开启生成/Judge，确认预算、真实 provider/model 和费用记录。
- 对系统默认 Agent 运行真实管线并验证工具副作用被隔离。
- 对已有 Workflow 运行真实 Executor，确认不触发 cron、Webhook 或业务写入。
- 报告页可筛选、查看失败、同口径比较和再次测评。
- 固定 Smoke runner 不出现在产品测评选择器中。

### 14.4 工程门禁

修改公共执行链、权限、RAG、Agent、Workflow、状态和持久化，必须执行相关专项、完整后端 pytest、ruff、mypy、前端 typecheck/Vitest/lint/build、Windows 专项和最终提交对应的 Ubuntu CI。真实模型/Embedding 质量结果必须记录 provider、模型、维度、配置和机器；未授权费用不得执行。

## 15. 回滚

- 通过功能开关关闭真实资源任务创建，保留报告和历史读取。
- 适配器可单独停用，不影响其他目标类型。
- 页面可退回只读报告模式，但不得重新把内部 Smoke runner宣传为真实评测。
- 回滚不自动删除任务、用例结果、报告或测试集。
- 权限收口回滚必须单独批准，不能为兼容旧页面而静默向租户角色重新开放平台数据。

## 16. 实施拆分建议

1. 修订 EVAL-003～005 的任务范围和验收，登记当前候选实现的偏差。
2. 统一 `system_admin` 平台页面/API 守卫，拆分测评和报告路由。
3. 落适配器契约、注册表、目标快照和逐用例结果模型。
4. 先交付 RAG 真实文档检索评测及 Silver/Gold 流程。
5. 接入系统默认 Agent 真实评测与副作用隔离。
6. 接入 Workflow 真实执行链与评测隔离。
7. 完成统一报告、同口径比较、迁移兼容和组合验收。

每一步均保留前一步可运行状态；在 RAG 真实评测未通过业务验收前，不把 EVAL-005 标记完成。
