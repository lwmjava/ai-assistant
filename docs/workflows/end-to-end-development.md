# 日常开发与交付工作流

> 适用：白天有人监督的功能开发与常规修复。规则以 [AGENTS.md](../../AGENTS.md) 为准。
> 这是操作说明，不是每卡必做的阶段清单。产品运行时架构、事故、夜间和生产流程只在触发时展开。

## 1. 开始

核对 Git 状态、当前任务和直接依赖；读取入口、实现、测试和调用方。已有验收与批准决定直接复用。
当前卡已有目标、范围、验收时，在原位补必要实现方案即可，不生成同内容计划，不再请求一次“开始实施”确认。
批次先明确卡清单、依赖、每卡范围与终点；没有获授权的任务不启动。

## 2. 实现与快速反馈

1. 为行为变化补有效失败用例；缺陷先最小复现。纯说明不机械写测试。
2. 做满足验收的最小修改，检查存量调用方与失败路径。
3. 开发阶段运行明确选择的模块/契约测试；选测说明只需改动模块、调用方、命令、剩余风险。
4. 使用 scripts/validate_delivery.py 隔离运行；预检失败先修环境，不启动长时间全量空跑。
5. 页面行为变化实际走查相关角色、成功/失败和返回路径；SSR或组件测试不能冒充真实浏览器操作。

普通任务不要为了流程补上下文图、状态机、Feature Flag、全维度Evaluation或回滚演练。实际改变架构/持久化/模型/权限时才增加对应验证和记录。

## 3. 审查与候选收敛

按 AGENTS.md 第9.2节判断实际影响。普通任务自审，复杂边界独立审查；检查输入是相关最终diff、契约、调用方、测试与疑点。
专项通过即可开始适用审查和页面走查，修复未收敛前不跑最终全量。阻断项闭合即退出，不再追加无目的的最终审核。
业务接受可在此取得，后续行为未变则复用；必要审查预算不足时列未覆盖项，不自动通过。

## 4. 最终检查与状态

完整命令、执行地点和证据复用统一按 AGENTS.md 第10节，不在这里维护第二套门禁。
本地跑专项及廉价就绪检查，最终完整回归可由最终SHA合格CI承担；验证设施首次修改等例外仍按该节本地全量。
提交/推送沿已有明确授权，缺授权时交付可审核候选并列待CI项。CI等待期间可推进其他已授权独立任务。
只使受相关输入变化影响的证据失效；更换审查者或补文字不构成重跑理由。
必要验证、审查和业务接受齐全后同步 tasks.yaml；缺项保持 in_review/blocked，具体状态以任务所处阶段为准。

## 5. 最小交付记录

在当前卡或已有记录一次写清：行为/文件、实际命令与退出码、证据版本、未验证项与适用回滚。不另写实现说明和关闭报告。
API、配置、运行说明等只同步本次变更造成的失真；没有变化不刷新全部文档。
交付说明先告诉用户能做什么、验证到哪里、还缺什么。不要用文档数、代码行数或done比例证明提效。

## 6. 特殊工作入口

| 触发 | 入口与增加的工作 |
|---|---|
| 普通缺陷 | [缺陷与事故](bugfix-and-incident.md) 的最短修复路径 |
| 实际架构/运行时边界决定 | [Harness规范](../governance/agent-harness-engineering.md) 相关章节及必要ADR |
| 评测数据构建 | [迭代指导](../AI辅助开发迭代指导.md) 第7、8节 |
| 夜间无人值守 | [夜间流程](nightly-autonomous-development.md)，保持准入、隔离、预算及次日独立审查 |
| 生产部署或恢复 | [生产编排](production-compose.md) 及适用发布/恢复手册，另行核对生产授权 |

新产品、重大迁移和生产发布可按实际需要补规格、迁移方案、灰度和观察窗口；这些不是普通功能的默认前置。
