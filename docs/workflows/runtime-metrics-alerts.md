# 运行时指标与基础告警阈值

本进程在 `GET /api/v1/metrics` 暴露存活、错误率和延迟。默认返回 Prometheus 文本；需要结构化字段时使用 `?format=json` 或 `Accept: application/json`。指标只按本实例、当前 300 秒窗口统计，不汇总多副本，也不接入外部监控或告警平台。

业务 API 统一挂在 `/api/v1`，因此本端点不在根路径提供 `/metrics`。若外部抓取工具约定访问 `/metrics`，可在反向代理上做路径映射，但这不是默认部署的一部分。

## 口径

- **存活**：进程能响应指标端点即 `process_up=1`，`alive=true`。进程是否真正可服务，仍以 `GET /api/v1/health` 的数据库和向量库连通性为准。
- **错误率**：窗口内 HTTP 5xx 次数除以窗口内总请求数。4xx 单独计数，不计入错误率。没有请求时 `error_rate` 为 `null`，Prometheus 文本省略该行，不用 0 表示未测到。
- **延迟**：最近秩分位数（nearest-rank）。`non_inference` 覆盖除对话生成以外的 API；`inference` 只覆盖 `POST /api/v1/chat`、`POST /api/v1/chat/stream` 和重新生成回复的路径，因其耗时包含模型推理。没有样本时分位数为 `null`，对应 Prometheus 行省略。
- **不计入窗口的请求**：`/api/v1/health` 与 `/api/v1/metrics` 本身，避免探活和抓取污染错误率与延迟。
- **标签**：只使用 `outcome`（success / client_error / server_error）、`scope`（non_inference / inference）和分位标签。不输出路径、用户或租户等就请求而变的标签。

## 建议阈值

下列阈值为运维建议，便于对照本端点做人工巡检或自行配置外部规则。其中 API P95 来自产品需求 6.1「API 响应时间 (P95) < 500ms，不含 LLM 推理时间」；错误率没有已批准的正式 SLO，因此给出保守缺省值，不能当作已经验收的线上承诺。

| 信号 | 建议警告 | 建议严重 | 说明 |
|------|----------|----------|------|
| 存活 | — | `process_up != 1`，或 `/api/v1/health` 不是 200 / `status=ok` | 进程无响应或依赖不可用 |
| 错误率（5xx，300 秒窗口） | ≥ 1%，且窗口内至少 20 个请求 | ≥ 5%，且窗口内至少 20 个请求 | 样本不足时不要告警，避免把偶发一次 5xx 当成故障 |
| 非推理 API P95 | ≥ 400ms，且至少 20 个 `non_inference` 样本 | ≥ 500ms，且至少 20 个 `non_inference` 样本 | 对应「不含 LLM」的 API 响应时间目标 |
| 对话生成延迟 | 仅观察 `scope=inference` 的分位数 | 不把 500ms 套用到这类路径 | 产品需求另有「首 Token P95 < 2s」，本端点只统计整段 HTTP 耗时，不能代替首 Token 测量 |
| 知识库检索 P95 | — | — | 产品需求目标是 < 300ms。本端点不单独拆出检索耗时，不能用来验收该项 |

窗口不足 20 个样本时，应视为数据不足，而不是用 0 或单次请求的分位数下结论。

## 非目标与缺口

- 不接入 Prometheus、告警通道或通知接收人，也不提供大盘。
- 不统计多实例汇总、首 Token 延迟或检索阶段耗时。
- 本说明只给出口径和阈值建议；把规则接到外部系统或改生产默认开关，需要另行授权。
